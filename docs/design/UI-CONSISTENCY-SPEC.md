# 视觉一致性规范（UI-CONSISTENCY-SPEC）

> 立档 2026-08-20。来源：用户报障「进行一次前端视觉 ui、页面排布、按钮元素、颜色规范的统一」，
> 8 维度全屏审计（82 条发现，对抗性复核后确认 65 条）。
> 本文只收**审计里反复出现、且已有机器门禁或明确判据**的几条，不重复 DESIGN-FIDELITY / LIST-PAGE-SPEC。

## 1. 下拉一律用 `ds/Select`，禁止原生 `<select>`

**判据不是审美，是物理限制**：原生 `<select>` 的下拉面板由**操作系统渲染**，
CSS 一行都管不到。把触发器画得再像设计稿，点开仍是 Windows 灰色系统列表。

审计当时全站 41 处原生 `<select>`，散在 17 个文件，各屏给同一个控件起了 12 个类名，
尺寸七零八落：

| 类名 | 屏 | 高度 | 字号 |
|---|---|---|---|
| `.bd-sel` | 楼栋抽屉 | 26px | 12px |
| `.md-in` | 电表抽屉 | 32px | — |
| `.rh-msel` | 报表首页 | 34px | 13px |
| `.lg-rs-sel` | 台账导入 | 34px | 12.5px |
| `.ct-in` / `.fin-in` | 合同/租户新建 | 40px | 13.5px |

最能说明问题的一处：`MeterDetailDrawer` 的**同一个表单网格里**，「租户」是设计好的
`FPTenantPicker` 浮层，紧挨着的「楼层/方位/楼栋/归属/表类型」是原生 select；
而同一个「归属」字段，在「新增表」弹窗里又是 `ds/Select`——
**新增表时是设计款，改现有表时是系统款。**

`meter-shared.css` 甚至写着 `.mt-edit.sel { appearance: auto; -moz-appearance: auto; }`，
即**显式主动退回**系统外观。这条已删。

### 用法

```vue
<Select size="sm"                                       // sm=28 | md=36 | lg=48
        :options="[{ value: '2024', label: '2024年' }]"  // value 必须是字符串
        :model-value="String(year)"
        @update:model-value="setYear(+$event)" />
```

- 期间选择器定宽：**年 110px / 月 92px**（LIST-PAGE-SPEC §2；给窄了把「2024年」截成「202…」）。
- 例外：需要 `:class` 承载校验态（如导入摘要的非法期别标红）时，可保留原生 select，
  但要在代码里写明为什么。**保住功能优先于统一外观。**

## 2. 字号只能取阶梯值，禁止小数

阶梯：`--fs-display 28 / --fs-h1 24 / --fs-h2 20 / --fs-h3 16 / --fs-h4 15 / --fs-body 14 /
--fs-label 12 / --fs-micro 11`。

审计当时全站 884 处硬编码 `font-size`，其中 **529 处在阶梯外、392 处是小数**
（12.5px×182、11.5px×126、10.5px×45、13.5px×32，分布在 98 个文件）。

**小数字号是真问题不是洁癖**：浏览器按设备像素取整，同一个 12.5px 在 100%/125%/150% 缩放下
渲染成 12 或 13，字重看起来忽轻忽重；同一屏并排的 12px 与 12.5px 在某些缩放下**完全一样**、
换个缩放又差一档，等于这个层级时有时无。

**中文可读性下限 11px**。低于此的中文（审计当时 4 张录入表的表头单位是 10px：度/元/吨/千瓦/元·kVA）
在小字号下「元」与「吨」轮廓接近，误判列含义会直接导致抄表数填错列。
**单位是语义信息不是装饰**——表头行高吃紧就把 th 加 2px，不许压字号。

## 3. `--text-disabled` 只给禁用控件

`--text-disabled` = `--ink-300` = `rgba(28,28,28,0.2)`，白底合成 ≈ `rgb(210,210,210)`，
**对比度 1.51:1**（WCAG AA 要 4.5:1）。给禁用控件用是对的——低对比正是「不可用」的信号。

但审计当时有 28 处拿它涂**有效信息**：租户抽屉的「联系人/联系电话/所属分类/主要单元/关联主租户」、
楼栋卡片的「在租面积/在租·空置/月租金」、四张录入表的表头单位。用户看到的是
「一串数字悬空、不知道这列是什么」，笔记本外接屏、投影、窗边阳光下基本消失。

**信息用 `--text-muted`（0.62 alpha ≈ 4.8:1，本仓早已为此场景备好的令牌）。**
tokens.css 里 `--text-muted` 那行注释就记着它当年为 a11y 从 0.4 提到 0.62——
`--text-disabled` 这条只是当时漏审了。

## 4. 语义色必须单一事实源

审计抓到唯一一条**会让用户读出错误业务结论**的颜色问题：合同「已到期/已终止」的红灰
在合同管理与租户组合分析**正好对调**。用户在 A 屏学到「红=该跟进」，到 B 屏就会认为
「已终止那批出了问题」去追查，而真正该跟进的已到期被灰色淡化了。

根因是 `FPContractStatus.vue` 把 MAP 内联在 SFC 里，分析层够不着，于是自己抄了一套并抄反了。
**状态→颜色/文案的映射一律抽成 `.ts` 模块**（先例：`components/fp/unitStatus.ts`、
本次新增 `components/fp/contractStatus.ts`），任何屏都从同一处消费。
顺带治好第二个病：同一批状态曾有**三套叫法**（执行中/生效中/在租；草稿/待入驻；已到期/到期）。

## 5. 未定义令牌有机器门禁

`npm run token-check`（已挂进 `build`）。引用了 `tokens.css` 里没有的 `var(--x)` 就红。

**为什么必须是机器门禁**：浏览器遇到未定义的 `var()` **不报错**，按 CSS 规范静默回退到属性初始值——
`color` 退成继承色、`border-color` 退成 currentColor、`background` 退成 transparent。
表现是「这个徽标的蓝色没生效」「这个按钮没有边框」，看起来像**设计没做好**而不像 bug，
所以能在线上活很久没人报。vue-tsc 不看 CSS、vitest 的 jsdom 不求值 CSS 变量、
code review 也不会去比对集合——三道现有门禁全抓不到。

审计当时催缴单屏有 10 处这类断链（`--accent` / `--text-tertiary` / `--border` / `--fs-sm`），
是全站最常用的出账屏：「已确认」与「草稿」两个徽标几乎分不开、行内「确认」按钮完全没有边框。

脚本排除两类合法写法：`var(--x, 兜底值)`（作者已显式给回退）、
模板字符串拼名（`var(--accent-${tint})`）。

## 6. 编辑按钮全站同一形态

浏览态 `outline`「编辑模式」→ 编辑态 `filled`「完成」。样板：`MeterView.vue`。

依据：浏览态下「编辑」是次要动作（用户在读），编辑态下「完成」是主要动作。
审计当时是**两派颜色**（6 屏白 outline / 11 屏黑 filled）、**三种文案**（编辑模式/编辑表格/编辑）、
**三种退出控件**（完成 / 取消+保存 / 退出编辑+保存）。

viewer 只读角色：编辑与导入按钮**不渲染**，不是渲染了点了才失败。
门放在共享页头组件里（`SchedHeader`），不要指望 N 个消费屏各自记得加——
审计当时那 7 屏**一个都没引 auth**，是整体缺失而非某屏漏了。
