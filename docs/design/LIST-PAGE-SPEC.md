# 列表页布局规范（LIST-PAGE-SPEC）

适用范围：主数据类列表屏——楼栋管理、租户管理、合同管理，以及后续所有「工具栏 + 表格卡片 + 分页」形态的 list 页。
基准样式：租户管理屏（2026-07 截图定稿）。三屏必须逐条一致，禁止各屏自带变体。

## 1. 页面骨架（自上而下）

```
标题行        h2 + 副标题 ·· 右侧操作按钮组（导入/新增，Button size=sm）
.mx-body      grid: 224px KPI 左栏(sticky) + minmax(0,1fr) 主列，gap 28px
  .mx-kpirail   KPI 卡竖排 gap 16px
  .mx-main      flex column gap 16px：
    .mx-toolbar   工具栏（单行，见 §2）
    .mx-listcard  列表卡片（见 §3）—— 分页器在卡片内部底部，不悬浮页面底部
```

首载 gate：summary 未返回前整块渲染 `.page-loading` spinner，不闪空 KPI/「共0条」。

## 2. 工具栏 .mx-toolbar（单行，与租户管理一致）

- 结构：`display:flex; align-items:center; justify-content:space-between; gap:12px; flex-wrap:wrap`
  - **左**：segment tab 组 —— 统一用 `FPPhaseTabs`（支持 `tabs` prop 自定义标签集，带计数徽标）。禁止复制其样式另建 tab 组件。
  - **右** `.mx-toolbar-right`（`display:flex; align-items:center; gap:10px`），顺序固定：
    1. （可选）`Segmented` 布局切换（仅楼栋卡片墙/台账列表）
    2. 搜索框 `.mx-search`：固定宽 230px，`radius-full`，左内嵌 16px 放大镜图标，高 36px
    3. 状态 `Select`：宽 130px，size=sm
- 期间 `Select` 定宽：**年 110px / 月 92px**（size=sm）。触发器是 `width:100%` + 单行省略号，宽度全靠外层定宽 div，
  给窄了就把「2024年」截成「202…」。下限算式：4 数字×0.6em + 「年」1em ≈ 50px 文本 + gap 8 + 箭头 16 + 左右 padding 24 + 边框 2 ≈ 100px。
  定宽而非 `fit-content` 是为了切月份时工具栏不抖（「1月」↔「12月」宽度不同）。
- 工具栏内**不放**「共 N 条/栋/份」文本——总数只出现在分页器（FPPager `total`）。

## 3. 列表卡片 .mx-listcard

- `Card surface=white :padding=0`，外观：`border:1px solid var(--border-subtle); overflow:hidden`。
- 高度由**布局链**决定（不由内容撑，也不做 100vh 视口数学——壳层 main.fp-content 自带 topbar+padding，视口常量必错）：
  页面根 `height:100%` → `.mx-body{flex:1;min-height:0}` → `.mx-main{min-height:0}` → `.mx-listcard{flex:1 1 auto;display:flex;flex-direction:column}`。
- `min-height:440px` = fitRows 下限 6 行(6×56) + 表头~30 + wrap padding 14 + 分页条~53：短窗时退化为外层滚动，**绝不裁行**。
- 校准标准：常规窗口高度下页面（含壳层 main）**不得出现任何滚动条**。
- 内部两段：
  - `.mx-tablewrap`：`flex:1 1 auto; overflow:hidden; padding:14px 4px 0` —— **禁止出现滚动条**，每页行数由 useFitRows 保证恰好放满（§6）。
  - `.mx-pagerbar`：`flex:0 0 auto; border-top:1px solid var(--divider); padding:10px 14px`，内放 FPPager。
- 过滤后 0 行：卡片内空状态，占住内容区，图标 + 一句 + 一个按钮。定稿·待实现（2026-09-30，画布 06-B 第 7 件「空状态」）。2026-10-01 jfen/hint-impl 已换成 `FPEmpty`（图标 + 一句），还差按钮：合同、租户、楼栋、账号等列表过滤后 0 行都没有「清除筛选」一类的按钮。
  2026-09-30 改：原来是居中空态文案（padding 40px，text-disabled）。

## 4. 表格行（等高铁律）

- 行高统一固定：`--mx-row-h: 56px`。tr 定高与 td 样式由 `FPSortableTable` 组件内联承载（`height:var(--mx-row-h,56px)`），对**所有**使用方统一生效（含导入中心等非分页表）。
- `td`：`padding: 0 16px; vertical-align: middle`（垂直留白由行高提供，不用上下 padding）。
- **所有行必须等高**。内容不得撑高行：单元格内容一律 `white-space:nowrap`；文字超长才 `overflow:hidden` + `text-overflow:ellipsis`，全文用深色气泡悬停出（12px，停 0.5 秒出，手机点一下出），不用浏览器 `title`；数字不省略（见下面列宽铁律）；两行式单元格（名称+副行）总高必须 ≤ 行高。
  已实现（2026-10-01，jfen/hint-impl；2026-09-30 定稿，画布 06-B 第 10 件「悬停说明」）。2026-09-30 改：原来是单元格一律 ellipsis、长文本用浏览器 `title` 出全文。
- 行分隔：1px `var(--divider)` 底边；hover 背景 `var(--bg-panel)`。
- **列宽铁律（2026-08-04 升级为全站一切表格适用，不限本规范的"列表页"范围）**：列宽跟内容走，按整列全部数据算；**数字永远不省略**，数字列按整列最长的数撑开；名称、文字列按整列最长的内容定宽，相关的格子挨在一起，文字超长走 ellipsis + 悬停气泡（见「所有行必须等高」那条）。**容器比表格宽时，多出来的宽度统一放进最右边一列空列（filler）**：每行末尾一个空 `td`、表头一个空 `th`，都带 `aria-hidden="true"`、`padding:0`；表头底色、行线、hover 底色照样铺满整宽。不把余宽塞给某一列文字列，也不用 `min-width:100%` / `width:100%` 让浏览器把余宽按比例摊到各列。表格比容器宽、要横滚时 filler 宽度为 0，其余照旧：名称列按 §9.1 封顶、省略号 + 深色气泡看全称，数字不截断，固定列按 §9.1 退。列位置不得因翻页或**滚动**而变化；数据换了（换月、换账册）按新数据重算一次（§9.1）。需要严格锁列时表格用 `table-layout: fixed`。**虚拟滚动/窗口化表格按整列全部数据（不是当前渲染的那几行）算一次列宽，写进 `table-layout: fixed` + `<colgroup>` 锁住，滚动、翻页都不变**——窗口化每帧更换渲染行，auto 布局会按可见内容逐帧重算列宽，快速滚动时列位置抖动（2026-08-04 抄表工作台实案：它按"工作台"立项未套本规范而漏网，教训=任何 `<table>` 一律受此条约束，与屏的形态命名无关）。
  定稿·待实现（2026-09-29 用户评论「数字不许显示不全」，画布 07-C）。2026-10-01 jfen/hint-impl 只在 7 张宽表（§9）落地；还差：`FPSortableTable` 等其余表格的数字列被压窄时仍走省略号。2026-09-30 改：原来是「每列显式定宽……内容超长走 ellipsis，不许撑列」，数字也照样省略。
  余宽放最右空列：已实现（2026-10-02，jfen/hint-impl；2026-10-02 定稿，用户拍板，画布 09/10）。原因是用户原话「像这些表格，左右两边间隔过大且中间没有任何信息，不会导致用户查看时候获取信息过于疲劳吗」。2026-10-02 改：原来是「至多一列弹性（吸收余宽，紧邻其他列排布、不留无用空隙）」；实际有两种做法——§9 七张宽表（月度台账、园区抄表、公共电核算、楼栋损耗、损益附表、附表10、工资）都用 `min-width:100%` 把余宽按比例摊到各列，催缴单、充电桩抄表、光伏分栋抄表等表留一列（位置、桩名、电站名、备注）吃余宽；宽屏时名称和数字之间隔出大段空白。
  写法（2026-10-02 已实现，jfen/hint-impl，§9 七张宽表以外的表格）：空格统一挂 `base.css` 的 `.fp-fill`（`width:100%`、`padding:0`、`min-width:0`），表格本身仍是 `width:100%`，filler 才有余宽可吃。auto 布局里有 filler 时，别的列的 `width`（含 `<col>` 的 px 宽）会被压回内容宽 —— 要锁宽的列写 `min-width`；会折行的说明列（计费参数「说明 / 算式」「覆盖了」）按最长一条排成单行的宽给，封顶后照旧折行。`table-layout:fixed` + `<colgroup>` 的表加一根不给宽的 `<col>` 当 filler，原来那根弹性列按整列全部值估宽（`useWideTable` 的 `textW`，不量 DOM）。分析层 `.ak-tbl` 一族用 `tr::after` 生成同一格（`ana.css`，不进 DOM，读屏读不到），表头吸顶、行态底色由那一屏给 `tr::after` 补同一条。催缴单列表的「位置」列放不下时（定宽列 + 最长位置串 > 表格区宽）回到吸收剩余、省略号 + 悬停，filler 0 宽；M↓ 的 980 保底只挂在这时（`.bn-tight`）。**列宽不跟着当前页、页签或编辑态变**（§7「交互期间零变化」）：只把当前页交给表格的屏（楼栋、租户、账号）名称列按全部数据估宽再传给列；按页签筛过的行不拿来算宽（光伏电站名按全部电站、期签宽一律算上）；编辑态才出现的输入框、铅笔、编辑行按「有没有权限」预留宽，不按「眼下在不在编辑、有没有哪行在改」（电费成本项目 / 备注、充电桩桩名、光伏电站名、催缴单水电费备注）。表格不给 px `min-width` 保底（附表水电 / 充电 / 光伏 / 电费、科目余额表已删）：保底宽比内容宽时，多出来的全落进 filler，横滚看到的是空白。有 filler 时 auto 布局只给不定宽的列最小内容宽：会折行的表头和副行写 `nowrap`，`width:100%` 的输入框改 `width:auto; min-width:100%`，图标写 `max-width:none`（`base.css` 给 svg 的 `max-width:100%` 会让它按 0 算）。已改：`FPSortableTable`（楼栋、租户、账号、导入中心）、`FinReportTable`（资产负债表、利润表）、科目余额表、附表水电 / 充电 / 光伏 / 电费、电费成本三张、充电桩两张、光伏电站档案、计费参数三张、报表首页勾稽、预算明细、光伏分析两张、催缴单列表与明细（水电、宿舍电、宿舍水）、系数簿、收款簿、导出通知单、分析层 `.ak-tbl` 全部。没改：抽屉 / 弹窗里末列就是备注的小表（余宽本来就在最右）；导入预览表（`FpImportModal`，`width:100%` 按比例摊，末列不是备注）和收款公司（`CompanyBookWindow`，fixed 布局、账号列吃剩余）勘察时判了不改，还没按新规则复核。还差：数据没到（骨架行）时租户名称列先给 240 封顶宽、楼栋名 / 账号角色列先按表头宽，数据落下后按实际估宽，首次进屏会挪一次 —— 2026-10-03 用户接受（列宽按全部数据算，数据没到不知道多长），记在 LAYOUT-STABILITY §7.1 例外。
- 表头：`position:sticky; top:0`（卡片内固定，配合无滚动实际不滚，仅作兜底）。

## 5. 分页器 FPPager（停靠卡片底部）

- 位置：`.mx-pagerbar` 内，永远贴卡片底边；跳页 popover 向上展开，随分页器停靠。
- 左侧：跳页触发按钮「第 X / Y 页 ˄」+「共 N 条」。
  - 触发按钮 `min-width:116px; width:auto`——**文本任何页数下不得溢出按钮边框**（如"第 26 / 26 页"）。
- 右侧：`Pagination` 窗口化页码 pills：≤7 个（首尾 + 当前±1 + … 省略号），32px 圆 pill，‹ › 步进；当前页 `bg-sunken` + semibold。
- 楼栋卡片墙布局：无列表卡片，分页器保持既有「spacer 置底」方式停靠页面底部。
- **停靠机制**（2026-09-13 自 `DESIGN-FIDELITY` §5.1 并入）：屏幕根容器 `min-height:100%` 撑满 `<main>` 内容区，
  列表卡片与分页器之间插一个 `flex:1 1 auto; min-height:0` 的撑高占位 `div` 把分页器顶到底。
  **行数不足一页时分页器仍停卡底，不得浮在页面中间。** 参照 `BuildingsView` / `TenantsView`，新建列表屏沿用。
- **窗口化算法**（2026-09-13 自 `DESIGN-FIDELITY` §5.2 并入）：`Pagination` 的上限是 prop `maxPills`（默认 7）。
  算法 `[1]` + `(left>2 ? '…')` + `[max(2,cur-1) .. min(count-1,cur+1)]` + `(right<count-1 ? '…')` + `[count]`；
  `…` 用 `--text-disabled` 且不可点。跳任意页仍走 JumpSelect popover（可滚动列出全部页）或 ‹ › 步进。
  门禁：`Pagination.spec.ts` windowing 三例（20 页/当前 10 → `1 … 9 10 11 … 20`；首端 → `1 2 3 … 20`；≤7 页无省略）。

## 6. 每页行数 useFitRows（防抖动铁律）

- **行高是常量输入**（`--mx-row-h`），**严禁测量已渲染行的实际高度**——pageSize 不得依赖页面内容，否则形成「pageSize→内容→尺寸→pageSize」反馈回路（即 2026-07-15 修复的第 23 页抽搐闪烁 bug）。
- 仅当容器**布局**尺寸变化（改窗口高、首次挂载）时重算：`pageSize = clamp(floor((wrap.clientHeight - padding - theadH) / rowH), 6, 30)`。容器高度必须是布局驱动（§3 卡片定高 + flex），与行数无关。
- 重算触发三通道：ResizeObserver(wrap) + ResizeObserver(documentElement) + `window resize` 事件监听（RO 对 html 盒尺寸不敏感的环境兜底）。
- 楼栋卡片墙每页固定 8，不适用本条。

## 7. 禁止事项清单

- ❌ 底部把所有页码全部列出（页数 > `maxPills` 必须窗口化 + `…`，见 §5；2026-09-13 自 `DESIGN-FIDELITY` §5.2 并入）
- ❌ 表格卡片内出现垂直滚动条（每页行数必须自适应放满）
- ❌ 行高随内容波动（这一条宽一点下一条窄一点）
- ❌ 工具栏两行式布局 / 工具栏内放总数文本
- ❌ 复制 tab/pager 样式另建组件
- ❌ pageSize 依赖渲染内容的任何测量
- ❌ 分页器脱离卡片悬浮在页面中部或底部（卡片墙除外）
- ❌ 任何交互（滚动/翻页/筛选/hover/编辑态切换）引发布局位移或闪烁——列宽、行高、sticky 偏移在交互期间必须零变化（审核清单项，全站表格适用）。
  只有两处按 §9.1 重算：数据换了（换月、换账册）重算一次列宽；表格可见宽度变了（拖窗口、收展侧栏）重算固定列退哪几根。2026-09-30 改：原来没有这两处例外。

## 8. 渲染开销铁律（2026-08-11 审计新增，全站表格适用）

> 根因：宽表在**编辑态**每敲一个字符就整表重渲染。此时模板里每个「返回新对象/新数组的函数调用」都会被乘以 `行数 × 列数`。

- ❌ **模板里禁止调用返回新对象的函数**（`:style="cellStyle(c)"` 这类）。返回值每次都是新引用 → Vue patcher 认为样式全变 → 全表元素重刷样式。
  - 只依赖**列**不依赖行的样式，必须做成按列缓存的 `computed`：`cellStyles[c.key]`（引用稳定，patcher 直接跳过 diff）。
  - 实案：`FPLedgerTable` 27 列 × 130 行，`cellStyle()` 每次渲染分配约 **5,300 个对象**；改按列 computed 后 **27 个**。影响 5 屏。
- ❌ **模板里禁止调用做全表聚合的普通函数**（`{{ sum(c.key) }}`、`{{ rowTotal(row) }}`、`{{ colTotal(id) }}`）。写在 `tfoot` 里就是「每列扫一遍全表」。
  - 合计一律做成**一次遍历产出全部列**的 `computed`，行合计与总计共用同一次遍历。
  - 实案：`FPLedgerTable` tfoot 约 3,500 次 reduce/渲染；`S10Table` 200 行时约 15,000 次乘加/渲染。
- ❌ **模板里禁止对数组做线性查找**（`cfgs.find(x => x.id === row.id)`）。预先 `computed` 成 `Map` 再按键取。
- ❌ **比较器/热路径里禁止 `new RegExp(...)`**。正则提到模块级常量（`useMeterWorkbench.floorRank` 实案：排序每次比较都在造正则）。
- ❌ **分组/排序结果若不依赖编辑草稿，禁止和草稿放同一个 computed**。拆成两个：`groups`（只依赖 `props.rows`）+ `usage`（依赖 draft），否则每敲一键全量重分组 + 逐组重排序。
- ✅ **行数可能上千的表必须窗口化**。`composables/useMeterWorkbench.ts` 的 `buildWindow()` 是现成实现（rAF 节流 + 窗口位移 <4 行不 setState + spacer 撑高），配 `table-layout:fixed` + `<colgroup>` 使用，**不要另写一套**。

## 9. 固定列与表格高度（有左右固定列的宽表）

已实现（2026-10-01，jfen/hint-impl，`composables/useWideTable.ts`；2026-09-30 定稿，画布 07-A / 07-B / 07-C）。管有左右固定（sticky）列的宽表，现有 7 张，全部照这一套：
月度台账、园区抄表、损益附表 1–5、附表10 销售收入、公共电核算、楼栋损耗、附表12 工资。

### 9.1 固定列

- **按表格自己能看见的宽度（容器宽）算，不按屏幕宽度分档。** 侧栏收起展开、屏左侧轨在不在，都按表格实际能看见的宽度算。
  现状是按视口档判，601px 以上任何宽度都一样：月度台账左 260 + 右 534 = 794，1366 笔记本侧栏展开时表格只有约 700，左右两组互相压住，中间一列都看不到（07-A）。
- **左右固定列加起来 ≤ 表格可见宽度的 40%**，中间至少留 60% 给跟着滚的列。
- **超了按先后退。** 每张表给固定列排先后：名称列第一，最关键的那个结果数第二，其余往后。超了从最后一根开始退，退到只剩名称列为止。
  - 月度台账：租户 → 本月结余 → 应收合计 → 上月结余 → 收款。（2026-10-01 用户确认，画布 07-C）。
  - 园区抄表：用途 → 用量 → 位置 → 状态。
  - 损益附表 1–5：科目细分（编辑态勾选列随它）→ 本年合计 → 分组 → 填入；备注不固定。
  - 附表10 销售收入：租户 → 合计。
  - 公共电核算：用途 → 位置。
  - 楼栋损耗：位置。
  - 附表12 工资：姓名 → 序号（编辑态序号格里有勾选框，跟姓名绑在一起不退）。
  - 园区抄表、公共电核算的名称列取「用途」不取「位置」：一行是一块表 / 一个池。编辑态勾选列跟名称列绑在一起，计入 40%，永远不退。以上先后出自 2026-10-01 实现规范（`docs/superpowers/specs/2026-10-01-hint-widetable-bell-impl-design.md` §1.8）。
- **退掉的列原地变普通列**：位置、顺序都不变，跟着左右滚；分隔阴影挪到还固定着的最里面那一列。
- **备注这类说明文字任何宽度都不固定。**
- **名称列最多占可见宽度的 1/5**：按最长的名字算宽，超了省略号，悬停（深色气泡，§4）看全称。字可以省略，数字不行。
  名称列格里带不缩的签（标签、徽标、勾选框、删除钮）时，封顶有下限：签 + 内边距 + 约 3 个字；1/5 比它还窄时按下限给，可以超过 1/5 ——不然名字被挤成 0 宽，悬停、点按都碰不到（2026-10-01 S2 实现，`planFixed` 的 `minW`；公共电核算、园区抄表、损益附表、附表10、楼栋损耗用到）。
- **固定的数字列不再锁死 128**：按整列最长的数算一次宽度，不省略（§4 列宽铁律）。现状：月度台账锁 128 带省略号；园区抄表读数锁 96 带省略号、悬停也看不到全值。
- **余宽放最右空列（§4 列宽铁律）**：表格不溢出时 filler 排在最后，右固定列跟着内容排、不必贴容器右沿；溢出要横滚时 filler 宽 0，不影响右固定列 `sticky right` 的偏移。名称列只按最长的名字算宽（上一条的 1/5 封顶照旧），不吸收余宽。已实现（2026-10-02，jfen/hint-impl；2026-10-02 定稿，用户拍板，画布 09/10）。2026-10-02 改：原来 7 张表都用 `min-width:100%` 把余宽按比例摊到各列。
- **什么时候重算**：表格可见宽度变了（拖窗口、收展侧栏）才重算退哪几根；数据换了（换月、换账册）按新数据重算一次列宽；滚动、翻页都不重算。

### 9.2 表格高度：至少露 8 行

- 表格至少露 8 行数据。不够 8 行时按顺序让，让到够为止：
  1. 屏顶瘦身：统计卡改成页签，说明文字收进悬停
  2. 分组表头不贴顶，只贴列名那一行
  3. 合计行不贴底，跟在最后一行后面，滚到底才看到
  4. 还不够：表格最少保留 8 行高，整页往下滚，不再把表格压扁
- 够 8 行时什么都不让：两行表头照旧贴顶，合计照旧贴底。
- 只按表格区的实际高度判断，不按屏幕型号。
- 现状（07-B，1366×768 笔记本推算）：月度台账只露约 6 行；园区抄表屏顶还有 6 张统计卡，只露约 3 行。
