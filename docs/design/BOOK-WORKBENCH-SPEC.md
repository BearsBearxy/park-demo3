# 账册工作台规范（BOOK-WORKBENCH-SPEC）

2026-08-24 立档。适用范围：月度台账、附表10 两屏的整体重构，以及**此后所有新增录入类页面的动线准则**（§7）。
设计稿：账册工作台设计稿 v1（四屏 mockup，已确认）。

## §0 决策记录（用户拍板，2026-08-24）

| 决策项 | 结论 |
|---|---|
| 自定义列落库 | **方案 A**：21 标准列保持物理列，自定义列存行级 `extra_fees` JSON |
| 模板版本口径 | **现行版全局生效**：版本更新后所有账期（含历史月）都用新版，直到再更新；历史版本仅供追溯/回滚 |
| 台账 / 附表10 | **保持两个独立页面**，共用账册工作台版式 + 模板编辑器 + 导入列映射三套组件 |
| 左栏账册范围 | **只放本屏账册**（台账屏 = 公司账册；附表10 屏 = 期区账册） |
| 新增账册 | **真落库**：插入 `ledger_book` 一行；**禁止每册建物理表**（动态 DDL = 已否决的方案 B，且会弄坏账单页/分析层/收入核对的跨册查询） |

## §1 概念模型

```
账册(book) 1 ─── n 模板版本(template_version)   ← 版本链,现行版指针挂在 book 上
账册(book) 1 ─── n 数据行(monthly_ledger / s10_record)
列(column) = 标准列(21/25 个,物理列) ∪ 自定义列(extra_fees JSON 键)
每列 ∈ 恰好一个语义槽(semantic slot)
```

- **账册**：一本独立维护的账（台账=每记账公司一册；附表10=每期区一册）。
- **模板**：账册的两级表头定义——一级分组 + 二级列（显示名/导入别名/语义槽/隐藏位/列序）。
- **语义槽**（8 个，全局固定）：租金 / 管理服务费 / 基础设施 / 公共维护 / 杂项税费 / 电费 / 水费 / 其他·未归类。
  槽集合是**代码常量**，用户不可增删——它是分析层的契约（§6）。

## §2 落库

- 新表 `ledger_book(id, screen, company_id|phase, name, current_version_id, …)`；
  `book_template_version(id, book_id, ver, definition_json, note, created_by, created_at)`。
- `monthly_ledger` / `s10_record` 各加一列 `extra_fees JSON`（可空）。**存量数据零迁移**。
- 自定义列在 JSON 里的键 = 列的**固定 id**（如 `c_parking`），绝不是显示名——改名永远不动数据。
- 派生口径唯一事实源仍是 `LedgerService.recalc`：应收Σ = 21 物理列 + extra_fees 全部值。
  任何消费方（分析/账单/核对）**禁止**绕开 recalc 自算。
- ❌ 红线：任何用户操作都不得触发 DDL。加列=改模板 JSON；建册=INSERT。

## §3 模板版本规则

- **现行版全局生效**：宽表渲染、导入匹配、模板下载，所有账期一律用现行版。
  自定义列在其出现前的历史月显示为空，属预期行为。
- **轻改动**（改显示名/加删别名/调列宽）：不升版本，直接改现行版定义，**必记操作日志**。
- **结构改动**（增删列/换语义槽/增删分组/改列序/隐藏切换）：生成新版本（v+1），必记操作日志。
- 回滚 = 把历史版本**复制为新版本**，版本号只前进不倒退。
- 标准列**不可删除**，可：改名、加别名、隐藏。隐藏列不出现在宽表与导入模板中；导入命中隐藏列时提示（不静默丢）。
- 自定义列可删除；名下有历史数据时删除动作改为「归档」（数据保留，宽表不再显示，合计仍计入其语义槽）。
- 模板编辑入口在**编辑模式**下（useEditMode 门,缺权限当场弹主管授权）。
- 所有模板改动经 `AuditLogService` 记录（操作日志时间线第四来源），格式：`模板 vN→vM: <改动明细>`。

## §4 导入规则（列级）

- 匹配词典 = 现行版模板（显示名 + 别名，标准列与自定义列同权）。
- **未匹配列必弹「列映射确认」面板，禁止静默丢列**（2024-01「宿舍区租金」29 万丢列事故的根治）。
  三个出口：① 挂到既有列（可勾「存为别名」→ 轻改动落模板）；② 新建自定义列并挂槽（结构改动升版）；③ 显式忽略（记入导入结果 notices）。
- 全零列自动折叠不打扰；派生列（本月合计/结余）自动忽略并在导入后逐户校验，不符者行级提示。
- 同一表头签名的多段（整册拆段）只弹一次映射面板，决策套用全部同签名段。
- 请求体自定义列走 `extraFees: {列id: 金额}`；后端按键合并（同「文件没这列=不动既有值，显式 0=清零」的列级 upsert 铁律），未知列 id 该行报错不静默吞。

## §5 账册工作台动线

```
左栏:本屏账册列表(一键切换,记住各自上次年份) + 新增账册
主区:账册头(模板版本/待处理徽标) → 年份段选 → 12 月卡矩阵 → 点月份卡进宽表
```

- **进宽表必须点击具体月份卡**；宽表内「换期」返回本矩阵。**禁止**顶栏年月 popover 直落表格。
- 新增账册向导：名称/绑定主体 → 模板起点三选（标准模板 / 复制现有账册模板 / 空白）→ 进模板编辑器。
- 待处理信号（未映射列/未绑定租户）以常驻徽标挂账册头与月卡，点击直达处理面板。

## §6 语义槽契约（分析层联动）

- 分析层**只消费语义槽与派生数，永不消费具体列**：
  12 屏用 应收Σ/收款/结余；用能缴费读〔电费〕〔水费〕槽；收入核对升级为**槽级三态对账**（两侧均为标准列的槽保留列级下钻），自定义列差异停在槽级并标注列名。
- 未挂槽（理论不可达，自定义列建列时必选槽）与「其他·未归类」槽：某账册未归类金额占比 > 5% 时，相关分析屏顶部出琥珀提示条，深链模板编辑器。**绝不静默摊派、绝不猜测归属**。

## §7 页面动线准则（后续新增页面必须遵守）

1. **明确选期门**：凡按账期组织的数据页，进表必经年份+月份的显式选择层（矩阵/月历），不得用 popover 让用户"顺手"落进某个期。
2. **实体切换在左栏**：多主体（公司/期区/账册/电站/桩）用左栏一键切换并记住各自上下文，不得让用户从头走选择流程。
3. **入口常驻**：功能入口（问题面板/待处理）不随数据有无出现消失——空态置灰，不挪位（LAYOUT-STABILITY 的延伸）。
4. **不静默丢数据**：导入/解析遇到认不出的列、行、名，一律转为交互处置或显式 notices，禁止静默跳过。
5. **写操作走编辑模式门**（EDIT-MODE-SPEC），配置类改动必记操作日志。
6. **契约上移**：可视化/汇总永远建立在稳定语义层（语义槽/租户档案/期区）上，不直接依赖用户可改的展示层（列名/账面名）。
7. **清单行点击 = 显式选期**：任何「去做这件事」的清单行/入口，点击时必须把当前期一并前置满足目标屏的选期门（先写 store 再带 `?p=`），不得让用户到了目标屏再撞一次矩阵。
   ⚠ 前置满足之后**目标屏的选期门就不挂载了**，而门往往是某些数据的唯一加载入口 —— 前置的一方要把那份加载补上，否则目标屏读到空数据显「一道工序都没走」。
   ⚠ 深链要带的不只是期：锁/入口里若还有第二维（公司 / 期区 / 哪一张附表），一并带过去，否则落到默认子视图，而那里没有用户要找的东西。
8. **已审核 / 待审核的表，任何写入口一律拒**（SIDEBAR-UX-REDESIGN §7）。闸落在 **service 层**的 `ReviewGuard.assertEditable(kind, period, scope)`，不落在 controller、也不落在权限表 ——
   提权是在 `WriteAccessManager` 里放行的，权限表拦不住它；而 service 之间互调（`ParamService.recalc` → `AllocService.generate`）根本不过 controller。
   ⚠ 判据是**被写数据的月**，不是 URL 上的月：抄表屏按年锁而审核按月，参数屏的 URL 月只是「站在哪个月看」，被写的是 `req.acctMonth()` 那一行。
   ⚠ 一次写落在多个月上（导入逐行带月、整年清空、改月份的读数）时**每个月都要判**；改月的读数旧月新月都判，否则可以把已审月的数据「挪」进未审月改完再挪回去。
   新写的写方法若确实不该进审核，用 `@NoReviewGuard(reason)` 显式标注并写明理由 —— `ReviewGuardCoverageTest` 会从源码推导出漏挂的那个方法并当场红。

## §8 迁移与兼容

**固定列口径(§9 澄清)**:租户/结余/本月应收合计/本月收款/备注是**结构列**(身份与派生,不是费用列),
不入模板 groups,§9「不得写死列中文名」不约束它们;换园区若固定列叫法不同,届时再把固定列名提为部署配置。
**整册多司导入的词典口径**:整册(多 sheet 多公司)导入以「当前选中公司」的账册现行版为匹配词典;
各司模板分叉后建议逐司导入(逐司词典各自生效)。

**结余链自动派生(2026-08-24 拍板)**:台账「上月结余」不再人工/导入维护——任何写入
(保存/导入/复制上月/绑定/改名)后按租户键(t:id / n:账面名)时序前滚归一(rechain):
非首次出现月的 balance_prev 强制 = 该键上一有据月的期末(缺月跳过,链跨空洞);
**租户首次出现月保留人工期初,是全链唯一可录入的位置**(编辑态该格开放,派生位只读);
导入一律屏蔽结余列(词典摘除+忽略清单静默跳过+后端兜底忽略)。
读路径与 recalc 口径零改动:消费方(分析/账单/导出)拿到的存量值恒为链上真值。

**账册模板入口与第16权限点(2026-08-24 拍板)**:模板入口移出页面编辑模式,独立成
两态常驻「账册模板」;面板默认只读(全员可查看现行版与**历史版本的列名与布局**),
面板内单独「编辑模式」按钮走 book-template:edit(第16点,V109 授 admin,角色矩阵自动第16行);
模板写端点(PUT template / POST adopt)后端同点把关。

**模板全局化(2026-08-25 拍板,取代 §2「每司一册一链」)**:台账屏所有模板版本挂在**一条全局链**上,
每家公司只持有一个版本指针(`current_version_id`)。规则:只能在链尾编辑;保存升版后**只带走原本
就在链尾的公司**,落后的原地不动;升级入口是模板面板顶部的「升到 vN」,不强制;切到缺列的版本时,
该公司在那些自定义列名下有数据则拒绝(口袋残值仍进 recalc 应收合计,列却不显示 → 合计对不上明细)。
「回滚」退化为切指针,链只追加不改写。完整规则见 docs/superpowers/specs/2026-08-25-global-book-template-design.md。
附表10 屏不在此列:它按期区分册,维持一册一链。

**模板 pin 按月独立(2026-08-26 拍板,修订上一条)**:版本指针从「每册一个」改为
**每册每月一个**(`book_month_pin`)。读某月的模板按「本月 pin → 最近一个更早月份的 pin → 链尾」解析。
版本**完全不可变**(任何保存都升版,不再有「轻改动就地更新」);月份**一旦落库数据就固化 pin 并冻结**
——已录入的月份既不许切版本也不许从它编辑模板,清空该月数据即自动解冻。
归档(hidden)列在**该月有非零值**时仍以只读列显示:hidden 的语义是「不再接受新录入」,
不是「藏起已经发生的钱」——藏起来会让应收合计永远对不上明细(recalc 全口袋照加)。
更换版本走第 17 权限点 `book-template:switch`。完整规则见
docs/superpowers/specs/2026-08-26-per-month-template-pin-design.md。

**选期矩阵 v3(2026-08-24 拍板,取代年份 tab)**:矩阵态全部年份纵排一屏,每年一行 12 月卡;
年份范围 = 数据年 ∪ 当前自然年 ∪ 手工年,连续补满(utils/matrixYears.buildYearRows)。
「＋ 补更早年份」向前补一年、「＋ 添加 {次年} 年」向后补;手工年按 屏+册 记本机 localStorage
(bw-extra-years:{screen}:{bookKey}),录入数据即转正;**数据年不可移除**,手工空年行尾 hover 可移除。
「每册记住上次年份」条款随 tab 退场作废——全年份可见。台账/附表10 同用 BookMonthMatrix 一个组件。

**组名 MON 占位约定**:模板种子里电费/水费组名存 `MON电费`/`MON水费`(与 layout.ts 既有约定同源);
前端 `toLedgerColumns`/S10Table 渲染时把 `MON` 替换为「{费用月}月」。模板编辑器里用户看到并可改这个占位——
删掉 MON 即失去月份前缀,属预期行为不做特殊拦截。

- 上线时为每家公司自动建册（v1 = 标准 21 列模板），附表10 建 4 个期区册（office/factory 版面为起点）→ 用户无感，存量流程不断。
- 现有 `LEDGER_ALIASES` 硬编码别名迁入各册 v1 模板后删除代码常量。
- 收入核对 26 科目映射保留为标准列的槽内下钻依据；槽级卷积为新的对账主口径。

## §9 产品化预留（多园区,2026-08-24 补充）

- **21 个物理列是「预留槽位」不是「业务含义」**：列的显示名、别名、语义槽全部来自模板;
  **代码任何位置不得写死列的中文名**(现存 lgColumns 的 label 迁入模板种子后退役为部署初始值)。
  这与金蝶/用友「预留列+自定义项」同范式——换园区只换模板种子,不换代码不动表结构。
- 售卖姿势 = **每园区一套独立实例**(单租户部署,复用现有 deploy 三件套):
  记账-核对-分析闭环随模板开箱即用;出账链(合同计费/抄表/公摊派生)按园区计费规则做实施。
- 新增账册功能定位:建公司/建期区流程的附带动作(自动建册 v1),不做独立大功能。
