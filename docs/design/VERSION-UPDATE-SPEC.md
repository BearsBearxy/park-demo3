**依据**：设计稿 `../../../运维文档/设计稿/未实现/版本更新-2026-09-18/`（线上画布 https://claude.ai/artifact/Rbm2WJX3dLVcYXTix7egue ），
7 块画板：Main 总览 / Desktop 打开后 / Entry 入口 / History 更新记录 / Motion 动效 / Mobile 手机 / Refresh 刷新提示条。
**图是规格**；本文件是图的压缩版，两者不一致以图为准。

**要解决的问题**（2026-09-18 用户原话）：「目前用户对版本更新完全不知道」。
两件事要分开：**发了新版没人知道**（→ §6 刷新提示条）与**新版改了什么没人知道**（→ §2 本次更新弹窗）。

## 2. 「本次更新」弹窗（Desktop / Mobile 画板）

居中弹窗，`PAGE-BEHAVIOR-SPEC §2` 的模态档，`z` = `--z-modal`。桌面宽 560、高 720（`max-height: min(720px, 86vh)`），
圆角 16、`border: 1px var(--border-subtle)`、`box-shadow: 0 24px 64px rgba(28,28,28,.28)`（与 `CommandPalette` / `FpImportModal` 同款）。

三段结构：

1. **页头** 164px，底色是登录页那组暗色（`#04070d` / `#08192e` / `#10133a` / `#05101f` + 品牌蓝 `#38b6ff`、`#5271ff` 两片光晕），
   右下角是放大的品牌标志（`opacity .14`）。内容：标志 + 「灵睿 LinkSight」→ 「版本更新 · YYYY-MM-DD」→ 版本号（`--font-mono` 28px 600）→ 一句话标题（15px）。右上角关闭按钮。
2. **正文**（本段滚动，页头与底栏不动）：本版重点卡（图标 + 「新增」标签 + 标题 16px + 说明 + 「去看看」+ 右侧 200px 小图）→
   `新增` / `改进` / `修复` 三组，每组一个分组标签 + 「N 项」。
   - 条目行：30×30 图标块（`--surface-card`，圆角 8）+ 标题 14px/500 + 说明 12px/18px `--text-muted`，右侧可选「去看看 ›」；整行可点，悬停 `--bg-hover`。
   - 修复组不用条目行，用一句一条的列表（12px/18px）。
3. **底栏**：`--surface-card` + `border-top`，左「查看全部更新记录 ›」（`--text-link`），右「知道了」（`Button variant=filled`，36px 高）。

**分组语义**：`新增` = 以前没有的屏或功能；`改进` = 原来就有、现在更好用；`修复` = 原来算错或点不动，写「原来哪里不对」。

**文案规矩**（`screen-copy-no-jargon-no-overlay` 同源）：用用户的话，不贴提交记录，不写「重构 / 门禁 / 口径」这类开发用语；标题与侧栏里那一屏同名；能跳转的才给「去看看」。

**手机（S 档）**：全屏接管（同 `CommandPalette` 在 S 档的做法）；页头 196px 且延伸到状态栏下（`padding-top` 含 `env(safe-area-inset-top)`）；
底栏固定，「知道了」整行宽、高 44，其上一行「查看全部更新记录」；重点卡改上下排。

## 3. 何时自动弹（Motion 画板）

- **触发**：只在**功能更新**时弹 —— 到当前版本为止最新的那版功能更新（版本号最后一位是 0），这个账号还没看过，且本次会话还没弹过。小调整（最后一位不是 0）不弹，只亮 ✦ 蓝点（RELEASE-NOTES-SPEC §7；用户 2026-09-19 拍板）。
- **时机**：登录后落到首页、**首屏数据到齐之后**才弹，不压在加载骨架上。
- **不弹**：`auth` 里 `editors.size > 0`（编辑态）时不弹，退出编辑后下一次换屏再判。
- **弹几次**：每个账号每版功能更新一次。跳过多个版本的人只弹最新那版功能更新，其余在更新记录里。
- **关闭的四种方式**（都算看过并落「已读」）：「知道了」、右上角 ×、点遮罩、Esc。
- 「去看看」= 关弹窗并跳到那一屏；「查看全部更新记录」= 关弹窗并开 §4。

## 4. 「更新记录」弹窗（History 画板）

宽 760、高 620 **固定**（切版本时弹窗不变大小，只换右边内容）。

- 头部 56px：标题「更新记录」+ 右侧关闭。
- 左列 216px（`--surface-card` + 右分隔线）：版本列表，每项 = 版本号（mono 14/600，当前版本带蓝底白字「新」角标，仅未读时）+ 日期 11px + 一句话标题 12px（最多两行，超出才省略号；标题上限 20 字，两行放得下）；选中项白底 + `--shadow-pill`。列底脚注写当前版本与「更早的版本没有整理记录」。
- 右列：版本号 20px mono + 「YYYY-MM-DD 发布」+ 一句话标题 + **本版重点卡**（与 §2 同一张卡、同一张配图，组件 `ReleaseFeatureCard`；旧版本不给「去看看」；2026-09-19 用户要求：关掉弹窗后在这里还看得到）+ 三组条目（与 §2 同文案，紧凑行：标题 + 说明，分隔线到底；重点那条只在卡上，不在行里重复）。
- **旧版本的条目不给「去看看」**（那时的屏可能已改名或合并）。
- 手机：全屏；版本列表变成顶部一排可横滑胶囊（高 ≥36），从「本次更新」进来时左上可返回。

## 5. 动效（Motion 画板）

| 部件 | 怎么动 | 时长 / 曲线 |
|---|---|---|
| 遮罩 | 透明 → `rgba(28,28,28,.34)` | `--dur-base` `--ease-out`（`fp-fade-in`） |
| 弹窗 | `translateY(8px) scale(.985)` → 原位，同时淡入 | `--dur-base` `--ease-out`（`fp-rise-in`） |
| 弹窗里的条目 | 跟弹窗一起出现，**不错峰** | — |
| 页头底色 | 与登录页同款慢速流动（同色同速，复用 `GradientWave`） | 持续；`prefers-reduced-motion` 时静止 |
| 关闭 | 直接消失（`v-if`） | 0ms |
| ✦ 蓝点 | 出现/消失瞬时，不弹入不脉冲 | 0ms（同铃铛红点 C7-03） |
| 入口提示（看完弹窗后在 ✦ 下出现一次，4 秒后消失） | `translateY(-4px)` + 淡入 | `--dur-fast` `--ease-out`（`fp-pop-in`） |
| 刷新提示条 | 底部淡入（**不上移**：它靠 `translateX(-50%)` 居中，位移帧会把它推到一边——同 `.fp-net-toast` 的既有注释）；不自动消失 | `--dur-base` `--ease-out` |
| 减少动态效果 | 全部 1ms 到终态、页头静止 | `motion.css` 既有全局规则 |

## 6. 刷新提示条（Refresh 画板）

**为什么**：页面一直开着的人不会自己拿到新版；而每次部署整个前端镜像换掉（`frontend/Dockerfile` 只拷新构建产物），
旧的按需加载块在服务器上已不存在——他再点开一个本次会话没打开过的屏就会加载失败。今天只有登录页处理了这种失败。

- **载体**：`AppShell.vue` 的 `.fp-net-toast` 家族第三条（前两条：网络错误、预览页签被顶），位置/颜色/按钮完全一致，只换文字；
  两条同时在场时更新这条在上（`.stacked`，`bottom: 84px`），S 档抬到底栏之上。
- **三种文案**：
  1. 有新版：`灵睿已更新到 v0.13.0，刷新后生效` + 「刷新」
  2. 页面打不开（按需加载失败后立刻出）：`这一页属于新版本，刷新后才能打开` + 「刷新」
  3. 编辑态：`灵睿已更新到 v0.13.0。你正在编辑，保存后再刷新`（后半句 `rgba(255,255,255,.62)`）
- **怎么发现**：构建产出一个极小的版本文件，页面每 5 分钟问一次 + 标签页切回时问一次（服务器对它设不缓存）；
  另外任何按需加载失败直接按第 2 种显示，不等轮询。**不管后端版本**。
- **不自动刷新**（会丢未保存的东西），**不自动消失**（网络错误那条 8 秒自消，这条要等人处理）。
- **点 ×**：本标签页不再为这一版提示；之后真有加载失败仍出第 2 种。
- 刷新后回到当前地址，随即命中 §3 的条件弹「本次更新」。

## 7. 数据从哪来

| 东西 | 来源 |
|---|---|
| 版本号 | 构建时从 `frontend/package.json` 注入；同一个值写进版本文件供 §6 轮询 |
| 更新内容 | 前端一个手写文件 `src/changelog.ts`：每版一段（版本号、日期、一句话标题、三组条目、可选跳转目标） |
| 已读 | 浏览器本地，按账号分开（`localStorage`）；换电脑或清数据会再弹一次最新版 |

**发版时要做的**：改 `package.json` 版本号 → 在 `changelog.ts` 顶部加一段 → 正常构建部署。什么时候必须做，见 §8。

## 8. 什么时候必须写更新公告

> 这一节是摘要。版本号、内容结构、字数、配图、动图、观看体验、检查清单的细则都在 `docs/design/RELEASE-NOTES-SPEC.md`（2026-09-19 对标市面产品定的），两处不一致以那边为准。

**判据：这个改动用户在屏上看得见吗。** 看得见（新屏、新功能、用法变了、修了用户碰得到的错），就在**同一个 PR 里**把下面四件事做完，不留到「发版时再说」；看不见（测试、构建、日志里的报错、内部整理），不写、不改版本号。

1. **版本号**：`frontend/package.json` 的 `version` 往上涨 —— 功能更新涨中间一位（0.14.0 → 0.15.0，自动弹），小调整涨最后一位（0.15.0 → 0.15.1，不弹），怎么判定见 RELEASE-NOTES-SPEC §2.1。**合并进 master 就自动部署**（CI 的 deploy 任务），所以每个用户看得见的 PR 合并就是一次发版；别的 PR 先合并、占了这个号，就同步 master 后再往上涨。
2. **更新内容**：`frontend/src/changelog.ts` 最前面加一段。结构、字数、句式照 RELEASE-NOTES-SPEC §3–§4，`changelog.spec` 会自动查其中能查的部分。「修复」写「原来哪里不对」之前，先对照 master 核实原来确实如此。
3. **重点卡配图**：有重点卡的版本在 `components/shell/release/` 新建 `Art<版本>.vue`、登记进 `art.ts`（每版一张，不覆盖旧的），并渲染确认放得下（配图内宽 178px），细则见 RELEASE-NOTES-SPEC §5。
4. **核文案**：这些字原样上屏。写完派 `screen-copy-adversary` 逐句对照源码核一遍，查出的不实之处改掉再提交。

PR 描述和收口消息里写一句：版本号是多少、公告里讲了哪几条。

**这几件事要在 PR 交给用户之前推上去。** PR 一合并就部署，之后再往那个分支推的提交不会进 master；要补，先查 PR 是不是已经合并（`gh pr view <号> --json state`），合并了就另开 PR。

> 来历：2026-09-19 页签栏（PR #43）开出去时漏了这四件事，用户追问「你没有放更新公告吗」才补；补的时候复查又查出两句不实（首页上点导航其实是开新页签；头像上写的是名字后两个字，不是全名）。补的提交推上去时 #43 已经合并部署 —— 没进 master，页签栏以 0.13.0 的版本号上了线，只好另开 PR。
