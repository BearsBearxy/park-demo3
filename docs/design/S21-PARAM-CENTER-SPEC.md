## 0. 一页结论

| 问题 | 结论 |
|---|---|
| G「公摊分摊度数」怎么来 | 五本一期源册公式**完全一致**：`G = ROUND(SUM(公共电分摊明细!S5:S9)/6, 2)`（园区 5 表：车库东/西照明、A1大堂、招商中心净电、生活加压泵；路灯不在分子；分母 6 手输）。引擎公式本就是这个；2023-08 差 670 的病根是 **rule 23 招商中心净电的默认加度 −670**（`alloc_rule.extra_qty` 列，对所有月份生效）。招商净额 = 电1+电2 − 5 子表 − 当月扣度，扣度只在 2023-12（−1470）和 2024-02（−670）出现，其余月为 0。**修法：默认 0，扣度做月参。** |

## 1. 调研结论（证据摘要）

### 1.1 一期源册 2023-08~12（p1_synthesis.md）
- 损耗表 G 公式五月一致；招商净额项 10/11 月**引用落空为 0、12 月手扣 −1470 变负**——源册数据事故，非口径。

### 1.3 引擎/价目盘点（code_engine_params.md / code_price_params.md）
- 参数四处存放、三套版本语义（§0 已述）；**alloc_cfg 月行不前滚** → 2024-02 校准的 36 条系数/6 条加度/10 条加点/宿舍单价与手输量到 2024-03 全部静默失效；**默认行对所有月生效且 UI 零写入口** → 2023-08 三处差额的根因。
- 价路分裂：一期损耗费单价走 `alloc_cfg p1.price_flat=1.11417`（默认行、截断值），二期 `p2.price_loss=1.25312`，与池成本走的价目簿月价两套；`recon` 端点还在读库里不存在的 `p2.price_norm/…`。
- 引擎在读、界面改不了的键：`manual_qty / price_override / std_add / park_share_div / loss_head / loss_c_meter / loss_recon / loss_supply_meter / 默认行一切`；价目侧 `fire_amount_fixed / loss_base_form(_b{bid}) / loss_base_park_amount|meter / lamp_rate` 白名单外。
- 死键/死行：`green_rate_live×16 / lamp_rate_live×10 / dorm.loss_rate / p2.lamp_rate|green_rate zone 行`。
- 生效链断点：价目页/系数簿保存后无「去重生成」引导；池快照与催缴单双重生成用户易漏；改参后屏上数字仍是旧快照无提示。
- BillNoticeService **无任何单价字面量**（全部走库）；Java 里剩的是结构常数（费键当行为开关、铝缆靠表名、率 4 位、dorm 不进损耗组等）。

### 1.4 成熟产品做法（ux_research.md）
- 国内物业系统三层：费项 → 收费标准（单价/公式）→ 绑定对象 + 起止日期；「每户单独录入」是标准的一种；「费用可清除或重算」是显式动作。
- ERP：**valid-from 版本 + 新版本自动截断旧版本**（SAP 条件记录）；**改错 vs 改变二选一**（Oracle DateTrack Correction/Update）；用过的版本只能归档不能删（Stripe）；每个生效值可展开「命中链」（户→栋→期→园区，找到即停）。
- 生效 UX：保存后横幅列影响范围 → 预览 → 一键重算（Terraform plan）；变更历史带 who/when/旧→新。
- 文案：先说对象、再说规则、再给算式；不出现字段名/id/枚举值；「仅 X 月」/「X 起长期」；不出现「默认·所有月份」。

## 2. 参数模型（统一）

### 2.1 一条参数 = 键 + 作用域 + 生效方式 + 值 + 备注

| 维度 | 取值 | 说明 |
|---|---|---|
| 键 `cfg_key` | 注册表白名单（§3） | 前后端各一份镜像常量；键之外一律 400 |
| 作用域 `scope` | `''` 全园 / `p1|p2|dorm` 期 / `building:{id}` / `meter:{id}` / `rule:{id}` / `tenant:{id}` | 注册表规定每个键允许的作用域种类；取值级联（户→表/池/栋→期→全园）**找到即停** |
| 生效方式 `mode` | `from`（自 acct_month 起长期，直到更晚版本；`''`=初始版）/ `month`（仅 acct_month 该月） | **新增列**，两表同构。注册表给每键**默认方式**，保存时用户可改 |
| 值 `cfg_value` | DECIMAL(14,8)；枚举/布尔/引用型（表 id、栋 id）也存数字，注册表给字典 | 不加列 |
| 备注 `note` | 来源锚点（"2023-08 源册 一期园区损耗!D5 +8000"） | 可编辑 |
| 变更日志 | `param_change_log`（who/when/表/scope/key/month/mode/旧值/新值/动作） | 新表；`updated_at` 不能当证据（strictUpdateFill 冻结） |

### 2.2 取值规则（两表同一实现 `VersionResolver`）
```
resolve(key, ym, scopes[]):            // scopes 按级联序：tenant:{id} → meter/rule/building → zone → ''
  for scope in scopes:
    rows = 该 (scope,key) 全部行
    hitMonth = rows 中 mode='month' 且 acct_month==ym 的行            → 命中即返
    hitFrom  = rows 中 mode='from'  且 acct_month<=ym 的 acct_month 最大者('' 最小) → 命中即返
  return null
```
- 与 PriceCfgService.resolveHit 现行为**兼容**：现「常数键前滚」= `from`；「月变键仅当月」= `month`。差别只在：判据从「键属于 MONTHLY_KEYS」变成「行的 mode」。
- 与 AllocService 现行为的差别：alloc_cfg 从「''∪当月」变成上式。**迁移把现有月行按键分类转成 from/month，使已生成的三个月（2023-08 / 2023-10 / 2024-02）取值一格不变**（§7.2）。
- `loadCtx` 改为整表载入后按 (scope,key) 分组，Ctx 里保存 resolver（不再是 `''∪ym` 的扁平 map）。alloc_cfg 与 tenant_price_cfg 都 <300 行。

### 2.4 池默认列归一（用户 2026-08-16 拍板：抽屉管「怎么算」，参数页管「算式里的数随时间怎么变」）
- `alloc_rule.coefficient / extra_qty` 两列**退出引擎**：迁移把非空默认值搬成 `alloc_cfg rule:{id}` 的 `'' from` 行（初始版本），`coefficientOf/poolExtra` 只读参数表。一个池的分母/加度只有**一条版本链**，不再有「默认列 vs 月行」两层。
- 池抽屉「③怎么摊」只留结构 5 项（分摊方式 / 基数键 / 出口费项 / 分摊标准算式 / ROUND 位数）+ 表构成 + 受益人；「基数」「默认加度」输入框删除，改为只读一行「当月分母 T=5.7（自 2023-12 起长期）· 加度 +170（仅本月）→ 去计费参数页改」。
- **新建池**例外：area/floor 且无基数键的池需要初始分母才能算，抽屉新建表单保留「初始分母」必填项，保存时经 `ParamService` 写成 `rule:{新id}.coefficient '' from` 行（同表同版本链、有日志）；池建成后该字段不再出现。
- base_key 非空的池（走路灯/绿化/园区/电梯面积基数等价目参数）在参数页**不出**「分母」可编辑行，只显示「分母 = 一期路灯面积基数 80000（价目参数）」并指到那条参数（消灭今天「系数(月)对基数键池是死旋钮」）。
- `validateRule`「area/floor 无基数键须有系数>0」改为查参数表（新建走初始分母字段；既有池按当前生效值）。

### 2.3 注册表 `ParamRegistry`（Java `ParamRegistry.java` + TS `paramRegistry.ts` 镜像，单测断言两份一致）
每键属性：`key, table(price|alloc), label(人话), unit, group(①~④/⑤), scopeKinds[], defaultMode(from|month), monthlyCheck(是否列入「本月核对」), valueKind(number|rate|money|int|bool|enum|ref_meter|ref_building|ref_rule), enumOptions?, formula(算式人话), hint, retired(bool)`。
前端 `PRICE_KEYS`（21 键）并入此注册表（价目页被本页取代，见 §5.6）。

## 4. 公式定稿

### 4.1 一期公摊分摊度数 G
```
G(月, 栋) = ROUND( Σ_{一期 fee_key='park_loss_pool' 的池} 池当月净量 ÷ park_share_div , 2 )
池当月净量 = Σ(绑定表用量×sign) + fold_qty 折入 + extra_qty(仅净额池, 月参, 默认 0)
招商中心净电 = 招商中心电1 + 电2 − 5 只子表 − 当月扣度(extra_qty 月行)
```
- 各栋 G 同值（不再有 loss_g_adj 分栋加减；分栋差异走 loss_adj_qty）。
- 屏上 G 格悬浮给分解：`(45.28 + 59.57 + 138.33 + 893.01 + 1195.53) ÷ 6 = 388.62`（池名+净量逐项，来自本次 generate 的池快照）。

### 4.2 收取租户损耗率 I（栋组 × 月）
```
C = 组头 infra 表Σ（loss_c_meter 设了则只取该表）；cable = 组内「铝缆」表Σ；D = tenant/share/park 分表Σ；E = D − C
分母 = loss_denom_cable ? C + cable : C
a = loss_adj_qty(组内成员栋 Σ, month) ；r = loss_adj_rate(组头, from)
variant(loss_variant): 
  net(0)        I = −ROUND((E − G − a) / 分母, 4) + r
  share_only(1) I =  ROUND(G / 分母, 4) + r
  none(2 或组内无分表)  I = null
loss_rate_manual(组头, month) 非空 ⇒ I = 手工率（覆盖上式；快照同时保存公式值供并排显示）
```
- 调整度数符号：**正数加大损耗（多收），负数减小**。源册三种写法映射：D+x ⇒ a=−x；E+x ⇒ a=−x；G+x ⇒ a=+x（1 期 10 起）；二期 H ⇒ a=H（12 月 J4 加号形态 ⇒ a=−H）。
- 铝缆表识别仍按表名含「铝缆」（改成表属性属另刀）。

### 4.3 损耗费单价（去掉 alloc_cfg 冻结价；只影响公共电核算/对账屏的「度数口径」金额，催缴单损耗费=金额基数×率，不读它）
```
一期/宿舍：price = elec_commercial(ym) + mgmt_fee_commercial   （= 池成本同一口径）
二期：     price = elec_grid_avg(ym) + mgmt_fee                （用户 2026-08-16 拍板 M1：供电局综合月均裸价，① 区每月填；
                                                              缺当月值回退 elec_flat + mgmt_fee）
```
`elec_grid_avg`「供电局综合电价（月均裸价）」= 供电局账单总金额÷总度数，与源册火炬园「高压用电分配」单价同一个数（2023-08~12：1.19129536 / 1.19502904 / 1.09842968 / 1.03205817 / 0.93727966；2024-02：1.09312 = 退役常数 1.25312−0.16），V100 已种六个月。
`recon` 端点 `ruleCostAmount` 同步改走价目簿（p2 分时用四段价+mgmt_fee）。

### 5.2 列语义与文案规则（硬性）
- 「来自」= 命中链尾：`本栋设定` / `继承一期` / `全园默认` / `户级例外(覆盖 全园 0.16)`；点开看整条链。
- 「生效区间」= `仅 2023-08` / `2023-08 起长期` / `2023-08 ~ 2023-10`（右端由下一版本自动推出）/ `长期（初始版本）`。**禁止**出现 `默认·所有月份`、`p1`、`building:13`、`rule:23`、`loss_variant=1`。
- 作用范围列显示：全园 / 一期 / 二期 / 宿舍 / A座 / 招商中心净电（池）/ 力美C201电（表）/ 力灏（户）。
- 值带单位与算式（元/度、元/kVA·月、栋、度、‰）；布尔显状态句；枚举显字典文字。
- ① 区月核对项若本月无专属值，显示灰字「沿用 2023-10 起长期值 12027.34」+ 徽标「未核对」；本月**无值**（各级都没设、命中链空）的全园/期级月核对项不折叠，值格显「— 缺」（与状态条「缺 N 项」对得上）；默认折叠只压对象级（栋/池/表）空行。
- `note` 是用户/迁移写的**自由文本**（来源锚点），历史/变更抽屉原样渲染；禁词规则只管系统文案（label/formula/hint/scopeLabel/valueText/rangeText/sourceChain），不管 note。

### 5.3 编辑交互（EDIT-MODE-SPEC v2）
- 浏览态零写入口；编辑态每行 [改…] → 小弹窗：**值 | 生效方式（○ 仅 2023-08 ○ 自 2023-08 起长期 ○ 改错：原地更正当前版本）| 备注** → 保存。默认勾选=注册表 defaultMode；「改错」仅当当前值来自某个明确版本行时可选。
- 「恢复为长期值」= 删该月 month 行；「结束于 X 月」= 在 X 月写下一版本（值=上级默认或空）——本刀只做删除月行 + 新版本，不做「结束」按钮（YAGNI）。
- 删除版本：仅未被任何已生成月份取用过的行可删（判据：该行 mode/acct_month 覆盖的月份 ∩ 已有 alloc_pool_result 月份 = ∅），否则提示改用新版本。
- 池参数/栋口径的对象选择用现有 FP 选择器（池 Select 按楼栋分组；表用 FPMeterPicker 若无则 Select 搜索）。
- 保存即写库 + 变更日志；成功后 patch 该行（WRITE-KEEP-CONTEXT 铁律二），状态条置「参数已改 N 项」。

### 5.4 历史与变更记录
- 行内 [历史] → 右抽屉：该 (scope,key) 版本时间轴（月份色条：`from` 连续条、`month` 单点）+ 变更日志（时间/人/旧→新/备注/动作）。

### 5.5 保存→生效闭环
1. 保存后状态条：「参数已改 N 项（自上次重算起），本月池核算/楼栋损耗/催缴单为旧快照」+ [重算本月]。

3. 其它屏常驻状态：公共电核算 / 楼栋损耗 / 催缴单 三屏头部显示「参数版本 与 快照 一致 ✓ / 参数已更新，本页为旧快照 ⚠ [去重算]」（判据 §6.3）。
