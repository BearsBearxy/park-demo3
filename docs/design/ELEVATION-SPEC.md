# 主管当场授权提权（ELEVATION-SPEC）v1

> 2026-08-22 用户拍板并落地。参照零售 POS 的「经理授权」与医疗系统的 break-glass。

## 0. 一句话

财务专员点得动他没权限的按钮；点了弹窗说明缺什么；主管走过来在**专员的电脑上**输自己的
账号密码；专员获得 30 分钟该权限；期间每一次修改的审计都同时记下**两个人**。

**这条改动把权限从「墙」变成了「减速带 + 留痕」。** 这是有意的：现实里主管本来就会走过来
点头。真正的硬墙是系统管理、审核、工资录入与全部查看权（见 §2 不可提权名单）。

## 1. 谁能请求提权

做成第 14 个权限点 `elevate:request`，走已有的 `auth_role_perm` 表和角色矩阵屏 ——
客户自己能配，零新表列、零新 UI。

| 角色 | `elevate:request` | 编辑模式按钮 |
|---|---|---|
| 系统管理员 / 财务主管 / 财务专员 / 总经理 | ✅ | 显示 |
| 只读账号 `viewer` / 园区股东 `shareholder` | ❌ | **不显示** |

后两个角色连提权窗口都不该有 —— 挡在 `PermissionRegistry`（URL 层），
`POST /api/auth/elevate` 对他们直接 HTTP 403。

## 2. 什么权限不可提权

`Perm.NOT_ELEVATABLE` = `system:view` / `system:edit` / `elevate:request` / `lock:takeover` / `review:approve`
/ 全部 9 个模块查看点 `master:view` `contract:view` `param:view` `meter:view` `billing:view` `entry:view` `salary:view`
`report:view` `analysis:view`（RBAC-SPEC §11.2 规则 6：查看借得到，「工资只给两个人看」就成了请主管授权 30 分钟的事）
/ 工资录入 `salary:edit`（2026-10-04 用户拍板，RBAC-SPEC §11.8：它隐含工资查看，借得到的话看不见工资的人请一次授权又能往工资表里导数）。
附表 12 页头对没有 `salary:edit` 的人把编辑按钮置灰、写明缺哪一项，不弹授权窗（`SchedHeader` 的 `no-elevate`）。
可批人接口 `GET /api/auth/approvals/candidates` 遇到名单里的点同样 403。

**`system:*` 必须留在名单里。** 能当场授权自己去建账号、改角色的话，提权就成了权限系统的
后门 —— 一次 30 分钟的授权可以换来一个永久的管理员账号，整套 RBAC 当场作废。
系统管理只能主管自己登录进去改。

`ElevationApiIT.systemPermsCanNeverBeElevated` 钉死这条：拿 admin（本人**确实有**
`system:edit`）去授权，仍然被拒 —— 所以拒绝理由只可能是「这一项不可提权」。

拒绝的话分两种（`ElevationService.elevate`，2026-10-04 复查）：`system:*` 照旧讲上面那条理由
（「…否则一次 30 分钟的授权就能换来一个永久管理员账号…」）；名单里其余各项只说去找谁 ——
「「工资录入」不能靠当场授权获得，要请系统管理员在角色里开通。」永久管理员那句对审核、查看、工资录入不成立。

## 3. 服务端

### 3.1 存哪

`ElevationStore`：内存 `Map<username, Map<perm, Grant>>`，TTL **30 分钟**，惰性清理。

不落库：授权是短命的会话态，落库要配清理任务、处理陈旧行、重启读回来。掉一次授权的代价是
重新叫主管点一下头，比维护一张只涨不跌的表便宜。真正要持久的那部分（谁授权谁做了什么）
落在审计日志里，那个一行不能丢。

> ponytail 上限：单实例态。多副本时授权不跨副本 —— 表现为「刚授权完下一个请求又要授权」。
> 到那一步再换 Redis。

**账号被停用 / 角色被改 → 授权一并清空**（`UserPermissionCache.reload()` 里）。**本人登录、登出、改密 → 本人授权清空**（`applySession`，2026-10-03 起）。
不清的话「停用立刻踢」这条就有个 30 分钟的洞。

### 3.2 判定接在哪

**`WriteAccessManager` —— 唯一的咽喉。** 角色判定失败后多问一次 `ElevationStore`，
命中就放行，并把授权人塞进 request attribute。

**126 个写端点一行不用改，全部自动支持；审计也自动带上授权人。**
接到业务层就是几十处散弹，且必漏。

例外是 URL 判不了要哪个权限的地方 —— `PUT /api/params`（按 `cfg_key` 分月度录入 / 计费口径两档）、
按账期批删读数连带删草稿催缴单（要 billing-run）、抄表导入改已有表倍率（要 meter-master，2026-10-03 起）。
这些走 `PermissionGuard`，语义完全一样（含主管临时授权）。

### 3.3 审计

`auth_audit_log.authorizer` 与 **`param_change_log.authorizer`（V103 新增）** 两张表。

后者不能省：最典型的提权场景就是改计费口径，而计费口径的日志走的是 `param_change_log`，
不是 `auth_audit_log`。缺这一列，整套提权的审计价值落空。

`value_change_log`（2026-10-05，RBAC-SPEC §14）的 authorizer 列 V139 补上（同日对抗复查）：提权期间手改的台账、读数、工资、报表、损益附表、目标与阈值记授权人（`ElevationStore.currentAuthorizer()`），操作日志那一行写「由 X 授权」。

日志长这样：

```
李四  改参数  loss_rate · A座 · 2026-08   0.2067 → 0.1980   授权人：张三
```

出事时查得清：**手是李四的，责任是张三的。**

### 3.4 这是一个口令试错口

`POST /api/auth/elevate` 让**任何已登录账号**都能拿它猜主管的密码。所以：

- 与登录共用 `LoginRateLimiter`，键 = `ip|授权人用户名`，5 次失败锁 15 分钟
- 失败**也进审计**（`elevate.deny` / `elevate.locked`）——「有人在反复试主管密码」
  必须查得出来，这正是审计存在的意义
- 授权人不存在 / 已停用时空跑一次 BCrypt（`DUMMY_HASH`），否则靠响应快慢能枚举用户名
- 不能给自己授权 —— 审计里出现「张三授权张三」是看似有责任人、实则没有

### 3.5 端点

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/auth/elevate` | `elevate:request` | `{perms[], authorizer, password}` → 授权 30 分钟。一次可补多个权限点（一个页面常同时要两三项，不该让主管输三遍密码） |
| DELETE | `/api/auth/elevate` | 任何已登录 | 结束本人全部授权，幂等 |
| GET | `/api/auth/elevate` | 任何已登录（RBAC-SPEC §11.3） | 刷新页面后恢复顶栏授权胶囊（§4.5） |
| GET | `/api/auth/perms` | 任何已登录（RBAC-SPEC §11.3） | 权限点字典。`/api/system/perms` 要 `system:view`，而弹窗要给**没有它的财务专员**看「你缺哪几项」 |

## 4. 前端

### 4.1 `auth.can()` 把提权并进去

```ts
can(key) = 角色给的 ∪ 有效授权
```

**59 处调用点一处都不用改。** 导航那几处（`can('system:view')`）行为完全不变 ——
`system:*` 在不可提权名单里，永远不会出现在授权里。

判断「这一项需不需要请人授权」用 `hasOwn(key)`（只看角色）。

到期不靠后端：`grants` 里带 `expiresAt`，前端每秒 tick，倒计时归零时写入口同时消失 ——
否则用户点下去才发现 403。

### 4.2 授权在哪作废

只有两个点：**主动点「完成」退出编辑模式** 和 **30 分钟到期**。
另有两条随之作废的路：在授权卡片上点「结束授权」（§4.5），和被系统提前收回（心跳报告授权没了，EDIT-MODE §6.2）。

⚠ 切页签**不**作废 —— 见 EDIT-MODE-SPEC v3 ①。专员切去别的页面核对一眼回来，
授权还在。

登出、重新登录、改密：由服务端结束本人授权（`UserPermissionCache.applySession`，2026-10-03 起），前端不再单独发 `DELETE`。
原来是前端登出时先发 `DELETE` 再清令牌，但请求拦截器异步执行、读到的 storage 已经清空，那一发从来没带上令牌（安全审计 F01 / F88）。

### 4.3 入口长什么样

**点「编辑模式」→ 缺任何一项就当场弹授权窗。**

| 选择 | 结果 |
|---|---|
| **[确认授权]** | 主管当场输账号密码 → 补齐 → 进编辑模式 |
| **[取消]** | **什么都没发生，留在浏览态** |

⚠ 2026-08-22 晚用户纠正:初版取消后会「用现有权限进编辑模式」,页面上冒出
`重新生成`/`完成` 等编辑态按钮 —— 用户认为那不叫"没通过授权"。现改为不进。

**代价**:财务专员要用公共电核算的「生成本月」也得先拿授权(那页两档权限都要)。
用户看过这个代价后仍选此方案。

**推论:编辑模式里不再有「点不动的控件」** —— askPolicy / askMonthly 那类包装已全撤。
配套地,授权到期会**自动退出编辑模式**(见 EDIT-MODE-SPEC v4),否则到期那一刻控件集体变灰。

⚠ **没有「本页还缺 N 项」的提示条。** 初版加过,它撑开了整页布局,被用户否掉 ——
信息已由授权弹窗给到,不需要第二遍。见 [LAYOUT-STABILITY-SPEC](LAYOUT-STABILITY-SPEC.md)。

- 授权期间看得见：顶栏授权胶囊 + 授权卡片，见 §4.5。（2026-10-03 前是 App.vue 顶上一条 fixed 满宽横幅「由 王主管 授权 · 可修改：计费口径 · 剩余 28:14 · [结束授权]」，盖在页签条上，已撤。）

### 4.4 授权是按权限点精确发放的

授权 `param-policy:edit` **不会**顺带打开 `param-monthly:edit`。
`ElevationApiIT` 第 ⑤ 步钉死这条 —— 挂掉就意味着「授权改 A」实际给了「什么都能改」。

### 4.5 顶栏授权胶囊（2026-10-03 用户定，画布 08 ElevChip / ElevStates）—— 已实现（jfen/elev-reports-params-import）

推翻 §4.3 原来的「全局横幅」。组件 `components/fp/FPElevChip.vue`，回执在 `App.vue`，小工具在 `utils/elevation.ts`。

**一「份」授权** = 同一次批准补齐的那几个权限点（同一个授权人、同一个到期时刻）。一次授权常常同时补两三项，它们一起到期，屏上算一份。

| 块 | 做法 |
|---|---|
| 胶囊 | 顶栏右区 ✦ 与铃铛之间，28 高蓝描边胶囊：钥匙 + 剩余 `m:ss`（分不补零、秒补零，取先到期那份）；多份时尾部带份数。没有授权时不渲染 |
| 卡片 | 点胶囊贴着它右对齐弹出，420 宽，**页面不变暗**；点外面 / Esc 收起。挂 body + fixed（顶栏自成层叠上下文），层级 `--z-modal-2` |
| 一份的卡片 | 卡头「临时授权 / 剩余 m:ss」；授权人（头像 + 名；远程批准的名后加一个灰字「远程批准」）；可修改（权限签 + 「所有页面都能改」）；时间「hh:mm 授权 → hh:mm 到期」（远程批准写「hh:mm 批准」）；「这次授权已记进操作日志，写明由{授权人}授权。」（稿上是「期间的每一次修改，操作日志里都会同时记下你和{授权人}的名字」，不成立：授权人只落在 `param_change_log` 与 `auth_audit_log`，台账格、抄表读数这类写入不进操作日志（2026-10-05 起进「数据修改」一路，V139 起带授权人，RBAC-SPEC §14；合同、催缴单等写入仍不进），导入 / 表档案 / 审核三路的授权人列恒空。2026-10-03 对抗复查改成只说成立的那件：授权本身那条 `elevate.grant` 带授权人）；卡底两句「结束后，用到这份授权的页面会退出编辑 / 点「完成」退出最后一个编辑页时，授权一并结束」+「结束授权」 |
| 多份的卡片 | 卡头「临时授权 · N 份 / 先到期的剩 m:ss」；每份一行（权限签、授权人、hh:mm 到期、倒计时）；「哪一份到期，用到它的页面就退出编辑。」；卡底「两份（N 份）一起结束」+「结束授权」 |
| 最后 1 分钟 | 胶囊和卡里的钥匙、时间变橙；底部出一条**不自收**的回执「授权还剩 1 分钟」，每份只出一次；卡片只剩卡头和卡底「到期后，用到这份授权的页面会退出编辑」。没有哪份在最后 1 分钟了（到期 / 结束 / 完成）就把这条回执收掉 |
| 结束前先问 | 点「结束授权」时，**会因此退出编辑**的屏有没保存的改动（`auth.dirtyScreens()`，即 EDIT-MODE §6.1 那套改动数；登记编辑器时带了权限点（`openEditor` 第四参）且全是自己角色给的不算 —— 结束授权它不退、改动不丢；没带的按「靠授权」算，宁可多问一句）→ 确认框「结束授权？」，正文「{页名}有 N 处改动还没保存。结束授权会退出编辑，这 N 处改动不会保存。」（多屏时页名顿号连起来、处数合计；改动数数不准的屏不报处数），按钮「继续编辑」/「放弃改动并结束授权」（红）。0 处不问 |
| 结束时的回执 | 见 EDIT-MODE §6.2：到期 / 提前失效 / 一份先到期三句分开写；点「完成」或「结束授权」不出回执 |
| 弹窗开着时 | 系数簿、收款簿、催缴单明细的标题旁挂同一枚胶囊（22 高）；卡片左对齐胶囊；回执在遮罩之上（`--z-toast`） |
| 手机（S 档，用手机顶栏的那一档） | 胶囊只留钥匙圆钮，页名让位截断；卡片贴顶栏下占满宽，时间写在卡里；卡里没有「所有页面都能改」、操作日志那句和「完成」那句，卡底一句「结束后，用到它的页面会退出编辑」 |

**「几点授权」与「远程批准」怎么来的**（2026-10-03）：`ElevationStore.Grant` / `GrantDTO` 带 `grantedAt`（毫秒）和 `source`（`onsite` | `remote`）：`ElevationService.elevate`（主管在请求者电脑上当场输密码）记 `onsite`，`ApprovalService.decide` 批准（主管在自己电脑上批）记 `remote`；续期整份覆盖，授权时刻、来源跟着换成这一次的。`GET /api/auth/elevate` 下发。卡片时间行直接用 `grantedAt`；远程批准的那份在授权人名后写「远程批准」，时间行「hh:mm 批准 → hh:mm 到期」（画布 08 ElevStates「远程批准」格）。旧后端没带 `grantedAt` 时才按「到期 − 30 分钟」推（`ELEV_TTL_MS`）。`ElevationApiIT.grantCarriesSourceAndGrantedAt` 钉住两条路。

**多份里一份先到期**：用到它的屏退出编辑；就算那是最后一个编辑页，别的份也照留、不去服务端收回（`endElevation()` 认得「到期那份还没摘 = 是到期把它踢出来的」，只摘到期的；到期那份在这一拍各屏守卫跑完后才从 `grants` 里摘掉）。之后点「完成」退出最后一个编辑页，剩下的照常一并结束。

**「结束前先问」列得准不准，看登记时带没带权限点**：全站登记点都已带（2026-10-03）—— `useEditMode`（本屏 `perms`）、附表页头（`perm`）、系数簿、收款簿、公司账簿（`master:edit`）、新建 / 编辑合同（`contract:edit`）、角色管理（`system:edit`）；只在锁上登记的三处由 `useEditLock` 第四参带：三大报表（`report:edit`）、账册模板（`book-template:edit`）、台账宽表（`entry:edit`）。`useEditMode` / 附表页头 / 系数簿底下那把锁不另带：它们递给锁的是同一个改动数函数，`dirtyScreens` 听带了的那条。

## 5. 顺带修掉的两个既有洞

1. **`PUT /api/params` 的口径细分只写在注释里没实现。** URL 层收「policy 或 monthly
   任一」，而按 `cfg_key` 的判定不存在 —— 只有 `param-monthly:edit` 的财务专员
   绕开前端直接调 API 就能改**任何一个计费口径键**。前端把按钮藏了，后端的门是开的。
   （`ParamPermissionSplitTest` + `ElevationApiIT` 现在钉死。）

2. **`POST /api/price-cfg/copy`（复制上月电价）挂错档。** 前端按 `param-monthly` 画按钮，
   后端要 `param-policy` —— 财务专员看得到按钮、点下去 403，而那正是他每月的活。

## 5.1 随之调整的角色矩阵（V104）

**月度电价 `param-monthly:edit` 从财务专员手上收走**（用户拍板 2026-08-22）。

原本给他的理由是「不给他，催缴单就出不了账」。**提权把这条从"不可行"变成了"可行"**：
专员每月点一次编辑模式，主管当场授权 30 分钟，足够录完那 14 个键，而且每一次改动都
记着两个人的名字。

电价是决定**每一户账单**的数字，录错一位数全园的催缴单一起错 —— 值得每月被主管过一次眼。

专员保留：抄表读数、台账/附表录入、出账运行（生成/重算）、报表。

> 代价：专员每月多一次「叫主管过来点一下」。这是用户明确选择的。

## 6. 未做

- 授权的**范围**只到权限点，不细到「哪一行」。真要「只授权改这一个池的系数」得引入
  对象级授权，复杂度跳一档，且现实中主管授权时看着屏幕，范围由人把关。
- 主管在别人电脑上输密码这件事本身有风险（键盘记录器）。内网工具可接受；
  真要消除得上二次设备确认。
