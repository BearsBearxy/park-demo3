# 表档案按月记录规范（METER-TIMELINE-SPEC）

2026-09-24 定稿。用户原话（六条要求）：

> R1 用户每导入一个月如果有不同，不能直接给全部月份的都改了
> R2 某个月份如果租户变动会出现的水电表变动，没有则从这个月份开始保持直到下一次改动
> R3 后面月份改动不会改变之前月份
> R4 之前月份如果改动也不能改变已有的后面月份
> R5 电表有停用但是还要显示在册上，停用从什么时候开始到什么时候结束
> R6 什么时候拆了，但是拆除不能影响之前已录入的月份

外加用户旅程复核（2026-09-24，10 agent 对抗复核）坐实的 35 条缺口，本规范一并收掉。
上位/相邻规范：METER-SPEC（表与读数）、METER-IMPORT-SPEC（导入认表）、S2-BIND-SPEC（合同绑定）、
BILL-NOTICE-WARN-SPEC（催缴告警）、S21-PARAM-CENTER-SPEC（需重算）、EDIT-MODE-SPEC（编辑态与锁）。
本规范与它们冲突处以本规范为准，并在那边加一句指回来。
**落地与下文不一致的地方以 §9 为准**（2026-09-24 收口时照实现回写）；§10 以 §10.5 为准。

---

## 0. 一句话

**表档案不再是一份，而是一串「从某月起是这样」的记录。只记起始月，不记结束月。**
看某个月 = 取「起始月 ≤ 这个月」的最后一条。没有结束月这一栏，就不存在「改前面顺手改了后面」。

---

## 1. 数据模型

### 1.1 `meter`（资产，不分月）
只留：`id kind zone name code factor device_type meter_type sort_no suspect is_dorm_room` + 时间戳。
表编号变了 = 换了一块表（拆旧装新），不是改 code。

### 1.2 `meter_assign`（归属，按月分段）
| 列 | 说明 |
|---|---|
| `meter_id, from_ym` | **UNIQUE**。一块表一个月最多一行 |
| `tenant_id, tenant_name` | tenant_name = 原册企业名称原文 |
| `building_id, ownership, area, spot, floor_label, side, room_no, sub_name` | 位置与归属 |
| `contract_id` | 人工钉的合同，只对这一段有效 |
| `tenant_manual, owner_manual, loc_manual` | 人工设定标记，**只锁这一段**（见 §3.2 G2） |
| `src` | `import / manual / migrate / contract` |
| `batch_id` | 导入批次（§3.5 撤销用），其它来源为空 |

### 1.3 `meter_status`（存在与状态，按月分段）
`meter_id, from_ym`（UNIQUE）、`status ∈ active | retired | removed`、`src`、`batch_id`。

| status | 册上 | 抄表进度/分母 | 计费（分摊、催缴） |
|---|---|---|---|
| 无（早于第一条） | 不在册 | 不计 | 不计 |
| `active` 在用 | 显示 | 计 | 计 |
| `retired` 停用 | **显示，标「停用」** | 不计 | 不计 |
| `removed` 已拆 | 不显示（筛「已拆」可见） | 不计 | 不计 |

取代旧列 `active_from_ym / retired_ym / removed_ym`（迁移后删除）。

### 1.4 `meter_archive_log`（每一次写都留底）
`meter_id, tbl(assign|status), from_ym, action(insert|update|delete), before_json, after_json, src, batch_id, file_name, row_ref, operator, at`。
抽屉「档案变更」页签、操作日志、撤销导入都读它。（列名落地为 `tbl`：`table` 是 MySQL 保留字，照 `param_change_log.tbl` 的先例。）

### 1.5 `data_change_log`（给「需重算」用）
`ym, source(meter-archive|meter-reading), changed_at`（Java 时钟写，与 param_change_log 同口径）。

## 2. 读

- `assignAt(表, ym)` = `from_ym ≤ ym` 的最大那行；早于第一行时取第一行（防御，正常路径不会发生）。
- `statusAt(表, ym)` = 同上；早于第一行 = 不在册。
- 一段的覆盖区间 = `[from_ym, 下一行的 from_ym)`；没有下一行 = 一直到以后。
- **所有带月份的读取只走一个入口**（后端 `viewAt(ym)` 一次装全部行，内存取值），禁止逐表子查询。
- 没有月份语境的读取（如档案枚举）取「最新一行」。
- 前端 `GET /api/meters?ym=` 返回站在 ym 看到的档案；**切月必须重拉**。

## 3. 写

### 3.1 总纪律
- 任何写都是「在某月写一行」（插入或更新该月那行），**绝不顺手改别的行**。
- 每次写都进 `meter_archive_log`，并对受影响区间里的每个月记一条 `data_change_log`（迁移除外）。

### 3.2 导入 M 月的册子
**每个导入的月份都写自己那一行，值和上一行一样也写**（R4 的地基：后面每个有册子的月份都有自己的一行挡着）。

逐行：`base = assignAt(M)`（写之前的样子），`want = base` 叠上册子的非空值，经过下列护栏，写入 M 行：

| # | 情形 | 处理 |
|---|---|---|
| G1 | 企业名称空 | 沿用 base 的租户 + 提示（现有） |
| G2 | base 上有人工标记（租户/归属楼栋/楼层方位房号三组） | 该组保留 base 的值并把标记带进 M 行；册子不同则提示 |
| G3 | 企业名称与 base 不同、但认不出是谁（tenant_id 解析为空） | M 行 tenant_id 置空 → 进「待核」，**不沿用老租户** + 提示 |
| G4 | 企业名称写着「停用」字样 / 编码写着「已拆」 | 不当租户名写；改状态：停用 → retired@M；已拆 → 有读数 removed@M+1，无读数 removed@M。提示 |
| G5 | 按编码认到的表，期区与这一行的期区不同 | **行级错误，整行不写**（243 那种错码） |
| G6 | 同一批里同一块表同一月被认到两次、读数不同 | 后一行行级错误，不覆盖 |
| G7 | 倍率 | 只有 M ≥ 该表已有最新读数月时才写回 `meter.factor`；否则只进本行 `factor_snap` |
| G8 | 按位置/标识认表 | 不认 M 月已拆的表；按编码认到 M 月不在服务的表且读数非空 → 照写读数 + 提示「自 X 起已拆/停用，本行有读数未计费」 |
| G9 | 按位置新建的表与一块在册旧表同址 | 提示「可能是换表：旧表 X 仍在册」 |
| G10 | M 早于该表第一条状态，且本行有读数 | 状态补 active@M、归属补 M 行（自愈）；读数为空不自愈 |
| G11 | 冻结月（§4） | M 月整批冻结（审核锁）→ 现有整批拒；单表冻结（已确认/已导出单含这块表）→ 读数照写、档案不改 + 提示 |

「变了」的判据（用于提示与「本月有变化」）：比 `租户(两边都有 id 比 id，否则比规范化名) / building_id / ownership / area / spot / floor_label / side / room_no / sub_name / contract_id`。规范化 = 去首尾空白、压空白、全角转半角。**推导列为空视为未知，不参与比较。**

批级断言：本批写入的所有行，from_ym ∈ 本批月份集合 ∪ {G4 的 M+1}，否则整批回滚。

导入结果逐条列出：`表 · 字段 · 旧 → 新 · 影响 M ~ Y`；G1–G11 的提示照列。结果带回本批 `batchId`。

### 3.3 屏上手改归属（抽屉，编辑态）
在查看月 V 改，当前生效行起始月 F：
- F = V：直接改这一行。
- F < V：二选一，**都写明影响哪几个月**：
  - 「更正自 F 起那一行」影响 F ~ 下一行前；
  - 「从 V 起变更」（默认）影响 V ~ 下一行前。
- 后面若有 `src=migrate` 且值与改前相同的行（上线时复制的同一份档案），给复选框「一并更正后面 N 段（上线时复制的）」，默认不勾。
- 同房间其它表（同楼栋 + 同房号，站在 V 看）一并列出、默认勾选，用同一个起始月一起写。
- 改动的字段组在目标行上置人工标记；抽屉显示「人工设定」及「改回按册子」（清掉这一行的标记）。
- 区间里有冻结月的选项灰掉，写明是哪个月、为什么。不提供「覆盖并清掉后面所有变化」。

### 3.4 状态（停用 / 恢复 / 拆除 / 新装）
- 抽屉状态区是列表：「自 M 起：在用 / 停用 / 已拆」，可加一行、可删一行（删 = 撤回误标；第一行不能删，只能改月）。
- **拆除问「最后一次抄表是哪个月 L」，写 removed@L+1**（拆表当月读数照收）。
- 写停用/拆除前，数出受影响区间里已有的非零读数，让用户确认「这 N 个月的读数将不再计费」。
- 拆除时提示这块表所在的公摊池与钉的合同（旧表不必移出池，自拆除月起自动不计；新表要自己加进池）。
- **新增表从当前查看月起在册**（弹窗显示「自 M 起在册」，可改）。
- 抽屉给早于第一条状态的月份补读数 → 同 G10 自愈，确认框写明「这块表将从 M 起在册」。
- 新表首月没有上月读数：抄表格开放「上月行至」录入起始底数；只有本月读数没有底数时，行状态为「缺底数」，不算已抄。

### 3.5 撤销
- 「批量删除本期」一并删除 `from_ym = 本期 且 src = import` 的归属行与状态行，预览里报数。
- 抽屉「档案变更」里每条导入来源旁有「撤销这次导入的档案改动」：按 `batch_id` 逆序还原 before_json（插入的删掉、更新的改回），**读数不动**（确认框写明）。区间里有冻结月则拒绝并列出。

### 3.6 合同联动
- **终止合同**：确认框列出这户在解约月挂着的表（同房号的默认勾选），勾选 → 写「解约次月起空置」行（tenant 置空、contract 置空，src=contract）。确认框写明「解约当月水电按月抄表，整月仍算原租户」。
- **待绑定 / 场地未定**：反查本月在租、场地含这块表房号的他户合同，给「从本月起改归 X」。
- 合同钉挪进归属行；**钉的合同不属于该月租户家族时不采用**，回落自动规则并告警。
- 换租写新行时不继承 contract_id。

## 4. 冻结与锁

某块表在某月 **冻结**，当且仅当：
1. 该月抄表审核处于锁定状态（ReviewGuard METERS），或
2. 该月有已确认/已导出的催缴单，其明细含这块表。

所有写（导入除外见 G11、手改、状态、合同联动、撤销）按受影响区间逐月查冻结；链尾段的区间取到「库里最大已生成月」为止，不退化成只查一个月。
后端是判据的唯一来源；前端灰选项调同一个查询。

---

## 5. 下游

- **需重算**：`snap()` 的 lastChange 并入 `data_change_log`（档案与读数改动）。提示文案从「改过参数」扩成「改过参数或抄表」，所有显示处同步。
- **公摊池**：池里 +1 绑定的表，只在该月归属属于公摊类（与 poolCandidates 同口径）时计入。池编辑里已拆的表显示为灰行「自 M 起已拆，不计」；移出有读数的表时确认框列出有读数的月份。
- **催缴单生成**：本月已被锁定单收过的表，不再出进别户的草稿单，并出告警。
- **已导出单**：明细行实时比对当月档案，不一致标「档案现归 X」（照收款公司橙点的做法）。
- **作废并重出**：已导出户抽屉提供「作废」（理由必填、落审计），作废后重新生成本月即重出。
- **操作日志**：档案写入进操作日志（表 · 月 · 旧 → 新 · 来源）。

---

## 6. 抄表屏

- 状态筛选加「本月有变化」（该表在本月有自己的行且与上一行不同）。
- 隐藏表提示条、状态提示按状态段说话（「停用 2024-03 ~ 2024-08」「自 2024-09 起已拆」），不再教人「清空账期」。
- 导出当月只导站在该月在册的表，档案取该月的值。

---

## 7. 迁移（一次性）

1. 归属：**每块表在它有读数的每个月各写一行**（2023-08 / 2023-10 / 2024-02），值取当前档案；没有读数的表写一行，起始月 = 原启用月，没有则取最早账期。src=migrate。
2. 状态：active@首月；原 retired_ym → retired 行；原 removed_ym → removed 行（旧语义「自该月起不在服务」与新语义一致）。
3. 原表级人工标记与合同钉复制到该表的每一行。
4. 迁移不写 `data_change_log`、不写 `meter_archive_log`。
5. 迁移后删除 meter 上被搬走的列。

上线后建议把三个月的原册各导一遍，每个月回到自己册子上的样子（「2 月显示 5 月的名字」随之消失）。

## 8. 不做

| 不做 | 理由 |
|---|---|
| 月中换租按天拆水电 | 水电一个月只有一次读数，没有可拆的依据；只在确认框和终止框里写明整月归谁 |
| 催缴单行上写「整月归谁」备注 | 同上；终止框已说明，单上再写需要逐户判合同起止，收益低 |
| 按年锁跨年补占 | 现有取舍（lockScopes 按年），不是本次引入的洞 |
| 「覆盖并清掉后面所有变化」 | 直接违反 R4 |

## 9. 落地记录（2026-09-24 收口回写）

上文与实现不一致的地方，**以实现为准**，逐条记在这里。接口细节见实施计划 `docs/superpowers/2026-09-24-meter-timeline-plan.md` §1、§2.1–§2.6。

| 条 | 上文写的 | 实际落地 |
|---|---|---|
| §1.4 | 列名 `table` | `tbl`（MySQL 保留字） |
| §3.1 | 受影响区间每月记 `data_change_log` | 早于库里最早已生成月（读数 / 催缴单 / 池结果）的月份不记：那些月没有结果，不会因此需重算；值一格没变的写既不写库也不留底 |
| §3.2 首句 | 值和上一行一样也写 | 上一行相同照写（R4 的地基不变）；**同一个月**已有一行且值一格不差（来源、批次号除外）不重写 —— 重导同一份册子不留底、不亮需重算 |
| G3 | 名称不同、认不出 → 置空 | 只在：规范化后名称不同 + 本行没给 tenantId + 底子上有 tenantId；同名 = 同一户，沿用底子的 tenantId |
| G4 | 「停用」「已拆」字样 | 企业名称含「停用」、编码含「已拆」即命中，两个都有按已拆；写着停用的那行不收 tenantId；「已拆」不拿去认表、不写回编码 |
| G9 | 按位置新建时提示 | 整批导完再判；旧表在本批同一个月的册子里也出现就不提示（两块都在用的同址表不算换表） |
| G10 | 读数为空不自愈 | 已有的表照此；**导入时新建的表**不论有无读数都自 M 起在册（= 新装，§3.4） |
| G11 | 单表冻结 → 档案不改 | 查的区间 = M 那一行归属的区间，加上有状态变更时的状态区间；冻结时编码 / 表类 / 倍率也不改；册子与档案真有不同才提示；**新建的表不查冻结**（它不在任何单里） |
| §3.2 行定位 | 逐条列出、带行定位 | 导入写的变更记录 `row_ref` 为空：前端没把「sheet!行号」传上来 |
| §3.3 F = V | 直接改这一行 | 直接写的条件：F = V（或 V 早于第一段）、没有同房间的表要一起改、没有上线复本、没有冻结月、不是换租户；其余都弹两选一 |
| §3.3 同房间 | 一并列出、默认勾选 | 只在换租户、改归属时列（房号、表名称不该抄到同房间的水表上）；同房间的表用第一块表的起始月一起写，它们各自的冻结月不在弹框里灰显，由后端整批 409 点名 |
| §3.3 换户 | — | 换户时同时写新户名；新写的一段不继承 contract_id（导入换户同样不继承） |
| §3.3 改回按册子 | 清掉这一行的标记 | 位置三列回到按位置原文解析的值；租户与归属的值不动 |
| §3.4 改月 | 第一行不能删，只能改月 | `POST /{id}/status` 带 `replaceFromYm` 挪月（删旧行 + 写新行，同一事务）；只能挪到前后两行之间，越过或落到相邻行那个月 → 409 |
| §3.4 自愈 | 给早于第一条状态的月份补读数 → 自愈 | 只在**新录**本月读数时自愈；改已有读数不补在册（否则会悄悄撤掉有意挪晚的第一行）；补的区间里有冻结月 → 409，读数也不写 |
| §3.4 缺底数 | 新表首月 | 按数据判，不限新表：本月读数没有自带上月行至，或两个月都没有读数；编辑态凡没有底数的行都开放「上月行至」；缺底数算未抄（保住「租户表 = 已抄 + 未抄」） |
| §3.5 撤销 | 按 batch_id 逆序还原 | 另拒「导入后又被改过」的行（现状 ≠ 当时的后像，不比 batch_id），整批 409 列出；还原按原来的来源写回、batch_id 清空，这次的变更记录 `row_ref` =「撤销导入 <batchId>」；**不还原**读数、资产列、导入时新建的表 |

## 10. 本月册子已核（2026-09-24 追加）

用户原话：「做」—— 针对「屏上分不出这个月册子里写的，和上线时照抄、这个月册子里根本没有」。
起因：243（南盛物流电）只出现在二期册子与 5 月建档册里，用户重导一期 2023-08/09/10 后屏上仍是照抄的南盛物流，看不出这一行没被当月册子核过。
迁移后同值重导不改写行（§9），`src` 一直是 migrate，数据上无从区分，所以要单独记。

### 10.1 数据
`meter_book_seen(meter_id, ym, batch_id, file_name, seen_at)`，UNIQUE(meter_id, ym, batch_id)，FK meter ON DELETE CASCADE，索引 (ym)。
「某表在 M 月册子里出现过」= 存在任意一行 (meter_id, M)。

### 10.2 写
- 导入：每一行只要认到表（含新建）、没被判行级错误（G5 期区不符、G6 同批重复等），就给 (表, 行的月份) 记一笔，带本批 batchId 与文件名。G2 人工保留、G11 冻结也记（册子里确实有这块表）。整批一次写入。
- 撤销这次导入：删本批的记录。
- 批量删除本期：按同样的筛选（kind / zone）删该月记录，预览多报一个数。
- **不回填**。上线前的导入不算（那时档案被别的月份覆盖过）；上线后到本功能之前的导入只在 archive_log 里留了有变化的表，回填会把「在册子里但值没变」的表误标成没有。屏上与更新公告写明：想让旧月份标对，把那个月的册子再导一次（同值重导不改档案，只记这一笔）。

### 10.3 读
MeterDTO 加 `bookSeen`（站在 ym）、`bookFile`、`bookAt`（该表该月最近一笔）。ym 缺省时 `bookSeen=false`。

### 10.4 抄表屏
- 按期区 × 表类看当月：**一笔都没有** → 不逐行打标，在表格上方一句「这个月还没导入过 {期区} 的{电表/水表}册子，这些表的档案都是沿用的」（多个期区合成一句）；**有记录** → 没出现的那些行在企业名称旁加小标签「本月册子没有」，悬停写「这个月导入的册子里没有这块表；显示的是自 {assignFrom} 起那一行（{来源}）」，来源 = 上线时照抄 / 导入 / 手改 / 合同终止。
- 状态筛选加「本月册子里没有」（与现有筛选同一个下拉，计数照现有惯例）。
- 抽屉「档案变更」页签：顶部写本月册子来源「本月册子：{文件名} · {时间}」或「这个月导入的册子里没有这块表」。
