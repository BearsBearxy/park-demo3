## 0. 复核结论

### G0.1「净电」是什么（用户问②）—— 账册行8，逐格对上

`rule 23 一期 招商中心·净电`，`method=direct`，通过 `fold_qty` 折入 `rule 24 一期园区·公共电（园区损耗池）`。

复刻账册 `S8 == 一期园区电!X50 + N8`，其中 `X50 == S49+S50-SUM(S44:S48)`（`POOL-FORMULA-AUDIT-2024-02.md:177-180`）：

| | 表 | 倍率 | 上月→本月 | 度数 |
|---|---|---|---|---|
| ＋ | 招商中心电1（总表） | 80 | 379.02→387.74 | 697.60 |
| ＋ | 招商中心电2（总表） | 80 | 136.04→141.60 | 444.80 |
| − | 中大A304公共电1 | 1 | 741→745.74 | 4.74 |
| − | 优凯A305电 | 1 | 1389.5→1389.5 | 0 |
| − | **双成电2（双成金属·三楼K306室）** | 20 | 856.99→872.77 | 315.60 |
| − | 中大4楼公共 | 1 | 858.38→858.38 | 0 |
| − | 4楼空调外机电 | 1 | 2186.59→2186.59 | 0 |

`1142.40 − 320.34 = 822.06`（净额）`− 670`（账册硬编码 `N8`，招商中心自用扣度）`= 152.06 度 × 1.11416875 = 169.42 元` —— 与屏上 `Σ 152.06 度 / 169.42 元` 逐分相同。

**语义**：招商中心两块总表的电，扣掉挂在它下面各分表的电，剩下的「公共净电」不直接向租户收，而是并进一期园区损耗池、按 `/6` 平摊到 A~F 六座的收取租户损耗率里。

### G0.2「招商中心·三楼K306室·双成金属·电表②」是什么（用户问③）

`meter 220 双成电2`，源册那一行是 `招商中心 | 三楼K306室 | 双成金属 | 户内用电 | 电表② | 210929000027 | 20 | 856.99 | 872.77 | 315.6`。它是**双成金属这个租户在招商中心三楼 K306 室的户内表**，绑在净电池上 `sign=-1`，屏上的「−」前缀就是「从总表净额里剔除」。这是账册 `SUM(S44:S48)` 的复刻，不是错误数据。

### G0.3 为什么很多行没有楼层方位（用户问④）—— 分三类，只有 2 个是真缺

池侧 90 个：**有楼层 62 / 园区级（无栋，正常）9 / 挂栋但楼层方位全空 19**。逐条看那 19 个：

| 类别 | 数量 | 结论 |
|---|---|---|
| 二期车间池（一~六车间的消防/电梯/广告字灯/电梯加价档） | **16** | **不是缺失**。二期 51 块公共表里只有 1 块带楼层——账册「公共电数据」二期是按**车间**分段的，本来就没有楼层维度 |
| `rule 23 一期 招商中心·净电` | 1 | 整栋净额池，绑定表跨三楼/四楼，没有单一楼层 |
| `rule 41 戎合B101公共电` / `rule 51 高建军C公共` | **2** | **真缺**：零绑定表 + `fee_name` 为 NULL，V70 判低置信度未改名 |

电表侧的缺失是另一回事：屏上「−招商中心·已停用·电表①」少一段楼层，是因为 `meter 219 优凯A305电` 的 `spot` 为 NULL —— **源册那一行的位置列本来就是空的**。但它的标识名 `优凯A305电` 里带着房号线索（同栋的 `218 中大A304公共电1` 是 `三楼东侧`，说明 A304/A305 都在三楼）。

### G0.4 招商中心两块总表的归属（用户要求①）—— V66 做过，被导入推翻了

`V66__pool_seed_fix.sql:45-51` 明文做过这件事：

```
-- 4) 招商中心电1/2 → 挂一期A座、ownership=share
-- → 净效果=招商中心电1/2(1142.4)计入A座分表Σ,招商中心其余表(S44:S48)净出;
-- 移除后招商中心(41)无 infra 表,不再自成损耗组(上轮"多出招商中心组"即由此二表造成)。
```

V66 于 2026-07-27 22:07 应用成功。**但现在库里是 `building_id=41` + `ownership=infra`** —— 被后来的导入推翻了。

**机制确凿**：`MeterService.applyDesc` 对 `ownership` 与 `buildingId` 是**无条件回写**。导入行 `area='招商中心'` → `buildingIdFor` 映射到 building 41；`meter_type='总电表'` → `classifyOwnership` 判 `infra`。**每导一次就推翻一次。**

这正是 2026-07-30 首次审计列的 P0 第 3 条「导入无条件回写 ownership，人工改过的归属每次重导都被静默推翻」，**至今未修**。所以只恢复数据没用，必须同时加护栏。

**对账闭合**：`33734.10（shadow 护栏生效后的 A座活数据）+ 1142.40 = 34876.50` = 原册「A座总用电量 34876.5」。

## G1【必做】恢复招商中心 223/224 归属 + 防再次被推翻

**数据**：新建 `V77__zs_meter_owner.sql`，把 `招商中心电1/招商中心电2`（`kind=elec, zone=p1`）改回 `building_id = 一期 A座`、`ownership='share'`，判据与 V66 §4 同源（按 name 匹配，不硬编码 id）。同时把这两块表标 `loc_manual` 无关的新列 `owner_manual TINYINT NOT NULL DEFAULT 0` 置 1（见 G2）。

**验证**：迁移后 2024-02 A座 `d_qty` 复算必须 = **34876.50**；building 41 不再自成损耗组（无 infra 表）；`alloc_pool_result` 的 rule 23 净电 `qty_total` 仍为 **152.06**、`cost_amount` 仍为 **169.42**（这两块表在净电池里是 `sign=+1` 成员，归属变化不影响池计算）。

## G2【必做】导入不再无条件回写归属（首审 P0，至今未修）

`applyDesc` 现在对 `ownership / buildingId / tenantId / tenantName / meterType` 一律无条件覆盖。

**改法**（与 §F6 的 `loc_manual` 同款范式）：`meter` 加 `owner_manual TINYINT NOT NULL DEFAULT 0`。
- 人工在档案抽屉改过 `ownership` 或 `buildingId` → 置 1（后端比对结果，不信客户端自报）。
- 导入时 `owner_manual=0` → 照常回写（自动分类继续起作用）；`=1` → **两列不动**，且当自动分类结果与人工值不同时落一条 warn：
  `表「X」导入判定归属=A/楼栋=B,与人工设定的 C/D 不同,已保留人工值`
- V77 把 223/224 的 `owner_manual` 置 1，从此导入推不翻。

## G3【必做】电表标签缺段时要说出来，别默默少一截

现在 `meterLabel` 是「非空段用 `·` 连接」，缺楼层就静默少一段，用户看不出是"没录"还是"不适用"。

**改法**：`meterLabel` 在 `area` 非空但 `floor_label` 为空时补一个 `·(位置未录)` 占位段；`spot` 也为空才补（`spot` 有值但解析不出楼层的，用 `spot` 原文那一段）。抄表屏与池屏共用，屏上一眼看得出哪些表要补位置。

**不做**：不从标识名/租户名反猜楼层（`优凯A305电 → 三楼305室` 这类推断有误伤面，且 §A.3 已经把位置三列做成可编辑，人工补一次即可）。改为在 `scripts/meter-loc-todo.tsv` 出一份「有区域无楼层且有读数」的清单，附上标识名里的房号线索供人工补。

## G4【必做】池缺楼层方位：分类标注，别让用户以为都是 bug

- 二期 16 个车间池：`AllocService.poolName` 与屏上「楼层·方位」列对 **zone=p2 且 building 是车间** 的池显示 `按车间`（不是 `–`），列头 title 注明「账册二期按车间分段，无楼层维度」。
- `rule 23 净电`：显示 `整栋净额`。
- `rule 41 / 51`：**真缺**，进 `scripts/pool-loc-todo.tsv` 清单（含绑定表为 0 的事实），屏上池名后加「待补定位」橙标，编辑抽屉打开时把定位三格高亮。

## G5【顺带】刀F 遗留两条

- **`shadow` 标记只能打不能解**：`MeterReq` 加 `suspect` 字段（只接受 `null` / `'shadow'` / `'incomplete'`），档案抽屉加一个「认领为独立表（解除存疑）」按钮；`apply()` 的自动清标逻辑保留。
