# 水电费账单自动派生（UTILITY-BILLING-SPEC）

> ⚠️ **草案·待用户拍板**（2026-07-26 起草）。用户开题"计划设计水电费的账单自动派生部分"后中断，
> 本稿基于就绪度审计（[bill_forward_readiness_audit]）与 BILL-FORWARD-SPEC 刀3 提纲整理，
> §2 的决策点全部拍板后才转正式 spec。北极星沿 BILL-FORWARD：**抄表读数 × 合同锁定单价 → 每户每月水电费表 → 与附表10 勾稽**。

---

## 0. 电表类型口径（用户拍板 2026-07-27）

| 表类型 | 定义 | 与计费的关系 |
|---|---|---|
| 单相电表 | 单相供电计量 | 照明/小功率（宿舍间表多为此类），单一读数 |
| 三相电表 | 三相供电计量 | 厂房/动力用电 |
| 多功能电表 | 具备**峰/平/谷/尖分时计量** | TOU 计费户与公共表；meter_reading 现有四段起止码即此类表读数 |
| 需量电表 | **现今新出**，带基本用电需量控制，**计量单位 1 kVA** | 与「装机容量费/基本用电费 22.6 元/kVA·月」直接相关：现按合同装机容量固定收取；需量表普及后可按实际最大需量计收（两部制按需量模式） |

另有**双向计量**能力（正向/反向有功各四段独立寄存器）。**✅口径已澄清（用户 2026-07-27）**：全园出现反向电量的
只有永龙一户，且已认定为**装表接线错误**（安装时误把光伏电表接进了户表回路），**不是计费政策**。
→ 引擎不建「反向按正向价计费」通用轨道；反向电量出现即**异常告警**（接线校验进导入门禁）。
2024-02 永龙账单（27,504 度×0.15 维护费等）按史实对账保留，不回溯改口径；
原「损耗基数只计正向维护费是否有意为之」问题随根因认定一并关闭——是接线错误的副产物，无政策含义。

→ 引擎要求：meter 档案加表类型字段（单相/三相/多功能/需量/双向）；需量表读数含 kVA 需量值，
为容量费从「合同 kVA 固定」切换到「按实际需量」预留数据位。

## 1. 目标与计算模型

每户每月一张**水电费表**（催缴单第二张表，第一张租金表属刀2）：

```
电费 = Σ_表 Σ_时段(尖/峰/平/谷用量 × 该户类别对应时段单价)
     + 用电服务费(元/度 × 当月总用量)
     + 装机容量费(仅大工业: kva × 单价 元/KVA/月)
水费 = Σ_表 用量 × 水费单价
```

- **用量侧（已就绪，零改模型）**：`meter_reading` 起止码对 ×`factor_snap`，电表尖峰平谷四段已完整落库（V45），
  `MeterService.usage()` 已是 public static。水表 total 两列同模型。
- **价格侧（当前全断链，见 §2 决策点①）**：合同层无任何电价/水价字段；`elec_price_cfg` 是园区成本参数、
  `alloc_cfg` 是公摊引擎私有（P-B 四表之一），均不可直接复用为租户售价。
- 计算函数复用先例：`AllocService.touAmount`（四时段算式，public static）提为共享工具。

## 2. 决策点（全部待拍板，①③是开工闸门）

|---|---|---|---|

| ② | 服务费/容量费单价值 | 现状仅有折进售价的 +0.16（V47 种子注释）与口述 23 元/KVA，条款文本不在册 | 人工补录进 ①的价表；派生引擎读表不读硬编码 |

| ④ | 尖段成本归并 | 抄表有尖段、成本侧发票只有峰平谷 | 尖并峰（行业惯例），只影响电费收益勾稽口径，不影响催缴单 |
| ⑤ | 词表统一 | elec_record.cat 中文自由文本 ↔ contract.power_type 枚举 | 固化映射常量，替换 ElecCostService 的 contains 匹配 |

## 3. 派生流程（月批）

```
选定账期 ym
 ├─ 门禁1: 该租户任一在租表「待核」(ownership='tenant' 且 tenant_id 空) → 该户跳过,进异常清单
 ├─ 门禁2: 该户任一表当月漏抄(prev/curr 缺) → 该户跳过(漏抄不出单),进异常清单
 ├─ 聚合: 新增服务端「租户×月用量」出口(复用 MeterService.usage):租户→{总,尖,峰,平,谷,水}用量
 ├─ 取价: 合同.power_type → tenant_price_cfg(月行回退) → 12价+服务费+容量费+水价
 ├─ 计算: §1 公式,金额逐项 ROUND 2
 └─ 落库: bill_notice 快照(见 §4),含 price_snap 与 usage 明细 → 草稿态
重导抄表防线: 该 ym 已存在非作废 bill_notice → 抄表导入拦截/警告(记入 MeterService 导入口)
```

## 4. 数据落点

- `bill_notice`（刀2 已提纲的快照表，水电与租金共表）：户×月×费项行，
  水电行 fee_key 新增 `elec_sharp/elec_peak/elec_flat/elec_valley/elec_svc/elec_capacity/water`，
  每行带 `qty`(用量)/`price_snap`(执行价快照)/`amount`；表级明细(哪块表多少度)存行内 params JSON 供下钻。
- `tenant_price_cfg`（方案A）：`scope`(industrial/commercial/resident) × `cfg_key` × `cfg_value` × `acct_month`(''=默认行)，
  uk(scope,cfg_key,acct_month)。水价可用 scope='water' 单行。
- `meter_contract_bind`（决策③兜底）：meter_id × contract_id × effective_ym，仅歧义户人工填。

## 5. 勾稽（刀5 衔接，本刀只留钩子）

- 派生明细粒度=表×时段；附表10 对手方只有 5 个汇总列（elecBasic/elecStd/elecMaint/waterStd/waterMaint）。
  **勾稽按 户×月×汇总列 卷积后比对**，明细留 bill_notice 内解释差异。
- 映射挂 `RECON_FEES` 单一事实源上扩第三 getter，禁另抄映射（ReconService 注释铁律）。

## 6. 非目标（本刀不做）

- 公摊水电分摊入户（P-B alloc 引擎独立演进，用户明示"先记下来"）。
- 租金表派生（刀2）、三方勾稽工作台（刀5）、抄表页 UI 重做（独立不阻塞，派生读库不读页面）。
- 附表13/14（办公·三期水电）：园区自身成本，与租户计费无关，不动。
