# 布局稳定规范（LAYOUT-STABILITY-SPEC）v1

> 2026-08-22 立。起因：提权功能在页面里加了一条「本页有 N 项需要主管权限 · [请主管授权]」
> 的流内横条，用户点一次「编辑模式」再取消，整页内容被它撑得往下跳一截。
>
> ⚠ **这条规则本来就存在** —— LIST-PAGE-SPEC §审核清单写着
> 「任何交互（滚动/翻页/筛选/hover/**编辑态切换**）引发布局位移或闪烁 ❌」，
> 但它埋在一份以表格为主题的清单里，写新功能时没人会去翻。所以提升为全站页面级规范。

## 1. 铁律

**用户的一次交互，不得改变屏幕上已渲染内容的位置。**

「交互」= 用户主动做的任何事：点按钮、切编辑态、翻页、筛选、hover、展开/收起、
保存成功、请求失败。

「已渲染内容」= 交互发生**之前**屏幕上已经存在的东西。

不许出现的画面：点一下 → 表格整体下移 40px → 用户眼睛要重新找行。

## 2. 想给用户一条新信息时，按这个顺序选做法

| 优先级 | 做法 | 说明 |
|---|---|---|
| **1. 不加** | 信息塞进已有的位置 | 徽标、按钮文案、tooltip、已有工具栏的一个 chip。**绝大多数提示条其实不必存在** |
| **2. 浮层** | `position: absolute` 覆盖在内容上 | 参照 `FPToast`（贴容器底、`position:absolute`+阴影，容器给 `position: relative`）。⚠ 原参照 `PoolLedgerView .pl-float` 已于 2026-08-25 随「生成告警」浮层收进告警抽屉（§6）而删除 |
| **3. 预留位** | 容器恒定高度，有没有内容都占位 | 只在「这条几乎总会出现、只是内容变」时用；空着占位是浪费 |
| **4. 流内条** | 直接插进文档流 | **只允许出现在首屏加载期**（见 §3），交互态一律不许 |

## 3. 唯一的例外：首屏加载期

数据加载完发现「本月尚未生成」这类条，出现在**用户还没开始交互**的时候，
它是初始布局的一部分，不算位移。

判据很硬：**这条的显隐只由「首次数据加载的结果」决定，不由任何用户动作决定。**
只要它的 `v-if` 里出现了 `editMode` / `selected` / `okMsg` / `saving` /
`筛选条件` 之类**用户能改的状态**，就不属于这个例外。

> ⚠ **这条例外只管「提示条」，不是「加载态可以随便跳」的通行证**（2026-08-27 澄清）。
> 本节连同 §2 讲的都是「你想给用户一条新信息时，那条信息放哪」——
> 主体内容自己的「没加载出来 → 加载出来」不在本节管辖内，见 §7。
> 换期（切月/切筛选）**是用户动作**，它引起的内容位移直接违反 §1 铁律，与本例外无关。

## 4. 具体到几类常见的条

| 条 | 判定 | 做法 |
|---|---|---|
| 「本月尚未生成」 | 加载期 ✅ | 可留流内 |
| 「参数已更新，去重算」（stale） | 加载期 ✅ | 可留流内 |
| 「保存成功」okMsg | **交互触发 ❌** | **用 `fp/FPToast.vue`**（见 §4.1），或按 §2 优先级 1 干脆不加 |
| 「本次生成有 N 条告警」 | **交互触发 ❌** | 2026-08-25 起收进告警抽屉（§6），页面不再出条 |
| 「本页有 N 项需要主管权限」 | **交互触发 ❌** | **删掉**（2026-08-22 用户要求）——信息已经由授权弹窗给到了，不需要第二遍 |
| 编辑态才出现的批量操作条（`cb-unibar` / `pb-unibar`） | 交互触发，但它是编辑态的**主体工作区**不是提示 | 见 §5 |

### 4.1 FPToast —— 反馈提示的标准件

2026-08-22 立。此前 5 处「保存成功」绿条各写各的流内 `<div v-if="okMsg">`，
一进一出把下面整块内容顶两次；已全部收编，`noInteractionLayoutShift.spec.ts` 的
`KNOWN_DEBT` 表随之清空（**请保持空的**）。

```vue
<FPToast v-model="okMsg" :duration="3000" />                          <!-- 贴宿主卡片底部 -->
<FPToast v-model="msg" tone="error" placement="page" :duration="0" /> <!-- 贴屏幕底部，不自动关 -->
```

**placement 的判据是宿主，不是审美：**

| 宿主 | 用 | 为什么 |
|---|---|---|
| 有 `position:relative` 且**不滚动** | `card` | 反馈贴着它所属的那块内容 |
| 没有 relative 容器 | `page` | card 会一路找到 body，位置失控 |
| `overflow:auto` 滚动容器（如 `FPDrawer` body） | `page` | **absolute 贴底会跟着内容滚走** |
| 弹窗内的操作 | `page` | `--z-toast`(400) > `--z-modal-2`(320)，盖得住 |

⚠️ **贴底不贴顶**：顶部留给「生成告警」那类要读的清单（`.pl-float`）。
一上一下各司其职 —— `PoolLedgerView` 两者同屏，实测不重叠。

## 4.2 表单的错误/提示位必须**常驻**

2026-08-22 用户实测指出：主管授权弹窗里密码输错，红字凭空长出来一行，
把下面的说明和「确认授权」按钮一起顶下去 —— **用户正要重点一次的按钮在他手指底下跑掉了。**

**铁律：任何可能出现校验错误或提示的字段，那一行的位置在常态下就要占好。**

```vue
<!-- ❌ 错误一出现就把下面顶走 -->
<p v-if="err" class="x-err">{{ err }}</p>

<!-- ✅ 位置常驻，内容才是条件的 -->
<p class="x-err"><template v-if="err">{{ err }}</template></p>
```
```css
.x-err { min-height: 18px; line-height: 18px; }   /* 恰好一行 */
```

**这类提示不走 toast。** toast 是"做完了"的事后反馈，飘走就行；
校验错误是"你得改这里"，必须**贴着出错的那个字段**、并且留到改好为止。
两者不可互换（用户 2026-08-22 明确：「这种账号密码输错的情况走这种提示不用 toast」）。

`ds/Input.vue` 已内置常驻提示位（`.ds-in-msg`），用它的地方不必自己处理。
自己手写错误行的（弹窗、抽屉、表单页）按上面的写法。

仓库里早有合规先例可抄：`MeterView` / `PvMeterView` / `ElecCostView` 的
`.*-dlg-err { min-height: 14px }`。

## 5. 编辑态本身怎么办

进编辑模式会多出一整排工具（批量条、勾选列、操作列），这**必然**改变布局 ——
它不是「提示」，是模式切换，用户预期就是换一副面孔。

这条允许。但要满足：

- 变化**局限在编辑区自身**，不得把无关的上下文顶走
- 表格的**列宽与行高**在两态之间不变（LIST-PAGE-SPEC 列宽铁律仍然管着）
- 退出编辑态必须**原样还原**，不留残余占位

## 6. 门禁

`frontend/src/views/__tests__/noInteractionLayoutShift.spec.ts` 在源码层扫：
页面根部的流内块，`v-if` 里若引用了交互态变量（`editMode` / `okMsg` / `saving` /
`selected` / `asking` …），且样式不含 `position: absolute|fixed`，即判违规。

同一文件里还扫 §4.2：带 `v-if` / `v-else-if` 的元素，class 名匹配 `/err|error/`
且该 class 在 `<style>` 里没有 `min-height`，即判违规（提示行整条被 v-if 掉 = 出错时凭空长一行）。

白名单只收 §5 那类「编辑态主体工作区」；§4.2 的白名单（`ERR_SLOT_WHITELIST`）只收
「加载失败态 / 空态」和「父容器已占位」两类。每条都要写明理由。

> 门禁只能抓源码形状，抓不到「看起来没动其实动了」。真正的验收还是**打开页面点一下**。


## §6 屏级告警：常驻 chip + 右侧抽屉（2026-08-25 用户拍板）

**禁止**把「快照过期 / 待重算 / 成员变动 / 生成告警」这类**状态型告警**做成流内提示条。
用户实测痛点：不管切到哪个月、哪个屏，页面顶部永远挂着一条橙色警告（池核算屏一度并存 5 条），
既顶动表格（违反本 SPEC 铁律），又因为清除条件苛刻而变成永久噪音——看久了就没人看了。

统一形态（与台账/附表10 的「未绑定」入口同款）：

1. **入口 = 工具条上的常驻 chip**，紧邻搜索框/主控区，位置固定不随有无告警变化：
   - 有待处理 → 实底警示色 + 计数（`待处理 3`）
   - 无待处理 → quiet 静默态（灰字描边，`无待处理`），**仍然渲染**，不留空洞不挪版
2. **详情 = 右侧抽屉**（`FPSideDrawer`），点 chip 打开。抽屉内按类型分组，每组：
   - 一句人话说明「这是什么、不处理会怎样」
   - 逐条明细（可点击跳转到问题所在处）
   - **可执行的动作按钮**——只报不给动作的告警不许进抽屉
3. **可清除性是硬要求**：告警必须有一条用户点得到的路径把它清成 0。
   跨月/批量类告警（如「另有 N 个月受影响」）必须提供**一键批量处理**，
   不许只给一句「请切到该月重算」让用户手工切几十次。
4. 例外：**写操作的即时反馈**（保存成功/失败）走 FPToast，不进抽屉；
   **阻断性错误**（加载失败、无权限）仍可用流内条，因为它们本就该打断流程。

参考实现：`views/params/ParamCenterView.vue`、`views/bills/BillNoticesView.vue`、
`views/alloc/PoolLedgerView.vue`、`views/alloc/LossLedgerView.vue`（2026-08-25 起为基准）。


## §7 「没加载出来 → 加载出来」怎么呈现（2026-08-28 落地）

§1–§6 讲的是「新信息放哪」。本节讲**主体内容自己**那一下：数据没到时屏上是什么，到了之后怎么换。

### 7.1 按「用户一天看几次」分三档

动画该不该有，先看频次 —— 一天几十次的东西，动效只会让它显慢。

| 场景 | 频次 | 做法 |
|---|---|---|
| **换期 / 换筛选** | 一天几十次 | **内容不动**，原地退让 + 顶边进度线。**不要转圈** |
| **首次进屏** | 一屏一两次 | 骨架按真实版式占位，**零位移** |
| **局部 / 抽屉详情** | 偶尔 | 该块自己占位，父容器高度不变 |

### 7.2 标准件

| 件 | 用途 | 要点 |
|---|---|---|
| `.fp-shim`（base.css） | 骨架微光条 | **尺寸一律由调用方给** —— 别把「多高」从版式里偷走 |
| `.fp-stale`（base.css） | 换期时旧内容退让 | `opacity .42 + blur 1.5px + pointer-events:none` |
| `FPLoadBar` | 顶边 2px 进度线 | 不占高度 → 不位移。宿主要 `position: relative` |
| `useDeferredFlag` | 200ms 防闪延迟 | 进场等、**退场立刻** |
| `FPLoadError` | 「没加载出来 + 重试」 | 全站唯一一份（收编前有 6 处） |
| `.page-loading` / `.page-spin` | 居中转圈 | **只用于版式真的未知的地方**（如图表容器） |

### 7.3 三条硬规矩

**① `pointer-events: none` 是安全项，不是观感项。**
抄表屏的注释早写过：旧数组还挂着时用户在那些行上录一格，保存走的是**旧行 id 的 PUT**，
直接覆盖上个账期的读数。留旧内容而不禁交互，等于把那条路重新打开。

**② 指示器要 200ms 延迟。**
本地后端常几十毫秒返回，转圈**闪现即消失**比不显示更晃眼。

**③ 版式已知就必须用骨架，不许用转圈。**
判据是 `useFitRows` —— 它的三个输入全是布局常量，
所以「该画几行」在数据到达前就算得出来。门禁：`views/__tests__/exactPlaceholder.spec.ts`。
零位移靠**外壳从不卸载**这个结构保证，不是靠两份版式对齐。
实测租户管理这一下原本是 **134px → 317px，位移 183px**。

### 7.4 reduced-motion 下的分工

- **转圈继续转** —— 停下会被读成「卡死了」（沿用既有例外）
- **进度线改呼吸** —— 保留「在动」但去掉横向位移
- **骨架微光停掉** —— 骨架的**形状本身**就说明了状态，不需要动

### 7.5 门禁抓不到什么

`noInteractionLayoutShift` 靠一份**变量名白名单**判断「是不是交互触发」，
认的是 `editMode` / `saving` / `selected` 那类。而换期的判据变量是
`summary` / `monthData` / `rows` —— 数据引用，不在名单里；
更根本的是**证据在 `<script>` 里**（`clearData()` 之类），而它只扫 `<template>` 的 `v-if` 形状。

所以这一节的很多条**只能靠人守**。真正的验收还是打开页面点一下。
