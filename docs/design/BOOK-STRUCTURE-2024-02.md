### 0.3 全簿通用范式（两期一致）

1. **A 列是身份键，且没有表头。** 列宽 2.43–2.5，肉眼几乎看不见。全簿所有 `VLOOKUP` 都以它匹配，**不是用电表编码 G 列**。命名毫无规律（`A4西侧走廊灯` / `力灏4042总` / `一车间尖` / `招商中心电1` / `101`）。
2. **定义名（defined name）一律是整表全行形态**：`碳紫 → 碳紫!$1:$1048576`。因此 `VLOOKUP(x, 碳紫, 24, FALSE)` 的第 24 列是**从 A 列起数的绝对列号 X**。
3. **r1 是列序号标尺行，不是数据**，且可能过期（见 §1.1 陷阱）。
4. **上月行至列 = 跨工作簿 `[N]` 引用上月册，已断链，只剩缓存值。** 一期用 `[3]`，二期用 `[3]`；`创显承担电费` / 宿舍电 r339 另用 `[1]` / `[4]` / `[5]`。
5. **本月行至列 = 手工录入常量**，个别格夹带算式（如二期 `N87='=6316.26+800'`）。

### 1.4 公式关系

**I/N 抄表拉取**
```
I{r} = IF(ISNA(VLOOKUP(A{r}, 一期园区电, 9, FALSE)), 0, VLOOKUP(A{r}, 一期园区电, 9, FALSE))
```

## §6 与系统现状的偏差清单 ★ 本节最重要

### 6.1 「净电」是系统编的名字 —— 原册中不存在

- **原册**：`公共电分摊明细` r8 原文 —— `A8='招商中心电1'`、`B8='招商中心'`、`C8='四楼'`、**`D8（企业名称）='招商中心'`**、**`E8（表类）='总电表'`**、`F8='电表①'`、`G8=220605000017`、`H8=80`。**全簿搜不到"净电"二字。** 二期整册 68 sheet 也搜不到"净电"，同时搜不到"招商中心"。
- **系统**：`alloc_rule` id=23 的 `fee_name='净电'`、`name='一期 招商中心·净电'`。
- **影响面**：这个概念是从 POOL-FORMULA-AUDIT 一路传到库里的臆造科目名（该文档第 159/160/172/177/325 行反复称其为"招商中心净电"）。而这一行的算法也和同块其余四行不同：`S8 = 一期园区电!X50 + N8`，`N8` 的公式原文是 `=-670`（硬编码扣度写在"本月行至"列位），`X50 = S49+S50-SUM(S44:S48) = 822.06` → 152.06。**用一个自造名承载一个特例算法，等于把特例合法化了。**

### 6.2 池 = 「楼栋+楼层+侧向+费项」四级定位 —— 原册没有这个概念（★报障根因）

- **原册**：`B3:C4` 是**合并单元格**，表头文字只有"区域"一个词，C 列**没有表头**。`一期园区电` 同样 `B3:C4` 合并，而且在 14 个总表/工地行直接把 B、C 两格**横向合并**掉（`B5:C5`、`B93:C93`、`B213:C213`…）。原册作者的心智模型是「**一个位置描述占两格，能细就细到楼层方位，不能细就整格写区域**」。
- **系统**：`alloc_rule` 用 `building_id + floor_label + side + fee_name` 四级定位，并按 `building_id` 分带（13=A座、20=B座…41=招商中心）。
- **最硬的反证 —— `side` 这个字段在原册不存在**：C 列 **26 行「天面」全部不带东西方位**，东西之分写在 **D 列（电表名称）**=`东侧货梯` / `西侧货梯`。系统却造出了 `天面东侧` / `天面西侧`：rule **59/60**(C座)、**69/70**(D座)、**78/79**(E座)、**88/89**(F座) —— **把 D 列的语义搬进了位置字段**。而 B 座同类池 rule **49/50** 又是不带 side 的单条，**同一份数据两种编码**。
- **floor_label 也不一致**：rule 41 `戎合B101公共电` 的 floor_label=NULL、side=NULL，而原册 r33 `C='一楼东侧'`；rule 51 `高建军C公共` 同样 NULL，而原册 r46 `C='一楼东侧'`。
- **影响面**：把两格宽的一个字段拆成三个独立字段，是系统单方面的结构升级，不是原册语义。分带依据错位后，A 座两块被合并、招商中心被抽成第七条带（见 6.3）。
- **注**：二期未被带偏 —— `alloc_rule WHERE zone='p2'` 共 21 条，`floor_label` 与 `side` **全部为 NULL**。**用户报的"四级定位"偏差是一期问题。**

### 6.3 `building` id=41「一期 招商中心」把「区域」的一个取值当成了物理楼栋

- **原册三条独立反证**：
  1. `一期园区损耗` 只核算 A/B/C/D/E/F 座 + G座 + G座自建专变，**没有招商中心行**；六座平摊的分母就是 6。
  2. `一期园区电` `S92「A座总用电量」= SUM(S7:S91) − S51 − S52 − S60 − S77 − S49 − S50 + X50` —— **招商中心两块 80 倍总表挂在 A 座变压器下**，只是被净额扣出。
  3. `一期园区电` r44 `A='中大A304公共电1' B='招商中心' C='三楼东侧'`、r45=`优凯A305电`、r46 `C='三楼K306室'` —— **房号 A304 / A305 明确是 A 座房号**。
- **系统**：`building` id=41 remark 原文 —— 「楼栋补建 2026-07-28：抄表区域「招商中心」原漏建（账册招商中心四楼）；面积待补」。
- **影响面**：损耗表六座平摊 `/6` 的分母、A 座总用电量的净额扣出逻辑、以及 r8/r17/r18 的块归属，在系统里**全部失去落点**。

### 6.4 系统 67 条 p1 规则 vs 原册 85 个数据行 —— 已核实的丢行

- **原册**：r12（B='A座' C='一楼' Z='联塑精铟'，无电表，AE12=AF12=232 手输固定额）；r47/r48/r49（B='C座' C='一楼西侧'，D='公共用电/杨道扬 / 卢志华 / 诺玲'，G='无公共电表'，I/N/S 为文本 `/`，AC/AD 字面 0）。

- **影响面**：⚠ 67↔85 的完整映射**未逐条比对完**，实际丢行/错并行可能还有（见 §7）。

### 6.5 `alloc_rule.name` 与原册自然键不可逆映射

- **影响面**：两套命名不可逆映射，任何按名回溯原册的核对都会断。

### 6.6 `alloc_rule.extra_qty` 把两种语义不同的加度塞进同一字段

### 6.8 ★ 二期园区电 r51 是一条 15527 度的幽灵行，已进合计与损耗

### 6.9 ★ 二期遗留隐藏表 `公共电分摊` 不是"仅剩一格备注"，它在污染 2024 年 2 月的实收金额

- **POOL-FORMULA-AUDIT 第 10 行**称它「2023年4-5月遗留模板，**仅剩 M109=0.01 一格仍被 2024 户表引用**」（同文档第 129 行又写「M109=0.01、M99=0.005 为硬编码备注价」，**前后自相矛盾**）。
- **原册实测**：
  - `公共电分摊!M99`（=0.005，硬编码路灯单价）被 **46 处** 2024 年 2 月租户 sheet 引用（`曹小芳!J16`、`罗立剑!J16`、`锂朋!J43`、`嘉荣!J43`…），公式形态 `J16 = 公共电分摊!M99`，**直接乘面积出钱**（曹小芳 `K16 = ROUND(0.005*3170.35, 2) = 15.85`）
  - `M109` 被 **39 处** 引用
  - 更严重：`曹小芳!I14 = ROUND(公共电分摊!L24 + 公共电分摊!L99*E16/0.7, 2) = 250.68`；`刘彪!I14` 同构用 /0.3。而 `L24 = ROUND(J24/6, 2) = 205.39`、`L99 = ROUND(J99/148918.01, 2) = 0.01`，J24/J99 又由 `=厂房电!E139/F139…` 与 `=厂房电!T10~T13` **现算**

### 6.10 `alloc_rule.coefficient` 对四车间电梯丢了业务语义

- **原册**：`T58 = 4.5`（四车间实际出租 4.5 层）；`V58 = ROUND(Σ/4.5/4*3, 2) = 286.59`（普通户按全层价的 3/4 计）；`V64 = ROUND(Σ/4.5/4 + V58, 2) + 100 = 482.12`（广联/氙明/威玛斯三户 +100 元）。
- **系统**：`coefficient = 6.00`（数值上无害，因为 `Σ/4.5/4*3 ≡ Σ/6`；`alloc_cfg` 里 rule:12 存的 18.00 = 4.5×4 也对得上）。
- **影响面**：**语义丢了**。原册的真相是「4.5 层」+「3/4 折」两个独立业务事实，被压成一个 6.00。以后出租层数一变（比如变成 5 层），这个 6.00 就没人知道该改成什么。**建议 coefficient 存 4.5，把 3/4 折做成显式字段。**

### 6.11 二期「分摊范围」被等价成 building_id

- **原册**：分带依据是 **S 列文本**；`S40 = '三车间企业\n（嘉荣、艾派斯）'` 把受益人白名单塞进范围文本、还带换行。
- **系统**：21 条 p2 rule 的 building_id 恰好都对（园区池 NULL、车间池 30–35），但这个"恰好"是靠人工映射来的 —— 因为 `公共电数据` 的 B 列对 4 个园区池写的是车间名（见 §2.1.1）。
- **影响面**：building_id=32 表达不了「三车间企业中仅嘉荣、艾派斯」这种白名单。**"分摊范围"必须是独立的一等字段。**

### 6.12 `alloc_rule.fee_key` 给充电桩配了错误费项

### 6.13 `alloc_pool_result.allocated_amount` 与原册 X/AE 列不是一回事

- **原册**：一期 AE（已分摊）是**从 `2024年2月电费总表` 按费目列 + 逐个租户行号硬编码回勾的实收**（如 `AE58 = T100+T61+T64+T80+T81+T83+T85+T43+T103`）；二期 X 列同理（手工圈的行区间）。原册的 Y/AF（盈亏）= 实收 − 池成本，衡量的是「**手工圈的收费名单与池成本的缺口**」。
- **系统**：`allocated_amount` 注释写「引擎按受益人试算摊出（非实收；账册AE=实收对账待账单模块）」，衡量的是别的东西。数值也对不上：rule 2（一车间消防）系统 allocated=141.26，原册 X4=425.51；rule 3（一车间电梯）系统 1017.60，原册 X10=848.96。原册合计 X126=12398.91 / Y126=−1934.69。

### 6.14 系统没有「收款公司 × 场地」维度

- **原册**：`一期租户水电费总表` 的 23 个物理列、`二期租户水电费总表` 的 C..V 列、以及全簿 VLOOKUP 列号 16..24，**整个体系都围绕这个维度**；同一租户的费用会拆给两家公司。
- **系统**：`bill_pay_company` 表存在但 `alloc_*` 系列没有收款公司维度。
- **影响面**：这是"应收"口径的**第一性维度**，目前缺失。

### 6.15 系统没有电费总表的三制式（商业/工业/居民）分段

- **原册**：每个租户的电费按用电性质分三段，每段各有独立的"基础容量/基础用电费"（容量电价，如 `400千伏安 / 9040 元`），且**居民段没有消防和电梯列，路灯公摊挪到 AC**。
- **系统**：`elec_record` / `elec_meter` / `alloc_result` 均未见制式字段。
- **影响面**：任何"三段同构"的建模假设都会错位。

### 6.16 火炬园被降格成一个池

### 6.17 一期宿舍电：分时表被拆成 28 块伪表，而模型本来就是对的
