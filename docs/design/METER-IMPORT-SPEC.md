# METER-IMPORT-SPEC — 园区抄表导入契约与身份键

> 前置:任务 A(解析链诊断)/任务 B(身份键调研)。本文只管**导入**:模板列契约、表档案身份识别、
> 字段刷新语义、未匹配与歧义处置。表档案字段语义、读数快照口径、分摊消费仍归 METER-SPEC / PB-ALLOCATION-SPEC。

## 1. 为什么改

现行导入把 `(kind, zone, name)` 当表的身份,`name` = Excel **第 0 列硬编码**的「标识列」。两个后果:

1. **用户新模板没有标识列**(A 列就是「区域」)→ 每行 `name` 取到「A座」,7 行塌缩成 1 块表,
   后端逐行 `applyDesc` 覆盖 + 读数先删后插,**一条报错都不给**,库里只剩最后一行。这是"导入不了/导入错"的直接原因。
2. 即使有标识列,标识是**会变的文本**:365 块表(26%)的标识里嵌着租户公司名(`创显办公室`/`公共用电/可莱恩`),
   换租户即换身份;宿舍 261 块表的标识就是房号,Excel 把 `101` 存成 `101.00` 就凭空多出 261 块影子表
   (dorm elec 2024-02 公摊池 99.95% 是假的)。

结论:**标识列不是身份,只是一个人类可读的标签。** 身份必须落在物理属性上。

## 2. 模板列契约

按**表头文字**定位列,**不认列号**。同时兼容两种版式:

| 列 | 表头文字 | 历史文件(一期2024年2月水电费.xlsx) | 用户新模板 | 必填 |
|---|---|---|---|---|
| 标识 | **无表头** | A 列(`A座总电`/`创显办公室`) | **没有这一列** | 否 |
| 区域 | `区域` | B | A | 是(表头必须存在) |
| 位置 | **无表头** | C(区域列与企业名称列之间的所有列) | B | 否 |
| 企业名称 | `企业名称` | D | C | 否 |
| 表类 | `表类` | E | D | 否 |
| 表名 | `电表名称` / `水表名称` | F | E | 否 |
| 编码 | `电表编码` / `水表编码` | G | F | 否 |
| 倍率 | `倍率`(可带电表/水表前缀) | H | G | 否 |
| 上月行至 | 以 `上月行至` 开头 | I(+尖峰平谷 4 列) | H | 是 |
| 本月行至 | 以 `本月行至` 开头 | N(+尖峰平谷 4 列) | M | 是 |
| 本月用电量 | 以 `本月用电量`/`本月用水量`/`本月用量` 开头 | S(+4 列) | R | 否 |
| 备注 | `备注` | X | W | 否 |

**标识列判定(唯一规则)**:表头行里 `区域` 的列号 > 0 → 第 0 列是标识列;`区域` 在第 0 列 → 无标识列。
除标识外所有列都按表头文字找,所以去掉 A 列后其余 11 列**自动对齐、零错位**。

其余识别闸门沿用现状(METER-SPEC §4):
- 闸门①:前 4 行内标题需匹配 `YYYY年M月…抄表记录`,并能从 标题+sheet名 取到 一期/二期/宿舍 与 电表/水表。缺项走 §2.4 降级。
- 闸门②:表头行需同时含 `区域` + `上月行至*` + `本月行至*`(挡掉标题被复制串味的分摊 sheet)。
- 尖峰平谷:表头**下一行**在「上月行至」列处为 `总` → TOU 版式,数据从 h+2 起;否则单列、数据从 h+1 起。

### 2.4 账期来源与降级(2026-07-29,用户报障「复制导入必须要有表头年月日」)

**账期不能从数据推断** —— 数据行里没有月份列,`上月行至/本月行至` 只是数字。所以解析器不猜,
缺了就**问人**:导入弹窗提供账期/分区/类别选择器,默认值取抄表页当前年月。

| 级别 | 标题情况 | 账期/分区/类别来源 | 段落 `ymSource` |
|---|---|---|---|
| L0 | 标题齐全(历史文件) | 全部取标题(+sheet 名) | `title`(零行为变化) |
| L1 | 标题有分区/类别但没年月 | 年月取 fallback,其余取标题 | `fallback` |
| L2 | 裸数据块(复制粘贴,无标题行) | 三项全取 fallback | `fallback` |

- 契约:`parseMeterWorkbook(sheets, master, fallback?: { ym?, zone?, kind? })`;
  段落回 `{ ym, ymSource }`,整册回 `notice`(有段落用了 fallback 才有),段标签追加「(按所选账期)」。
- **闸门②一步不放宽**:没有 `区域`+`上月行至`+`本月行至` 的 sheet 照旧拒收,否则无关 sheet 会被当抄表读。
- 弹窗侧:`FpImportModal` 新增可选 `fallbackPicker` 属性(仅 registry 的 meter 项注入),
  **只在结果带 `notice`(= 真用上了补录值)时**才渲染补录条;改任一项即用新值重解析已选文件。
  其余 20 个导入器不传这个属性 → 一行 UI 都不多,`parseWorkbook` 的第二实参它们不接即可。
- 错误文案:表头认出来但没账期 → 「请在上方选择账期/分区/类别后重新解析」;
  连表头都没有 → 「表头行需同时含 区域+上月行至+本月行至(标题行可以没有)」。

### 2.1 垃圾行与合计行

| 行型 | 判定 | 处置 |
|---|---|---|
| 段落合计行 | 标识列或区域列含 `总用电量/总用水量/总用量/合计/小计` | 丢弃(如 `A座总用电量`、`E座总用电量`) |
| 空行/游离备注行 | 标识、区域、位置、企业名称、表名、编码**全空** | 丢弃 |
| 区域纵向合并的续行 | 区域列空但本行有其他内容 | **保留**,区域向下继承上一非空值(Excel 合并单元格只在左上角给值) |

> 旧实现是「标识列空即丢弃」,合并版式下会静默吃掉大半数据且不报错。现改为内容判定。

### 2.2 单元格归一

| 问题 | 现象 | 处置 |
|---|---|---|
| 日期型位置格 | `C11` 是 datetime + `mm-dd-yy` 格式,`raw:false` 出 `5/18/23` | `M/D/YY` → `YYYY-MM-DD` |
| 编码被科学计数法截断 | 常规格式的长数字 → `2.20605E+11`,**有效位已丢,不可还原** | **按无编码处理**(不写进 code,不参与编码匹配),整册给一条非阻断 warning 提示改文本格式后重导 |
| 数值化的标识/编码 | `101` 被存成 `101.00` | 去掉尾部 `.0+`(这是 261 块影子表的直接成因) |
| 前后空格 | ` 230828010084 ` | trim(现状已有) |

### 2.3 本月用电量列

**不入库**。用量口径仍是 `(本月行至 − 上月行至) × 倍率`(唯一定义点 `MeterService.usage`)。
该列只进导入预览的「表列用量」栏做人工对照;与派生值差异超 `max(1, 1%)` 时预览值带 `⚠`。
> 不落库的理由:落库就出现两个用量口径,分摊/账单要选一个,选择本身就是新的错源。要对账,眼睛在预览里对一次就够。

## 3. 身份键:分层匹配管道

**核心转变:导入不再「用业务键建档」,改为「用物理特征匹配已有档案」。身份是 `meter.id`,不是任何文本键。**

覆盖率实测(1417 块表):有编码 505(35.6%)、无编码但有区域 598、两者皆无 314。
所以单靠编码导不进 64% 的表,单靠地址有 41 组冲突 —— 必须分层。

```
入参:kind, zone, area, spot, subName, code, name(标识,可空)

L1 编码   code 非空 → 候选 = { m | m.kind=kind ∧ m.code=code }
L2 地址   area 非空 → 候选 = { m | m.kind=kind ∧ m.zone=zone ∧ m.area=area ∧ m.spot=spot ∧ m.sub_name=subName }
L3 标识   name 非空 → 候选 = { m | m.kind=kind ∧ m.zone=zone ∧ m.name=name }   ← 即旧的唯一键,退化为兜底
L4 新建
```

规则:

- **逐层下探,不是短路**:某层候选为 0 就进下一层。理由:现存 912 块无码表在新模板里会**第一次拿到编码**,
  若在 L1 落空即新建,这 912 块全部重复建档。
- **换表护栏**:任一层里,若导入行有编码、候选也有编码且**两者不同**,该候选剔除
  (同一位置换了新表 = 新的物理表,不该继承旧表的历史)。
- **命中唯一才算命中**;候选 ≥2 → **歧义**,该行不导入、不建档,进错误清单并列出候选表 id。
- L2 候选 ≥2 时先用 `name` 再筛一次(实测 `+name` 后冲突归零),仍 ≥2 才判歧义。
- 匹配成功后,行里的编码会被写回档案 → **库逐月自愈向 L1 收敛**。

命中率与冲突(实测,见 §7):L1 505 块 / 5 组编码重复;L2 598 块 / 8 组同址多表;L3 314 块 / 0 冲突。

### 3.1 标识列缺失时的 name

`name` 仍是 NOT NULL 且 `uk_meter(kind,zone,name)` 仍在(它现在只是「标签 + L3 兜底」)。
无标识列时,**建档**用 `区域-位置-表名` 拼(截 64 字);仍为空则用编码;再为空才报错。
拼出的名撞了唯一键(且不是同一块表)→ 追加 `#2/#3…`。

### 3.2 字段刷新语义

| 类别 | 字段 | 导入时 |
|---|---|---|
| 身份锚点 | `id` | 永不变 |
| 分区/类别 | `kind`, `zone` | 匹配条件之一,不改 |
| 可刷新属性 | `area`, `spot`, `tenant_name`, `tenant_id`, `building_id`, `ownership`, `meter_type`, `sub_name`, `code`, `factor` | 行里**非空才覆盖**(空不清既有——同一块表在不同 sheet 详略不一) |
| 人工资产 | `contract_id`, `retired_ym`, `device_type`, `sort_no` | **导入永不动**(合同绑定/停用是人工裁定) |
| 读数 | `meter_reading` | 按 `(meter_id, ym)` 先删后插;`factor_snap` = 行倍率,空则档案倍率 |

### 3.3 换表 / 停用配合

- **换表**:同位置新编码 → 护栏剔除旧候选 → 新建一块表。旧表由人工在档案里填 `retired_ym` 停用。
  (旧做法是给标识加「新」字后缀就地改名,历史读数从此挂在叫「XX新」的档案上,「新」字永久烙进身份。停止。)
- **停用**:导入**不写** `retired_ym`,也不因「已停用」字样跳过行(读数照收,用量本来就是 0)。
  停用是账期口径的人工裁定(`MeterService.retired`)。

### 3.4 未匹配处置

| 分类 | matchBy | 落库 | 展示 |
|---|---|---|---|
| 按编码命中 | `code` | 刷新档案 + 写读数 | 计数 |
| 按位置命中 | `addr` | 同上 | 计数 |
| 按标识命中 | `name` | 同上 | 计数 |
| 新建 | `new` | 建档 + 写读数 | 计数(**异常放大器**:重导老文件时这个数应≈0,暴涨=身份判错) |
| 歧义 | — | **不落库** | 错误清单逐行列候选 id |

> 为什么歧义不猜、新建仍自动落库:歧义猜错会把 A 表的读数写进 B 表(不可逆、无痕);
> 新建猜错只是多一条孤儿档案(可见、可删)。代价不对称,处置就不对称。

## 4. 返回体

`/meters/import` 返回 `MeterImportResultDTO`,在共享 `ImportResultDTO` 上加一个 `matches`:

```
{ imported, skipped, errors:[{rowIndex,label,reason}],
  matches:[{rowIndex, label, matchBy:'code'|'addr'|'name'|'new', meterId}] }
```

其余 20 个导入器的 `ImportResultDTO` 不动(结构兼容,多一个字段前端忽略)。
导入结果弹层按 `matches` 分组显示四个计数;歧义行走既有错误清单。

> 真·导入前预览(dry-run)没做:匹配要查库,预览在前端。要看分类先导一次——
> 歧义行本来就不落库,新建行可见可删,代价够低。等误建真的发生了再加 dry-run 端点。

## 5. 迁移

**不加 V69。** 理由:
- 不需要新列 —— `code`/`area`/`spot`/`sub_name` 都已存在(V45/V46/V63/V68)。
- 不需要新唯一键 —— 编码有 5 组已知重复(宿舍 3 组同码 + 工地水表拿文字当编码),加 UK 会直接卡死导入;
  歧义在应用层报出来给人处置,比数据库拒绝整批更有用。
- 不需要新索引 —— 导入一次性 `selectList(null)` 全量载入(1417 行)在内存里建三个索引,零 N+1。

已有的影子档案(261 对 `.00` + 28 条尖峰平谷假表)是**存量数据问题**,给合并脚本
`backend/scripts/fixes/meter_merge_shadow.sql`,**默认只跑清单查询,合并语句全部注释**,待人工核对后执行。
