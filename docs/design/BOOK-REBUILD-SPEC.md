## H1 六车间电梯2 倍率按 40

**复核（直读原册）**：同一块表 `220605000026` 在两张 sheet 上倍率不同——

| sheet | 倍率 | 度数 | 用途 |
|---|---|---|---|
| `公共电数据` H119 | **40** | `L119 = ROUND((726.28−706.11)×40,2) = 806.8` | **对外收费依据**：`V119 = 132.77 元/层` 是租户实付单价 |
| `二期园区电` H88 | 50 | `S88 = 1008.5` | 抄表底稿 |

系统现按 50 出账（`std_value = 165.96`），每层多收 33.19 元（+25%）。

**改法**：`V79` 把 `meter id=77 (code=220605000026)` 的 `factor` 改 **40**，并置 `owner_manual` 无关的新标记不动；`note` 写明「原册两张表倍率打架，用户 2026-07-31 拍板按对外收费表（公共电数据 H119=40）」。

**验证**：重生成后 rule 22 的 `qty_total = 806.80`、`cost_amount ≈ 796.59`、`std_value = 132.77`，与原册 `L119/W119/V119` **逐格相同**。这三个数是硬锚点。

⚠ 已录的 `meter_reading.factor_snap` 是快照，改档案倍率**不会**改历史月。必须一并把 2024-02 / 2024-05 该表读数的 `factor_snap` 改 40（迁移里做），否则重生成仍按 50。

## H2 `永龙反向有功` 不进 Σ —— 新增 `ownership='register'`

**复核**：原册 `二期园区电 r51` 整行只有 `H51=100`、`N51=155.27`，`A/B/C/D/E/F/G` 与 `I:M` 全空 → `S51 = ROUND((155.27−0)×100,2) = 15527 度`。系统导入成 `meter 1421 永龙反向有功`（三车间·三楼302室，`ownership='tenant'`，`prev_total=0.00`），**正计入 building 32 的分表Σ**（47884.05 里占 32.4%）。

**这是两个错叠加**：
1. 「反向有功」是同一块物理表的**另一个计度寄存器**（与 `永龙电` id=40 同为三楼302室），不是用电量；
2. 原册 `I51` 是**空**，导入按 0 起算，把一个绝对读数当成了本月增量。

**改法 —— 新增 `ownership` 第 6 个值 `register`**：
```
register = 非计费计度寄存器(同一物理表的反向有功/需量等附属读数)
           不进楼栋分表Σ、不进公摊池分母、不向租户收、不进抄表进度分母
```
- `Meter.ownership` 的 `@Pattern` 与前端 `OWNERSHIP_LABEL` 同步加这一档（标签「计度寄存器」）。
- `AllocService.inSubSigma` 与前端 `meterSplit.inSubSigma` 一并排除。
- `V79` 把 `meter 1421` 置 `register`。
- 导入侧 `classifyOwnership`：名称含 `反向有功|正向无功|反向无功|需量|最大需量` → `register`（这些是电表寄存器的标准叫法，不会误伤真表；判据写进注释）。

**验证**：building 32 的 `d_qty` 从 **47884.05 → 32357.05**；二/三/四车间合并组 `d_qty` 从 81158.44 → **65631.44**，`e_qty` 从 −4511.56 → **−20038.56**。这个变化是**预期的**，spec 明确允许，V1 要逐栋列出。

⚠ **同时要查全库还有没有同类寄存器行**（名称含上述关键词的），一并处理并列清单。

## H4 按原册重建一期公共电模型（本刀主体）

### H4.1 原册真实结构（图谱 §1，直读所得）

- `B3:C4` 是**合并单元格**，表头只有「区域」一个词，C 列**没有独立表头**。作者心智：**一个位置描述占两格，能细就细到楼层方位，不能细就整格写区域**。
- **85 个数据行，B/C 两列零缺失**，且 **B/C 完全没有纵向合并**（每行都重复写）。
- **分块靠 7 个合计行**，不靠区域：`r11 A座及园区公共表合计` / `r31 A座电梯及楼层公共电合计` / `r45 B座` / `r62 C座` / `r74 D座` / `r85 E座` / `r97 F座`。
- **`side` 在原册不存在**：C 列 26 行「天面」**全部不带方位**，东西之分写在 **D 列（电表名称）** = `东侧货梯`/`西侧货梯`。
- 真正表达「共用一个值/同一个池」的是 **AC/AE/AF/AG 等列的纵向合并**（如 `AA27:AA30 / AC27:AC30` = A座 4 部电梯一个池），**不是 B/C**。

### H4.2 改法

| # | 原册 | 系统现状 | 改成 |
|---|---|---|---|
| a | C 列 = 楼层+方位**一格** | `floor_label` + `side` 两个字段，且造出「天面东侧/天面西侧」 | **废弃 `alloc_rule.side` 的一期用法**：一期池的定位统一回落到**一格** `floor_label`（值域直接取原册 C 列 17 个取值）。`side` 列保留不删（二期全 NULL，无害），但一期不再写入，屏上不再拼接 |
| b | 分块 = 7 个合计行 | 按 `building_id` 分带 | **分带改为原册块**：`alloc_rule` 加 `book_block VARCHAR(32)`，值 = 原册块名；屏上按 `book_block` 分带、带尾出合计行（口径与原册 `SUM` 区间一致，含 `r31` 那个 `S` 起于 13 而 `AD/AE/AF` 起于 12 的怪癖，按册复刻） |

| d | 自然键 = A 列（`A4西侧走廊灯`/`中大4楼公共`） | `一期 A座·四楼西侧·走廊灯` 四段拼名 | `alloc_rule` 加 **`book_key VARCHAR(64)`** = 原册 A 列原文，作为回溯锚点；`name` 保留现状（不破坏既有引用），但屏上池名称列**优先显 `book_key`**，全名进 title |

### H4.3 验收线（硬锚点，逐条对原册）

1. 一期屏按 **7 个块**分带，块名与原册 `B11/B31/B45/B62/B74/B85/B97` 逐字相同。
2. 招商中心 3 行分别落在**块1**（`r8`）与**块2**（`r17/r18`），**不再自成一带**。
3. 一期池的「楼层」列取值 ⊆ 原册 C 列那 17 个值；**屏上不再出现 `天面东侧`/`天面西侧`/`整栋净额`/`按车间`/`–`**。
4. 池数 = **85**（含补回的 4 个无表行）。
5. A座天面 4 行、`AC27` 一个池（`12487.04㎡`、`0.08`、`AD` 逐行 151.3/298.82/225.28/335.78）——与原册逐格相同。
6. **红线**：`alloc_pool_result` 的 `cost_amount / std_value / base_snap / qty_*` 对**既有 67 个池**必须逐格不变（新增 4 个 manual 行除外）；`alloc_loss_result` 只允许 H1/H2 造成的变化。

## H5 抄表批量删除导入数据（新功能）

**背景**：用户原话「2023年是我自己测试导入的2023年数据，抄表现在没有批量删除导入数据的功能，添加」。库内 2023-10 有 80 条读数 + `alloc_pool_result` 90 / `alloc_loss_result` 2 / `alloc_result` 30 条派生。

**现状**：只有 `DELETE /api/meters/readings/{id}` 单条删除；`import_log` 只记摘要，无行级关联，**按导入批次回滚做不到**。

**改法 —— 按账期批量删除**（这是用户真实需要的粒度，也是唯一无歧义的批次单位）：

1. `DELETE /api/meters/readings?ym=&kind=&zone=` —— `ym` 必填，`kind/zone` 可选。
2. **先预览后执行**：`GET /api/meters/readings/delete-preview?ym=&kind=&zone=` 返回「将删 N 条读数 / 涉及 M 块表 / 其中 K 块删完后零读数 / 该月已生成的派生快照 X 条」。
3. **级联选项**（默认全开，UI 上可勾）：
   - 同时删该 ym 的 `alloc_pool_result` / `alloc_pool_meter_result` / `alloc_loss_result` / `alloc_result`（`source='gen'` 的；`manual` 行**保留**并在预览里点名）
   - 同时删「删完读数后零读数、且非种子建档」的表档案（撞 `alloc_rule_meter` FK 的**跳过并列出**，不静默失败）
4. **二次确认**：前端弹窗必须复述预览数字，输入账期字符串才放行（不可逆操作）。
5. **审计**：写一条 `import_log`（`data_type='meter_delete'`、`type_label='抄表批量删除'`、`target=ym`、`ok=删除条数`、`operator`）。
6. **权限**：仅 admin（viewer 只读角色不可见入口）。
7. UI 落在 **园区抄表屏编辑态**的「批量删除本期」按钮 + 导入中心的账期行操作。

**IT**：预览数字与实删一致；`manual` 行不被删；撞 FK 的表档案跳过并出现在返回里；viewer 调用 403。
