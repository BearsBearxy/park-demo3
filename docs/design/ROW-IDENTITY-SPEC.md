# 刀I：行的身份回归原册（ROW-IDENTITY-SPEC）

> 定稿 2026-08-01。原册结构唯一事实源 = `BOOK-STRUCTURE-2024-02.md`。

## 0. 病根：行的身份来自「池」，而原册的身份是「行」

刀E/F 做的「逐表行」只把**电表列**摊开了，**楼层/名称两列仍取池级属性**；`sign=-1` 的净额构成表也被当成分摊明细的行渲染；`fold_qty` 折入量在合计里被计了两遍。

**原册的合并规则（图谱 §1.3 实测）**：
- **B（区域）/ C（楼层）/ D（企业名称）永远逐行写，从不纵向合并**；
- 真正纵向合并的是 **AA（分摊系数）/ AC（分摊标准）/ AE（已分摊）/ AF（盈亏）/ AG（备注）**。

所以正确模型是：**一行 = 一个身份（B/C/D 各自独立）；「池」只是 AA/AC/AE/AF 的共用范围**。

## 1. 复核：问题只落在两个池

只读 SQL 盘查 p1 全部多表池：

| **23** | 招商中心电1 | 7 | 2 | **5** | ✗ 5 块负号表不该出行 |
| **24** | 地下车库东侧照明 | 4 | **2** | 0 | ✗ 折错：4 行本是各自独立的行 |

**结论：改动只涉及 rule 23 / rule 24 与渲染层，其余 8 个多表池一格不许动。**

## I1 拆开 rule 24：4 块表还原成 4 行

**依据**：原册 r5–r9 的 `AC/AD` **逐行独立**（32.88/20.67/113.10/169.42/244.21），**没有纵向合并**——它们不是一个分摊池。这 5 行唯一共用的是 `AG5:AG9` 合并的备注「计入园区损耗分摊」，那是**去向标记**，不是分摊池。

而 `一期园区损耗!G4/G6..G10 = ROUND(SUM(公共电分摊明细!S5:S9)/6, 2)` 取的是**这 5 行的 Σ**，不是某个池的量。

**改法**：
1. `V84` 把 rule 24 拆成 **4 条独立规则**（`book_key` = `地下车库东侧照明` / `地下车库西侧照明` / `A1大堂` / `生活加压泵`，各绑 1 块表，`method='direct'`，`AC=AD=整额`），`sort_no` 按原册行序（r5/r6/r7/r9）。
2. 这 4 条 + rule 23（招商中心，r8）**共 5 条**统一标 `fee_key='park_loss_pool'`（现成键，语义就是「计入园区损耗分摊」），并把原册备注「计入园区损耗分摊」写进 `note`。
3. **删除 `fold_qty 23 → 24` 这条链**（rule 24 已不存在）。
4. **损耗侧改取「这 5 条规则当月 `qty_total` 之和」**：`AllocService` 里 `park_loss_pool` 的取数从「某个池的量」改成「Σ(fee_key='park_loss_pool' 的 p1 规则)」。
   - 锚点：`Σ = 29.51+18.55+101.51+152.06+219.19 = 520.82`；`G = ROUND(520.82/6, 2) = 86.80`；A座另 `−1500` → `g_qty = −1413.20`。**六座 `g_qty` 必须一格不变。**

## I2 `sign=-1` 的净额构成表不出逐表行

**依据**：招商中心那 5 块负号表（`中大A304公共电1 / 优凯A305电 / 双成电2 / 中大4楼公共 / 4楼空调外机电`）在原册**「公共电分摊明细」上根本不存在**——它们是 `一期园区电`（抄表底稿）的 `S44:S48`，是 `X50 = S49+S50−SUM(S44:S48)` 这个净额公式的中间量。

**改法**：`poolMeterLines` 只为 `sign=+1` 的绑定表出行；`sign=-1` 的表进主行的 **hover 明细**（列出「净额构成：总表 A+B − 子表 C/D/E…」，含各自度数），并在主行「电表」列尾加一个 `−5` 角标示意有 5 块被扣减的表。

**验收**：招商中心在块1 只占 **1 行**，用量 152.06、应分摊 169.42；hover 能看到 `697.60 + 444.80 − (4.74 + 0 + 315.60 + 0 + 0) − 670 = 152.06` 的完整构成。

## I3 逐表行的 楼层 / 名称 逐行取自该表

**改法**（`PoolLedgerView` + `poolLedgerLogic`）：
- 「楼层」列：取 **该行电表的 `floor_label`**（`MeterLine` 已有 `spot`，需后端补 `floorLabel`），不再取池级 `floor_label`。
- 「池名称」列：取 **该行电表的用途**（`tenantName ?? name`，即原册 D 列「企业名称」），不再取池级 `book_key`；池级 `book_key` 移到该池**首行**的副标题（与 `Σ 用量/金额` 同处）。
- **rowspan 只保留给** 分摊语义 / 分摊标准 / 系数(月) / 加度(月) / 摊出 / 差额 / 实收 / 盈亏 / 备注 —— **与原册 AA/AC/AE/AF/AG 的合并范围逐一对应**。
- 单表池（占绝大多数）两种取法结果相同，无变化。

**验收**：块1 前 4 行楼层 = `负一层 / 负一层 / 一楼 / 负一层`，名称 = `地下车库东侧照明 / 地下车库西侧照明 / 大堂 / 生活加压泵`——与原册 B/C/D 逐格相同。

## I4 tfoot 合计不许双计

`poolFooter` 现在把每个池的 `qty_total / cost_amount` 无条件相加。`fold_qty` 的目标池其量里已含源池的量 → 双计。

**改法**：合计时**跳过「作为 `fold_qty` 源被别的池吃掉」的那部分**——I1 之后 `fold_qty` 链已删，理论上不再发生；但要**加一条防御**：`poolFooter` 对存在 `fold_qty` 入链的池，扣减其链入量（后端在 `PoolRow` 上给出 `foldedQty` 字段供前端扣减），并补单测锁死。

**验收**：块1 小计 = **3204.62 / 3570.49**，与原册 `S11 / AC11` 逐格相同。

## I5【临时措施】幽灵行先停用，等用户拍板

V79 已把 `meter 1421 永龙反向有功` 改成 `ownership='register'`，一旦重新生成，二/三/四车间租户损耗率会从 **0.0255 → 0.2067**（8.1 倍）。用户尚未在 A/B/C 三个选项里拍板。

**改法**：`V84` 里把 `meter 1421` **暂改回 `ownership='tenant'`**，恢复拍板前的状态，使本刀的验证能在「损耗数字不变」的前提下进行。迁移注释写明：这是等待用户拍板的临时回退，选项与后果原样记录在注释里。

**红线**：本刀 `alloc_loss_result` 全列必须与刀前逐格相同。
