# S20-BILL-DELIVERY-SPEC — 催缴单交付链：收款账户 / 确认状态 / 导出

> 需求来源：用户 2026-08-12。范围**只做交付闭环**，不碰附表10/台账对账、不做回款核销。
> 前置调研：wf_04bd0096（paymap 键体系与抽屉结构）、wf_5d0e5dea（导出实现与源册版式规格）。

## 0. 一句话

催缴单从「算出来」走到「发出去」：**指定收款公司 → 核对确认 → 导出 Excel（通知单 / 对账表）**。

## 1. 数据层

### 1.1 `management_company` 扩列（V94）

现有：`id / name(唯一) / short / sort_no`（6 家：创显/B2/帮管好/一泽/积前/创燊高）。

| 新列 | 类型 | 语义 |
|---|---|---|
| `full_name` | varchar(128) NULL | 法定全称，印在通知单落款与账户块（如「佛山一泽科技有限公司」）。空则回落 `name` |
| `status` | tinyint NOT NULL DEFAULT 1 | 1=启用 0=停用（停用的不再出现在收款公司选择器，历史单不受影响） |

**本刀只保证「能新增/改名」**，账户明细由用户后续在界面自行录入。

### 1.2 `company_account` 新表（V94）

一个公司可有多个收款账户（对公银行 / 微信 / 支付宝 / 个人卡）。

| 列 | 类型 | 语义 |
|---|---|---|
| id | int unsigned PK | |
| company_id | int unsigned NOT NULL FK | → management_company |
| kind | varchar(12) NOT NULL | `bank`(对公银行) / `wechat` / `alipay` / `personal`(个人卡) / `other` |
| account_name | varchar(64) | 户名（对公=公司全称，个人=收款人姓名） |
| account_no | varchar(64) | 账号 / 收款码标识 |
| bank_name | varchar(128) | 开户行（bank/personal 用；wechat/alipay 留空） |
| is_default | tinyint DEFAULT 0 | 该公司默认收款账户（导出时预选） |
| sort_no | smallint DEFAULT 0 | |
| remark | varchar(255) | 备注（如「仅限水电费」） |

字段全部可空 —— 建表即用，用户后续逐条补录。

### 1.3 `bill_notice` 状态流（V94 加两列）

| 新列 | 语义 |
|---|---|
| `confirmed_at` / `confirmed_by` | 用户点「确认无误」的时间与账号 |
| `exported_at` | 最近一次导出时间 |

**状态机**（`status` 复用现有列，值域扩展）：

```
draft(待核对) ──确认──> confirmed(已确认) ──导出──> exported(已导出)
     └────────────────── 重新生成(仅 draft) ──────┘
                         confirmed/exported 户被跳过并计数报告
```

- **单向流转**，不提供"退回草稿"按钮（要改就作废后重生成，走既有 `void`）。
- **重新生成保护**：引擎已有 `issuedTenants` 跳过机制（`BillNoticeService:437-439`），扩为"status ∈ {confirmed, exported} 的户整户跳过"，生成结果里报告跳过户数——**这是防止已核对数据被静默覆盖的闸门**（呼应审计 P0「月度关账」的轻量版）。
- 状态是**单据级**存储、**户级**展示：该户全部单都 confirmed 才显示"已确认"；部分确认显示"部分确认"。

## 2. 交互流（借鉴成熟财务产品：草稿→审核→发出）

### 2.1 催缴单列表新增「状态」列

| 状态 | 徽标 | 含义 |
|---|---|---|
| 待核对 | 灰 | 生成后默认 |
| 已确认 | 蓝 ✓ | 用户核对无误 |
| 已导出 | 绿 ✓✓ | 已生成交付文件 |
| （叠加）未设收款公司 | 橙色小圆点 | **提示不阻断**，任何状态下都显示，直到设了公司才消失 |

行内「确认」按钮（hover 出现）+ 表头批量「确认选中」。

### 2.2 确认时的提示（用户明确要求：提示但不阻断）

点确认时若该户存在 `pay_company_id IS NULL` 的单：

> ⚠ **该租户有 N 项费用未指定收款公司**
> 导出的通知单上这部分将不显示收款账户信息，租户可能不知道往哪付款。
> 　　[ 去指定 ]　[ 仍然确认 ]

- 「去指定」→ 直接打开该户的收款方分段（S19 抽屉段）。
- 「仍然确认」→ 状态照常变 confirmed，**橙点保留**（用户要求"提示依旧存在"）。
- 导出时同样不阻断，只在导出结果里报告「N 户无收款账户」。

### 2.3 导出后的反馈

导出成功 → 该批户状态变 `exported`，列表状态列变绿；顶部出现结果条：
`已导出 42 户 / 68 张通知单 · 其中 5 户无收款账户`。

## 3. 三个入口（催缴单页 `.bn-actions`，从左到右）

1. **收款公司**（新）→ 管理公司与收款账户（§4）
2. **收款簿**（S19）→ 批量指定 租户 × 费用项 → 公司
3. **系数簿**（S14，已有）
4. **导出** ▾（新）→ 两项：`发租户 · 通知单` / `发财务 · 对账表`
5. **重新生成**（已有）

## 4. 收款公司管理窗口

左栏公司列表（可新增/改名/停用），右栏该公司的收款账户列表（可增删改、设默认）。
本刀交付**能用的空表单**：公司名必填，账户所有字段选填。

## 5. 导出

### 5.1 发租户 · 通知单（多选窗口）

- 期页签 + 楼栋分组 + **租户多选**（默认勾选"已确认"的户；未确认的可勾但会提示）；
- 每家公司选用哪个收款账户（下拉，默认取 `is_default`）；
- 导出粒度：**一户一个 Excel 文件**；同户跨两家收款公司 = 文件内两个 sheet（sheet 名 = 公司名）；
- 打包 zip，文件平铺：`费用缴费通知单-2024年02月-王红婷.xlsx`。

> **2026-08-14 改（用户拍板）**：原方案是"一联一个文件、zip 按公司分文件夹"。
> 用户指出：一户可能要给几家管理公司分别转账，按公司分文件夹等于把同一户的单据拆到几个目录，
> 发给租户时没法整理。改为**一户一个文件**，跨公司的拆分下沉到 sheet —— 租户拿到一个文件，
> 翻 sheet 就知道每家公司各收多少、各自的账户是哪个。
>
> 同一刀把**租金板块并入通知单**：一页两表，上表「租金、物业维护费」、下表「水电费」（§5.3）。
> 文件名与页头标题随之从「水电费缴费通知单」改为「费用缴费通知单」——里面已经不只是水电了。

### 5.1.1 单户导出（催缴卡片按钮，2026-08-14）

明细抽屉底部「导出本户 Excel」：同一套版式与账户口径，只是不打包、不经多选窗口。
账户没有选择界面 → 取各公司的**默认收款账户**（`is_default`，其次首个）。
与批量一致地回标 `exported`（"已导出"= 这户的文件生成过，不区分从哪个入口生成）。

### 5.2 发财务 · 对账表

单文件多 sheet：每家公司一个 sheet（户 × 费项 × 金额），+ 一张「总表」列各公司合计与未设置公司清单。

### 5.3 版式（选 A：引入 exceljs）

SheetJS 社区版不支持字体/边框/填充（Pro 功能），无法复刻源册通知单。**引入 `exceljs`（懒加载，与现有 xlsx 并存不替换）**，按调研测得的源册规格复刻：

- 12 列宽：`[3.43, 4, 6.86, 17.43, 10.86, 9.86, 8.43, 9.29, 10.71, 13.29, 12.86, 16.71]`
- 结构：标题(B:L合并) / 计费期限 / 租户名+位置 / **租金表(§5.3.1)** / **水电表** / 水电费合计(双线) / 本期合计 / 上期欠费 / 收款banner / **账户块(3行合并)** / 制表复核 / 签收信息栏 / 落款(公司全称+日期)

#### 5.3.1 上表：租金、物业维护费（2026-08-14）

版式基准 = 源册 `…/2024年3月费用数据/二期/二期2024年03月租金.xlsx` 每个租户 sheet 的通知单块（B34:I40）。
源册 8 列映到本页 12 列栅格，**金额落 K、备注落 L，与下表逐列对齐**（两表看着是同一张纸上的两块）：

| 源册列 | 本页列 | 取值 |
|---|---|---|
| 物业名称 | B:C（按 premise 竖跨合并，同下表块名） | `groupRentByPremise` 的块 label |
| 收费项目 | D（= 下表「项目」同列） | `rentFeeName`（mgmt/infra 带段类型前缀） |
| 空地面积㎡ | E | 段类型 `land` 的面积 |
| 建筑面积㎡ | F | 其余段类型的面积；带公摊时是 `rentAreaText` 的「1528+458」拆解串 |
| 面积单价㎡/元 | G:H | `price_snap` |
| 月单价（元） | I:J | 面积 × 单价（签约标准月额）；无面积的按月固定项回落金额本身（源册 G38=H38=300） |
| 应收金额（元） | K | `amount` |
| 备注 | L | 人工覆盖 > 引擎（折算式「1000÷29×21」/「免租扣 5200.00」） |

- **月单价 ≠ 应收金额**是源册本来的语义（前者签约标准额，后者当月实收）。2024-02 全库实测两值逐行相等，
  差额只出现在按天折算/免租那几行——算式就在备注列。
- 块小计仅在多场地时补（源册单场地只有一个「合计」B40:G40，本实现跨度照抄）。
- **不做**：源册的问候语段落（「尊敬的X：…请于X月X日前缴至我司账号」）——缴费截止日没有数据模型支撑，
  编一个日期比不印更糟。收款截止靠既有的「滞纳金按每日 ‰收取」行表达。
- 公摊三类行特殊形状：电梯消防「每层 N 元，共 X 层」/ 损耗「基数 × 率%」/ 路灯绿化「面积 ㎡ × 单价」
- 无账户信息时**整块省略**（源册本就有 17/56 户是无账户块的简化版）
- A4 纵向、scale 85、边距按源册
- **口径复用**：所有费项名/合并行/用量单价格式一律调用 `billNoticeLogic` 现成纯函数，禁另抄

### 5.4 落地（`frontend/src/utils/billNoticeExcel.ts`，2026-08-12）

版式基准 = 源册 `…/2024年3月费用数据/二期/二期2024年2月水电费.xlsx` 的 `王红婷` sheet 逐格实测
（两联：电/水费联 → 一泽；维护费联 → 积前 —— 正是「按收款公司拆」的当年实物）。

**导出入口**

| 函数 | 作用 |
|---|---|
| `exportNoticeZip(items, ym, accountOf, companyOf)` | 一户一个 workbook → fflate zip（level 0）平铺，返回 `{files, sheets}` |
| `exportTenantNotice(item, ym, accountOf, companyOf)` | 单户直接下载一个 xlsx（催缴卡片按钮，§5.1.1） |
| `exportReconWorkbook(rows, ym, sheets)` | 总表 + 每公司一 sheet（户 × 费项 × 金额）单文件下载 |

纯函数（spec 锁 35 例）：`splitByPayCompany` / `buildNoticeSections` / `buildRentBlocks` / `noticeFileName` /
`buildReconSheet` / `buildReconSummary`；`tenantWorkbookBytes` / `reconWorkbookBytes` 出字节供测试与打包复用。

| 线路损耗「基数 × 率%」 | ✅ | I 走 `0.00`，J 走 `0.00%`，备注固定「用电总金额×损耗率」 |
| 路灯/绿化水「面积 ㎡ × 单价」 | ✅ | 面积走 E:G 合并，备注「面积×公摊单价」 |
| 尖峰跨 2 行（D/E/F/G/H 竖合并） | ❌ 不做 | 源册手工法产物：一个尖峰寄存器按比率拆「按峰值/按尖峰」两行。引擎逐段独立行（各段自带行至），数据形态不产生该配对 |

**口径复用点**：项目名 `billFeeLabel`/`segLabel`；维护费块 `mergeMaintRows`（纸单一项一行，
合并粒度=场地带内，与抽屉同口径）；用量/单价 `billQtyCell` 与合并行的 `qty/price`；备注 `noteDisplay`
（人工覆盖 > 引擎）。⚠ 单价印的是**能验算的最少位数**（144×1.20607=173.67），与屏一致，
不印落库全精度 1.20606875 —— 源册手工表印全精度，此处刻意从屏（S7 拍板）。

**已知简化**：⓪未指定收款公司的那个 sheet 落款处不印公司名（不知道印谁；日期照出）；
①块合计一律取 `groupExcelStyle` 原始行累加，不经合并行（一分钱不改）；
②同块跨多场地/多块表时才给项目名冠场地/表名（单表户与源册逐字相同）；
③公摊项行序照 `MERGE_RANK`（消防在电梯前），与源册手工顺序（电梯在前）相反；
④宿舍逐间子表版式未接（源册宿舍段另一套宽行范式，本刀按通知单正表出）。

**View 侧提取**：`BillNoticesView` 内联的 `utilRows` 拍平已提到
`billNoticeLogic.buildUtilRows(groupExcelStyle(lines))`（band/line/merge/sub/part 五型，泛型），
集成时 View 改调它即可，模板不动。
