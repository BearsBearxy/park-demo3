# 编辑模式规范（EDIT-MODE-SPEC）v4

> **2026-08-22 晚 v4 修订（用户纠正，推翻 v3 的 ③）**
>
> v3 写的是「有其中任一项即可进编辑模式，缺的那几项在页面内单独给授权入口 +
> 一条『本页有 N 项需要主管权限』的提示条」。用户看到实物后否了两点：
>
> **① 点了编辑模式、授权取消 → 必须留在浏览态。**
> v3 的做法是「用现有权限进编辑模式」，于是页面上出现了 `重新生成` / `完成` / `新增池`
> 这些编辑态按钮 —— 用户原话：「我说的不是如果没通过授权的话依旧是非编辑模式吗，
> 现在重新生成，完成这些按钮不是进入编辑模式下的按钮吗」。
>
> **② 那条提示条撑开了整页布局，删掉。**
> 用户原话：「你那条请求授权的提示撑开移动的整个页面的布局，我不需要有这个提示并且按钮」。
> 见新立的 [LAYOUT-STABILITY-SPEC](LAYOUT-STABILITY-SPEC.md) ——
> 这条规则本来就写在 LIST-PAGE-SPEC 的审核清单里（「编辑态切换引发布局位移 ❌」），
> 是我加提示条时没去翻。
>
> **于是新铁律：进得了编辑模式 ⇒ 本页权限一定齐。**
>
> | 点「编辑模式」 | 结果 |
> |---|---|
> | 权限齐全 | 直接进 |
> | 缺任何一项 | 弹授权窗 → 授权成功才进；**取消 = 什么都没发生** |
> | 连提权都不能问（viewer / 股东） | 按钮不出现 |
>
> 推论：**编辑模式里不再存在「点不动的控件」** —— 这才是「脱裤子放屁」的根治。
> `askPolicy` / `askMonthly` 那类「点了转成授权请求」的包装已全部撤掉。
>
> ⚠ **连带必须做的一件事**：授权有 30 分钟 TTL，到期时人可能还在编辑模式里。
> 不处理的话控件会突然集体点不动，正好绕回要根治的毛病。
> 所以 `useEditMode` 里有 `watch([editMode, missing], ([on, m]) => { if (on && m.length) exit() })`
> —— **授权失效即自动退出编辑态**。带上 `editMode` 是因为深链会直接写 `editMode.value = true`，
> 只盯 `missing` 抓不到那条路。
>
> **代价（用户已知悉）**：财务专员要用公共电核算的「生成本月」，
> 也得先请主管授权 `param-policy` 那一档 —— 因为那一页两档权限都要。


> **2026-08-22 v3 修订（用户拍板）—— 两条改动，都来自实际使用中的反馈：**
>
> **① 切页签不再退出编辑模式。** v2 的 `onDeactivated` 复位是为了防「忘了自己在编辑态」，
> 但代价是「专员切去别的页面核对一眼回来，编辑态、草稿、刚拿到的主管授权全没了」。
> 现在切页签**只关浮层**（抽屉/弹窗 Teleport 到 body，不随实例停用移出，必须关），
> 编辑态与草稿跟着页面实例留着（KeepAlive）。抄表屏原来的 `draft.clear()` 一并去掉 ——
> 那正是「没保存的东西自己没了」这类事故的源头。
>
> **② 无权限的账号也看得到编辑模式按钮。**
> v2 §1 是「仅 admin 可见」「viewer 永远无按钮」。v3 改为：
>
> | 角色 | 编辑模式按钮 | 点下去 |
> |---|---|---|
> | 有本页任一写权限 | 显示 | 直接进；缺的那几档在页面内单独给授权入口 |
> | 无写权限但有 `elevate:request`（财务专员、总经理…） | **显示** | 弹主管授权窗（ELEVATION-SPEC） |
> | `viewer` / `shareholder`（园区股东） | **不显示** | —— |
>
> 理由：藏掉入口的话，用户只会以为系统没有这个功能，而不会去想「我可能没权限」。
> 「看得见、点得动、点了告诉你缺什么并给出路」才是能自助解决的界面。
>
> **③ 编辑模式内不得存在「点不动的写入口」。**
> 一页同时碰多档权限时（如公共电核算 = 出账运行 + 计费口径），进了编辑模式却有一半控件
> 灰着不给点 —— 用户原话「有点脱裤子放屁」。改为：控件照常画，点下去无权则转成授权请求，
> 页面顶部同时给一条「本页有 N 项需要更高权限」的提示条 + 「请主管授权」。
>

> **↑ 这一段已被 v4 推翻**（2026-08-22 晚）。当时的顾虑（专员每月出账要叫主管）属实，
> 但用户在看过实物后选择了「宁可多叫一次主管，也不要似是而非的半开编辑态」。

## 1. 核心规则（v2）

- **浏览态（默认）＝完全只读**：页面上任何数据都不可修改——常量、配置、月度金额、抄表/充电记录、电表值、映射关系，一律纯文本展示；导入、新增、删除、模拟填充等一切写入口**隐藏**。
- **编辑模式＝一切修改的唯一入口**：工具栏右侧「编辑模式」按钮（仅 admin 可见）→ 进入后按钮变「完成」；行内输入、抽屉增删改、写入口全部出现。
- 只读操作不受管：查看、展开、搜索、切期、模板下载、导出、打印。
- 编辑态不跨会话：离开页面/切页签回来即回浏览态（onDeactivated 复位）。
- viewer 角色永远等同浏览态且无编辑模式按钮。

## 2. 适用范围（v2：全站）

- **所有含数据修改能力的页面**，不限于抄表/成本类新屏。
- **老屏等价条款**：既有页面已存在的显式编辑开关（如附表10「编辑表格」、台账编辑态）视为编辑模式的等价实现——不强制改名重做，但必须满足"浏览态零修改入口"这一铁律；不满足的（存在无开关的裸行内编辑/裸可点修改）列入改造清单。
- 新页面一律用统一的「编辑模式/完成」按钮。

## 4. v3 实现（2026-08-22）

统一收在 `composables/useEditMode.ts`，页面只声明「这一页会碰哪些权限」：

```ts
const { editMode, canEnter, missing, asking, toggle, askFor, onElevated } =
  useEditMode(['billing-run:edit', 'param-policy:edit'])
```

已接入：计费参数、公共电核算、催缴单、充电桩、电费成本、抄表、光伏 7 屏 +
`SchedHeader`（附表族 7 屏共用，一处到位）+ 系数簿 / 收款簿两个窗口（各有自己的
退出语义，直接用 store 的 `endElevation`，没套 composable）。

授权的作废点只有两个：**主动点「完成」** 与 **30 分钟到期**。切页面不作废。
