- **状态**：设计中（三项关键决策已获用户拍板：自动生成并保存 / 任何年份补齐 / 直接写入派生值）
- **日期**：2026-07-03
- **作者**：Claude
- **前置**：P2-G 派生链接（spec ed67249）已交付 overlay（对照徽标/填入）。本刀把定位反转：**派生负责生成账目骨架**，用户只补无派生源的行。

---

## 0. 定性（用户口径）

> 「我希望的是派生生成账目结构，剩下没有派生的才由用户手动输入或者导入；导入的数据如果与派生创建的重叠，对的上就显示对的上，对不上就显示对不上。」

- 有派生源的 36 条映射行（35 个物理行位）**自动出现在附表里并落库**，不再等导入。
- 其余 188 行照旧手录/导入。
- 导入与派生行重叠 → 复用 P2-G 已有对照（已证√ / 差异N月），零新机制。

## 1. 决策（Decision Log）

| # | 决策 |
|---|---|
| H1 | **进年自动生成并立即落库**（用户拍板）：进入某年明细、派生数据到位后，缺失的映射行自动生成并走现有 PUT 整年保存，成为正式行（年份门/报表中心/导出立即同步）。生成条件=该行派生序列**该年至少 1 个非空月**（全空不生成噪音行）。PUT 失败静默、表照常显示，下次进入重试 |
| H2 | **任何年份都补齐**（用户拍板）：不限空表；缺失判定 = (schedule, normalizeHeader(分组), normalizeHeader(行标签)) 无既有行——同标签双分组行（s2 光伏消纳×2）各自判定 |
| H3 | **生成行直接写入当时派生值**（用户拍板）：初始对照=已证√；此后数据层变化 → 该行自动显 差异/可填入（复用 P2-G overlay），即「对得上/对不上」的实现载体 |
| H4 | **DERIVE_MAP 扩展 `group` 字段**（35 物理行位的母册分组，实证见 §2）；生成行 kind=`detectKind(label)`（光伏小计→subtotal、损益→pnl、其余 detail）；插入位置=同分组**最后一个 detail 行之后**（无 detail 则该分组末行后；分组不存在则按 MAP 顺序追加到表尾成新分组块） |
| H5 | **零后端改动**：生成=客户端算行+现有 `PUT /api/pnl/{schedule}/{year}`（clear+insert，row_key 服务端重建）。幂等：每次进入按缺失判定算，已有则不重复生成 |
| H6 | **导入语义不变**（整年替换）：导入后文件行获派生对照徽标；文件里缺的映射行下次进年自动补回。既有「小计行存文件原值不自动重算」口径不变——生成行不触发小计重算 |

## 3. 行为与数据流

1. `PnlScheduleView` 进入某年明细：`loadYear` 与 `loadDerive` 都到位后（竞态守卫 year 未切走、非编辑态）→ `generateMissingRows(schedule, existingRows, deriveData)`。
2. `generateMissingRows`（`reports/pnlDerive.ts` 纯函数）：遍历扩组 MAP → 缺失判定（H2）→ 该 series 本年有非空月 → 产出 `{groupLabel, label, kind: detectKind(label), m: derived 12 月}`，按 H4 规则算插入位置，返回**完整新行序列**（既有行+生成行，顺序定妥）。
3. 有生成行 → 走现有整年 PUT → 重拉该年 → overlay 徽标照常渲染（生成行初始 已证√）。每 (schedule,year) 单次进入只尝试一次；PUT 失败静默。
4. 导入不变；「填入/全部填入」不变（数据层新增月份后对既有行补值仍走填入）。

## 4. 测试

- `pnlDerive.spec` 补 `generateMissingRows`：空表全量生成（含 kind 判定与分组顺序）/ 部分行补齐（s1 4 行种子→补 6 行且插位在同组 detail 尾）/ 同标签双分组独立判定 / 全空序列不生成 / 已齐全返回空。
- E2E 真跑：附表4（现 0 行）进入 2025 → 7 行自动出现且**落库**（年份门变已录入、刷新仍在、徽标已证√）；附表1（4 行种子）→ 补 6 行（二期租金收入=锚点值 2,841,683.37 派生月落位）；导入母册附表1 → 整年替换后对照徽标「对得上/对不上」如实；0 console error。
