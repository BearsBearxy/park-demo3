# 台账导入 v2/v3 规范 — 列名别名 + 多公司/多年月拆段 + 同sheet多月堆叠(2026-07-06)

## 背景:两次真实事故

**事故一(2025年1月表,已修)**:旧位置映射逐列硬套 → 创显表(创显标记列+12月结余+17费用+应收/收款/结余)整片错位。已改 matchByHeader 表头匹配 + balancePrev/totalCollected/note 可导入 + 后端列级 upsert(null=不动/0=清零) + 全零跳过记名 + 两屏双确认。

**事故二(2025年10月表,本规范修)**:导入 107 行跳过 19 行。经与 dev 库逐条核对,三个原因:
1. **旧后端进程未重启**:新 DTO 字段(balancePrev/totalCollected/note)被旧后端 Jackson 丢弃 → 只有结余的行(戎合 2,499,022.41 / 碧沃丰 / 翔海 / 暨南医美 / 尧萍 / 可盈)被全零防线跳过;88 行已导入的结余/收款/备注全部丢失。**运维铁律:改后端后必须重启 dev 后端(或 compose 重建)再导。**
2. **表头列名变体不识别**:10月表用「商铺租金/宿舍配套设施费/商铺基础设施维护费」,与系统列名「商铺、宿舍租金/宿舍配套费/商铺、宿舍基础设施维护费」字面不同 → 3 列整列丢弃 → 只有商铺租金的 5 家(传齐商铺 19,620/吉罗德商铺/李李商铺/袁华圣/广联宿舍)变全零被跳过,另有约 12 家(张丽莉 5,459.33+859.80/博浩/健明包装 6,122.72/…)对应列被静默置 0。
3. 真占位行 8 家(布司曼/可莱恩食品/威奈斯/神州航天/丁天伦/曹志明/万众/次生代)按设计跳过 ✓。

## 一、列名别名注册表(matchByHeader 引擎扩展)

`ColumnMapEntry` 增加可选 `aliases?: string[]`:匹配时 主label+aliases 全体参与(normalize 相等或列头前缀),模板展示/预览列仍只用主 label(避免"模板显示两个结余列→照模板制表空列覆盖清零"的旧问题)。引擎改动为纯增量,其余 8 屏零影响。

台账别名(事实源 = importRegistry.ledgerColumnMap):

| key | 主 label(系统/1月表) | aliases(10月表变体) |
|---|---|---|
| shopRent | 商铺、宿舍租金 | 商铺租金 |
| dormFacilitiesFee | 宿舍配套费 | 宿舍配套设施费 |

前缀碰撞已核:商铺租金/宿舍配套设施费/商铺基础设施维护费与既有 21 主 label 及分组行(办公室、厂房费用/宿舍费用/其他费用/N月电费/N月水费)互不误命中。新增别名时必须重做该核对。

## 二、多公司 / 多年月拆段导入(整册 workbook)

台账条目新增 `parseWorkbook`(优先级高于 customParse;粘贴路径被包装成单 sheet,行为不变):

- **每 sheet 独立解析**:标题年月正则(前3行「yyyy年m月」) + matchByHeader(含别名)。**balancePrev 动态标签按该 sheet 识别到的年月重建**(11月表的「10月结余」也能吃;识别不到才用屏上下文 prev)——否则跨月 sheet 的结余整列静默丢失(复审击穿后修复)。
- **公司识别**(每 sheet,按优先级):
  1. 前置标记列:**仅扫租户列左侧**(真实表标记列都在最前;右侧备注/费用列天然出局,不会被同文本备注误判成公司——复审击穿后收紧),在有租户名的数据行里 ≥90% 为同一非数字文本(如整列"创显")→ 该文本为公司名。需 matchByHeader 返回 meta(nameCol),引擎增量返回不破坏现有调用。
  2. sheet 名等于/包含某已有管理公司名 → 该公司。
  3. 回退当前屏/表单上下文公司。
- **单 sheet 有记录 → 返回 {records}**(现有平铺流程:租户预检 ResolveDialog、两道 confirm 全保留)。
- **多 sheet 有记录 → 返回 {sections}**:label=「公司 · y年m月 · N条」,records 各自携带 __company/__ym;FpImportModal 既有 labelSections 确认屏(勾选/取消勾选)复用,零修改。
- **run() 的 Pick[] 分支**:逐段 公司名匹配 management_company、未匹配自动 companyApi.create(同利润表导入惯例) → ledgerApi.import(该公司, 该y, 该m, 剥 __ 前缀键的 rows) → 聚合 ImportResultDTO。
- **段流程的租户预检**:hub/LedgerView 把各段 records 平铺收集未登记租户名 → 一次 ResolveDialog(关联/新建/跳过) → skip 名字从各段过滤 → 再 run。
- v1 边界:段流程不做逐段覆盖确认(跨公司跨月成本高);后端列级 upsert + 结果 toast 已兜底。年月识别失败的 sheet 用表单年月并在 label 标注「(未识别,用当前)」。**已知限制**:整册中表头损坏解析失败的 sheet,在其他 sheet 有记录时被静默丢弃(真实册含汇总/非台账 sheet,逐个报错是噪音;权衡记录在案)。ResolveDialog 全跳过后不发空请求、不落 rejected 误导日志;两屏覆盖预检统一按去重租户家数计。

## 五(v3)、同 sheet 多月纵向堆叠拆段

**事故三(2025全年发生额、预算对比\台账测试.xlsx)**:单 sheet 873 行 = 12 个月纵向堆叠(每月一段「2025年X月园区费用明细表①」标题+3行表头+数据+合计)。matchByHeader 把「最后一个表头行」当唯一表头 → 只识别最后一段 22 行,前面 800+ 行**无告警静默丢弃**。

- **块切分(双保险,复审击穿后收紧)**:块起点 = 单元格命中 `/^\s*(\d{4})\s*年\s*(\d{1,2})\s*月.*明细表/`(**锚①以年月开头**,拦「费用参见2024年12月…明细表附页」类备注引用)**且该行非空格 ≤3**(**守卫②**,标题行只有 1~2 个非空,数据行远多于此,拦「2024年12月…明细表欠费」类以年月开头的备注)。首个起点之前若有行自成前导块(解析失败静默丢弃,同坏 sheet 权衡)。整 sheet 无起点 → 单块 = 现行为,零回归。
- **每块 = 虚拟 sheet**:parseLedgerSheet 原样复用——块首 3 行识别年月 → 结余动态标签按块年月(2月段表头「1月结余」),公司三级回退(标记列/sheet 名/ctx)。
- **汇总规则**:全工作簿(所有 sheet × 所有块)有记录的块总数 =1 → 平铺 records;≥2 → sections(label=公司 · y年m月)。
- **台账测试.xlsx 验收(按文件地面真相修正,复审②)**:实测该文件 = **6 公司块 × 2 个月**(2025年1月/10月 各 6 块:创显/B2/帮管好/一泽/积前/创燊高,公司名全部来自各块前置标记列)→ 12 段共 **789** 条;创显·2025年10月 = 107 条与事故二真实导入行数交叉印证。该文件同时实证了多公司自动识别。

## 八(v4)、段内同名租户行合并(2026-07-07 全域对账事故四)

真实数据击穿了"同文件同名两行 last-wins"边角:台账测试.xlsx B2·2025年1月「万众宿舍」为同名两行(调整行 balancePrev=-2,082.41 + 费用行 collected=935.71),last-wins 使调整行静默丢失(库两列各偏 +2,082.41,结余恰自抵)。真实台账本就"同租户多处物业分行记"。

- **前端合并**:parseLedgerSheet 产出后、段内按 tenantName 聚合——数值键逐列相加(同文件同段列集一致,空格=0,直接加),note 非空去重后以「；」拼接,__ 前缀键取首行。确认屏行数=合并后行数。
- 后端 last-wins 语义保留(兜底,不再被正常路径触发)。
- 验收:万众宿舍样例 → 单条 balancePrev=-2082.41、totalCollected=-1146.70;B2·1月段 balance_prev 合计 1,362,601.08、total_collected 合计 2,170,341.40 与文件一致。

## 九(v4)、垃圾租户行过滤(附表10 事故五)

附表10测试.xlsx 10月二期/三期块尾有**未标「合计」的合计行**(名为「202510二期」「202510三期」,数值=该段各列总和)与「0」伪租户行;isSubtotal 只认 /合计|小计|总计/,若直接上传该 xlsx,合计行按租户入库、段金额虚高一倍。

- matchByHeader 增可选 `opts.skipName?: (name)=>boolean`(第5参,缺省无过滤——**办公水电的关键列是"月份"、纯数字合法,绝不能全局过滤**)。
- 台账与附表10 通路传入统一谓词 `isGarbageTenantName`:纯数字(如「0」)或以 6 位数字开头(如「202510二期」)→ 跳过。
- 库内已有的 2 条 '0' 全零行(s10_record id 455/692)已手工清除(2026-07-07)。
- 验收:附表10 10月二期段解析 78 条(不含合计行/0行)、段合计 4,816,398.02(不再翻倍);办公水电月份行照常收。
