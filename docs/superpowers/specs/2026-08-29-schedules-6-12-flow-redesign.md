## §2 设计

### D1 · 功能门 → 左栏（附表6 / 7 / 8 / 11）

三个功能门的文案、结构、脚注**几乎逐字相同**，三个 `mode` ref 也逐字相同
（`PvView.vue:27` / `ChargingView.vue:45` / `ElecView.vue:27`）。
它出现的原因写在代码里（`api/elecCost.ts:5-6`：「与附表11 完全独立（功能门入口分叉，原功能零改动）」）——
**为了不动老屏，新屏借了老屏的导航项**。

两支是两个**相互独立的数据源**（后端分别是 `/api/pv` 与 `/api/pv-meter`），
不是同一份数据的两种看法 —— 那是**实体轴**，§7-2 原文要求它在左栏一键切换。

而且 `mode` 是**纯本地 ref，零记忆**：侧栏点击走 `tabs.openFresh()` → epoch 递增 →
组件全新重建 → **每次进来都要重答一遍这道选择题**。日常只用其中一支的人，每天白点若干次。

**改**：功能门退成左栏两项（常驻、高亮当前、记住上次）。
主区直接是该支自己的门。进屏点击数：**2 → 1（首次）/ 0（之后）**。

**连带必须一起修**（否则拆了会露出来）：
`NAV_SCOPE_PREFIX` 是 `Record<string, string>` —— **一个导航项只能登记一个前缀**。
功能门让 4 个导航项底下各多出一套锁根（`pv-meter:*` / `cp-meter:car|ebike:*` / `elec-cost:*`），
这几条**没有任何办法登记进去**。表现：有人正在改分栋抄表，侧栏圆点永远不亮。
`lockScopes.ts:89` 自己预言过这个失效模式，但护栏测试是**单向**的
（只断言「每个前缀对得上某个构造器」，不断言「每个构造器被某个前缀覆盖」），所以照样绿。

### D2 · 三个明细屏补选期门（C → D 形状）

复用出账链那套：`BookMonthMatrix` + `utils/matrixYears` 已现成，
`ChainMonthGate` 本身就是这个组合的一个特例，抽通用即可。
**期存 store 而不是屏内 ref** —— 理由与出账链同一条：`openFresh` 会重建组件，屏内 ref 每次被清掉。

删掉三处 `latestPeriodOf` snap。

**顺带修掉一个真 bug**：附表7/8 的 snap 用的是**不分车型**的月份全集 ——
电动车录到 2026-03、汽车只到 2025-12 时，汽车屏一进来就落在 2026-03，
满屏空、直接撞空态。矩阵按本车型 `hasData` 画格，这件事本身消失。

### D3 · 附表12 压成一层门（修我 P4 留下的退化用法）

现状是「年份门 + **单年一行**月矩阵」两层门，而 `BookMonthMatrix` 的设计意图写在组件头：
「全部年份纵排一屏——每年一行 12 张月卡」。**一层就够**。
退化的代价立刻可见：矩阵渲染的「＋ 补更早年份 / ＋ 添加次年」两个按钮
**是死的**（`SalaryView.vue:210` 只接了 `@pick`）——加年份的真入口在上一层年份门的虚线卡里。

**改**：去掉年份门，直接全年份矩阵 → 宽表。与月度台账、附表10 同形，一层门。
年份增删由矩阵自己的两个按钮接管（`utils/matrixYears` 的手工年机制，
取代 SchedYearGate 的 `fp-sched-years-salary`）。

代价写明：年卡上的「¥X万 / 全年实发·N 人次」年度指标会消失。
矩阵格子给的是「哪几个月有数据」，对**按月录入**的屏更有用。

### D4 · 年轴屏的 summary 分支：不加月门

附表6/7/8/11 的 summary 取数签名是 `records(year)`，后端一次返回整年，
记账月是表里的**一列**，tfoot 是年合计，期区/类别小计并排在同一张表里。

**判据很干脆：取数函数签名里有没有 month。**
有 → 必须有月门（附表10/12 与 C 的三屏）；没有 → 年门就够了。

给年轴屏加月门 = 把一张能横向比 12 个月的表拆成 12 次点击。§7-1 管的是账期粒度，
这类屏的粒度就是年，年份门已经是它完整的门。

### D5 · 不动：期区 / 运营商 / 电站 / 桩 / 电表 留在屏内当筛选

三条判据全部指向「同屏横向比较」：
① 同表分组小计（`PvTable.vue:81-97`，`phase='all'` 时三期并排、每期一个组头）；
② 切换不重新取数（纯客户端 `computed` filter，没有任何 API 带这个参数）；
③ 合计跨它们求和（`PvTable.vue:100` / `ChargingTable.vue:88`：`if (phase === 'all') return props.total`）。

搬进左栏 = 把「一屏横向比三期 + 一行跨期年合计」拆成各看各的，是 §7-2 的**误用**。

**唯一存疑的一根轴**：附表11 的费用类型（电量电费 / 基本电费）。
切换重新取数、列集完全不同、合计不跨类 —— 像两本册；
但年卡指标跨两类、清空本期导入跨两类，且锁键**明文禁止** type 进键
（`lockScopes.ts` 注释：「clearImported(y) 跨 energy+basic 两类 → type 不得进键」）。
这一根需要单独拍板，本稿不动它。

## §4 调研顺带查出、**不属于动线**的问题

按严重度排，都带证据，**建议单独立项**，不混进这次的 diff：

1. **明细屏三屏缺两个浮层**（high）。走 SchedHeader 的 summary 分支有
   `FPElevateDialog` + `FPTakeoverDrawer` + `FPEvictedDialog` 三件套；
   `PvMeterView` / `CpMeterView` / `ElecCostView` **只有第一个**。
   后果：别人占着锁时按钮显示「张三 编辑中」但并不 disabled，点下去 `acquire` 返回 false、
   **什么都不发生**（死按钮，无接管路径）；编辑中被接管时 `evictedBy` 被填上却无人渲染，
   用户被**静默踢出**编辑态。
2. **首载失败 = 永久转圈**（high，四屏同形）。四处 `onMounted` 均无 catch，
   失败后 overview 停在 null、模板落到 `.page-loading` 无限转圈、**无重试入口**。
   对照 `MeterView` 走的是 `FPLoadError`。
3. **门栈不进 URL**（high）。`mode`/`year`/`month`/`phase`/`type` 全是组件内 ref，
   四屏没有一处 `router.push`、没有一处读 `route.query`。
   后果：浏览器后退 = 整屏离开而不是退一层门；「附表12 2025年7月」不可分享、不可收藏、刷新即丢；
   **`ElecAnalysisView` 推的 `/elec-cost?view=cost&y&m` 深链落空**——elec 目录无人读 query。
4. **四屏不接 `onReactivated`**（medium）。切回页签不回拉主数据。
   接了它的是 alloc / bills / contracts / ledger / meters 五屏；pv / charging / elec / salary 零命中。
5. **受管年不回流**（medium，五屏同形）。年份门可自建 2000–2099 任意年，
   抽屉的年份 `Select` 却只吃 `overview.years` —— 在自建年里开抽屉，
   下拉显示「请选择」而底下的值是那一年。这是**共享脚手架的一个缺口**，不是五个独立 bug。
6. **在场头像口径不一致**（medium）。`SchedYearGate` 用 `presence.editorsUnder()` **不排除自己**，
   `BookMonthMatrix` 用 `.find(e => !e.self)` 排除。附表12 同时用了两个组件：
   年卡上叠着你自己的头像，月卡上不叠。
7. **抽屉默认月硬编码**（medium）。Pv/Charging/Elec 三个 Drawer 都是 `ref('1')`
   （Pv 的发生月还是 `'12'`）。而 `SalaryRecordDrawer` 是 `String(props.initMonth)` —— 因为它有月轴。
   **补上月门之后，这三处的默认月就有了正确来源**，是 D2/D3 的正面副产品。
8. **存后静默跳期**（low，四屏同形）。存一条别的年的记账，屏整个跳过去，无提示。
   不跳的话 refresh 之后看不到刚存的那条 —— 缺的只是一句 toast。

**两条不打算修但必须写下来的前提**（它们让「锁住这一期 = 别人改不了」这个前提不成立）：
- **后端完全不校验锁**。整个后端只有 `LockController` 消费 `LockService`，
  任何业务写端点都不检查调用者是否持锁。它是纯前端劝告锁。
- **导入中心是绕过全部门的第二道写口**。`IMPORT_TYPES` 里这八个屏的条目全在，
  磁贴点「上传」就地开同一个导入抽屉、走同一个 `runImport` 落库，
  而 `ImportCenterView` 全文没有 lock / scope 一个字 —— 没有功能门、没有年份门、没有月门、没有锁。
  期由文件内容推出来。
