## 0. 一句话

给 demo3 做一个**独立的产品展示站**（不在应用仓内的路由里）：像 Apple 产品页那样，一次滚动讲完「这套系统怎么把园区的账算清」，用真产品录屏做画面，用滚动驱动的转场把 11 个章节串成一条叙事。

### 设计判读（Design Read）

> 读作：面向**工业园区运营方与管理公司**（财务、运营主管、园区业主）的 B2B SaaS 产品展示页，语言是 **Apple 产品页式的章节滚动叙事**（深夜蓝开场，进入报表章翻为纸白），实现倾向 **原生 CSS + GSAP ScrollTrigger 钉住 / scrub**，视觉沿用产品自己的 Factory Park 设计系统（品牌蓝、三柱标志、Roboto Mono 数字）。

### 三档旋钮

| 旋钮 | 值 | 理由 |
|---|---|---|
| DESIGN_VARIANCE | 7 | Apple 式：大留白、单章单意、舞台居中或 55/45 分栏，不做实验性错版 |
| MOTION_INTENSITY | 7 | 用户点名要 Scroll Animations；六个章节钉住并 scrub，其余一次性上浮。全部尊重 `prefers-reduced-motion` |
| VISUAL_DENSITY | 3 | 每章一个标题、一段 ≤ 40 字的说明、一个画面。数据密度留给产品本身 |

## 2. 受众与叙事弧

### 2.1 两类买家，一条叙事

| | 小客户（一个园区、一家管理公司、两三个人） | 大客户（多期园区、多家管理公司、几十个人） |
|---|---|---|
| 主要顾虑 | Excel 用得挺好为什么换；没有 IT；怕算错 | 同时录账互相覆盖；各公司账要分又要合；谁改了什么查不到 |
| 页面上的回答 | 导入中心（§4.4）、公摊引擎「逐格全等」（§4.3）、底座「一条命令私有化」（§4.9） | 协作章（§4.7）、账簿报表「一套账多家公司」（§4.5）、RBAC 与审核（§4.7 / §4.8） |
| 专门一章 | §4.8「两个人的园区，和两百人的园区」左列 | 同章右列 |

叙事顺序按**数据在产品里流动的方向**排：先看见（总览）→ 怎么算出来（出账链、公摊引擎）→ 数据怎么进来（导入）→ 算完落到哪（账簿报表）→ 怎么用（经营分析）→ 多人怎么用（协作）→ 你是哪种园区（大小园区）→ 为什么可以托付（底座）→ 预约演示。

### 2.2 口号候选（D3）

1. **园区经营，算得清。**（原型采用；四字对四字，Apple 式短句）
2. 从抄表到催缴单，一条链算到底。（更具体，已用作出账链章标题）
3. 把整个园区，装进一本会算账的册子。

### 2.3 文案铁律

- 不出现破折号「——」与「—」；不用「·」做万能分隔符（每行最多一个）。
- 不写「赋能 / 无缝 / 一站式 / 颠覆」。动词要具体：算、导、拦、对上、留痕。
- 数字只用仓内坐实的（D8），示例数据明确标「示例」。
- 每章一个标题（≤ 12 字）+ 一段说明（≤ 40 字）。

## 3. 视觉系统

沿用产品 `tokens.css`，只做展示站需要的放大与深色版。

| 角色 | 深色阶段（首屏至导入章） | 浅色阶段（报表章起） | 来源 |
|---|---|---|---|
| 页面底 | `#0B0F16`（偏蓝夜黑，不用纯黑） | `#F5F7FA`（偏蓝纸白，不用米黄） | 新增 |
| 卡 / 纸 / 舞台 | `#121826` | `#FFFFFF` | 新增 |
| 主文 / 次文 / 弱文 | `#F2F5F9` / 68% / 44% | `#14181F` / 68% / 46% | 对应 ink-900/700/500 |
| 强调色（唯一） | `#4C98FD` brand-blue；深 `#1F5FBF`；浅 `#A8CDF0` | 同 | `tokens.css` `--brand-*` |
| CTA 按钮底 | `#2668CC`（白字对比 5.3:1，两种底色下都过 AA） | 同 | 新增 |
| 语义色 | 仅异常格用 `--hue-orange` 系 `#E08A2E`，不算强调色 | 同 | `tokens.css` |

- **字阶**：display `clamp(46px, 7.4vw, 108px)` / 900 / 行高 1.02 / 字距 -0.035em；章标题 `clamp(34px, 4.6vw, 64px)`；说明 `clamp(17px, 1.35vw, 21px)` 行高 1.6；数字 Roboto Mono 500，`tabular-nums`。大字负字距、小字正字距，不用一个 letter-spacing 走到底。
- **圆角规则**（全站一致）：舞台 / 纸 / Bento 格 22px；内嵌素材 14px；按钮、标签、公司条 胶囊。
- **材质**：顶栏与批注卡用半透明 + `backdrop-filter: blur(20px) saturate(160%)`，内容从下面滑过；`prefers-reduced-transparency` 时回落为实底。
- **阴影**：深色阶段 `rgba(0,0,0,.5)`，浅色阶段 `rgba(20,40,80,.16)`（带底色色相，不用纯黑投影）。
- **图标**：沿用产品的 lucide（`gauge / siren / calendar-clock / scale-3d / bell-ring / sun / plug`），描边 1.75，与应用内导航同形。
- **标志**：三柱标志（`factory-park-mark.svg`）在首屏放大成「三栋楼」做载入动画，顶栏与页脚用 22px 版。

## 4. 页面结构与逐章动效

滚动距离用「屏高」计（1 屏高 = 100vh）。「钉住」= GSAP `ScrollTrigger pin: true, start: "top top"`，`scrub` 值为跟手平滑秒数。所有动效只动 `transform / opacity / clip-path`（配色翻转动 CSS 变量，见 §4.5）。

### 4.0 顶栏（常驻）

60px 高，半透明材质，左标志 + 产品名，中间 7 个章节锚点（当前章下划线高亮，`ScrollTrigger` 按章节中线切换），右「预约演示」。桌面端单行，< 900px 隐藏中间锚点。

### 4.1 首屏「园区经营，算得清。」

| | |
|---|---|
| 版式 | 左：放大的三柱标志（150px 高）；右：两行 display 标题 + 一段说明 + 两个按钮（「预约演示」主，「看它怎么算」幽灵，锚到出账链）。屏幕舞台在下方露出上半部，邀请下滚 |
| 载入 | 三根柱从底部升起（`scaleY .12→1`，错峰 0.12s，expo.out 1.1s）；标题两行 `y 30→0` 上浮；说明与按钮再 0.1s 错峰；舞台 `y 90→0, scale .965→1` |

## 5. 相邻章节转场总表

| 从 → 到 | 手法 | 为什么这样接 |
|---|---|---|
| 首屏 → 总览 | 首屏文案上移淡出，舞台留在原位，总览章的舞台在同一水平位置钉住 | 视觉上「同一块屏幕」被接走，不重新聚焦 |
| 总览 → 出账链 | 解钉正常滚动，出账链标题正常出现，横滚区再钉 | 两个钉住之间留一段正常滚动，避免连续劫持 |
| 出账链 → 公摊引擎 | 横滚末步「催缴单」到位即解钉；公摊章钉住，舞台在右 | 横向结束在最右，下一章重心也在右，方向连续 |
| 公摊引擎 → 导入 | 揩开完成解钉；导入章居中构图 | 从「结果对得上」转到「数据怎么进来」，构图从偏右回到居中，节奏一松 |
| 导入 → 账簿报表 | **整站配色深 → 浅**，scrub 70vh | 产品从「算」进入「账册纸面」，纸白呼应报表；这是全页唯一一次翻转 |
| 账簿报表 → 经营分析 | 第三张纸滚出，Bento 错峰上浮 | 纸张叠放（竖向）接 Bento（平铺），版式家族切换 |
| 经营分析 → 协作 | 普通滚动进入钉住 | 单窗到双窗，主题从「看」到「一起改」 |
| 协作 → 大小园区 → 底座 → 预约 | 全部普通滚动 + 一次性上浮 | 后三章是说服与收口，不再劫持滚动，让人能快速读完并点按钮 |

版式家族清点（不重复）：分栏舞台（总览）/ 横向平移（出账链）/ 揩开对比（公摊）/ 飞入映射（导入）/ 纸张叠放（报表）/ Bento（分析）/ 双窗（协作）/ 两列问答（大小园区）/ 四格数字（底座）/ 居中收口（预约）。

## 7. 技术方案

| 项 | 取法 | 理由 |
|---|---|---|
| 构建 | Vite 静态站（纯 HTML + CSS + 少量 JS，或 Vue 3 单文件组件），独立目录 `site/`，独立部署（Caddy 多加一个 host 块） | 与团队现有工具链一致；不进产品包体 |
| 动效 | **GSAP 3 + ScrollTrigger**（钉住 / scrub / 横移 / 配色翻转）；一次性上浮用 `ScrollTrigger.batch` 或 CSS `animation-timeline: view()` | 六个章节要 pin + scrub，这是 GSAP 的主场；不与其他动效库混用 |
| 禁止 | `window.addEventListener('scroll')`、在 React/Vue 状态里存滚动进度、动 `top/left/width/height` | 逐帧重排；只动 transform / opacity / clip-path |
| 录屏 | `<video muted autoplay loop playsinline>`，WebM 优先 MP4 兜底，`poster` 用首帧 WebP；进入视口才 `play()`，离开 `pause()` | 首屏 LCP 靠 poster，不靠视频 |
| 配色翻转 | GSAP 直接 scrub `body` 上的 CSS 变量；全站颜色只走变量 | 一处驱动，任何章节不写死颜色 |
| 减少动态效果 | `gsap.matchMedia()` 三档：桌面 / 移动 / `prefers-reduced-motion`。reduce 档：不钉住、不横移、不飞入，所有终态直接可读；配色翻转改 400ms 直切 | 非可选项 |
| 移动端（< 900px） | 全部不钉住；出账链改原生横向 scroll-snap；Bento 单列；双窗上下排 | 小屏劫持滚动体验差，且 Apple 移动端也大量降级 |
| 字体 | Google Fonts 只拉 Noto Sans SC 500/700/900 + Roboto Mono 400/500，`display=swap`；正文系统字体 | 中文标题字重要够，正文不额外下载 |
| 性能预算 | LCP < 2.5s（poster 预加载）、CLS < 0.1（所有舞台定死 aspect-ratio）、首包 JS < 60KB（GSAP core + ScrollTrigger 约 45KB gzip） | |
| 可访问性 | 顶栏与按钮键盘可达、可见焦点环；录屏有 `aria-label`；批注卡只在设计稿期存在，上线删除 | |
| SEO | 单页，每章 `<section id>`，标题层级 h1 → h2 → h3；OG 图用首屏截图 | |

## 8. 不做什么

- 不做定价页、不做自助注册、不做客户 logo 墙（D5 / D9）。
- 不做插画、不做 3D、不做粒子；画面全部是真产品。
- 不做双语；不做暗 / 亮手动开关（配色由叙事决定，不由用户切）。
- 不在产品仓 `frontend/` 里加路由或依赖。

## 9. 验收标准（实施期）

1. 桌面 1440 宽：六个钉住章节的 `start` 都是 `top top`，钉住期间无跳动（`anticipatePin: 1`），解钉后无空白。
2. 从底部往回滚到导入章：配色回到深色（翻转可逆）。
3. 系统开「减少动态效果」：页面无任何钉住与位移，全部文字与终态可读，配色翻转为直切。
4. 390 宽手机：无横向溢出；出账链可横向拨动并吸附；所有素材位 aspect-ratio 定死，CLS < 0.1。
5. 视觉字符串扫描：全站 0 个「—」「——」；每行「·」≤ 1；眉标 ≤ 4 个（现 3 个）。
6. 「预约演示」三处文案完全一致；无第二个同意图按钮。
7. Lighthouse 桌面：Performance ≥ 90，Accessibility ≥ 95。
