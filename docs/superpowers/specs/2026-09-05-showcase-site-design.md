## 0. 一句话

给 demo3 做一个**独立的产品展示站**：像 Apple 产品页那样一次滚动讲完两件事：**每月出账不再手填**（五道工序算到每户催缴单），**数据录完分析就有了**（20 屏经营分析自动派生）。用真产品录屏做画面，用滚动驱动的转场把 15 个章节串成一条叙事，全程黑底。

### 设计判读（Design Read）

> 读作：面向**工业园区运营方与管理公司**（财务、运营主管、园区业主）的 B2B SaaS 产品展示页，语言是 **Apple 产品页式的章节滚动叙事**（全程黑底），视觉遵循 **Apple 的克制**：系统字体 + Semibold 承担层级，黑色单一页底，格不描边不投影，强调色（香槟金）只给按钮、链接、进行中状态、图表尾点；实现倾向 **原生 CSS + GSAP ScrollTrigger 钉住 / scrub**；标志沿用产品 2026-09-18 起的新标志（两片刃），站上改两档灰。

### 三档旋钮

| 旋钮 | 值 | 理由 |
|---|---|---|
| DESIGN_VARIANCE | 7 | Apple 式：大留白、单章单意、居中标题、舞台居中或 55/45 分栏 |
| MOTION_INTENSITY | 7 | 用户点名要 Scroll Animations；两个卖点章钉住 scrub 最重，其余轻。全部尊重 `prefers-reduced-motion` |
| VISUAL_DENSITY | 3 | 每章一个标题、一段 ≤ 40 字的导语、一个画面 |

## 2. 受众与叙事弧

### 2.1 两类买家，一条叙事

| | 小客户（一个园区、一家管理公司、两三个人） | 大客户（多期园区、多家管理公司、几十个人） |
|---|---|---|
| 主要顾虑 | Excel 用得挺好为什么换；没有 IT；怕算错 | 同时录账互相覆盖；各公司账要分又要合；谁改了什么查不到 |
| 页面上的回答 | 以前长这样 + 催缴单（§4.2 / §4.4）、公摊引擎（§4.9）、底座（§4.15） | 协作（§4.11）、账簿报表（§4.10）、协作章的 RBAC 与审核；两边都看手机章（§4.12） |
| 专门一章 | §4.14「大小园区」左面板 | 同章右面板 |

### 2.2 叙事顺序与重量

前三章只做一件事：让会计在第 1 章认出自己每月手填的那份 Excel（152 个 sheet / 209 个通知单块 / 920 条费项行），第 2 章看见五道工序怎么接成一条链，第 3 章在同一个 152 上看到「核对一遍再发」。卖点 a（省时出账）在全页前 40% 起落完成；横滚的终点直接放大成催缴单舞台，所以这一段是全页唯一一次连续劫持滚动。

第 4 章转轴用一句「没有一格是填进去的」和一根 1px 引线把读者从产物一（催缴单）牵到产物二（经营分析），同时隔开两个重章。第 5 章钉住看四个维度，接着用一块宽格说「不替你下结论」（v1.3 新增：屏上不编数字这件事，产品把它做成了机器门禁，放在两个分析章之间），再 Bento 平铺九个专题。

后七章（公摊全等 / 账簿 / 协作 / 手机 / 每天打开的样子 / 大小园区 / 底座）全部不钉住，按买家顾虑的自然顺序排：怕算错、账要分又要合、多人会不会打架、出门在外能不能看、天天用着顺不顺手、我是哪种园区、能不能托付。公摊放在账簿前，因为它回答催缴单「算对没有」，账簿回答「对得上没有」。手机章与「每天打开的样子」是 v1.3 新增的一对：前者讲同一套账在三种宽度下怎么重排，后者把 2026-09 新做的外壳（页签与首页、深色、更新记录、控件）凑成 2×2。尾屏回扣第 1 章的通知单，只留一个动作。

**重量分配**（屏高）：出账链 1.2 轻钉横滚（六卡改五卡，横移距离变短）→ 催缴单 2.6 钉住换画面（连续约 3.8 屏）；经营分析 2.6 钉住换画面；其余全部 sticky、经过式 scrub 或一次性。全站只在底座章计数一次数字。三个新章都不钉住：不替你下结论 0.5 屏、手机 1 屏、每天打开的样子 1 屏。

### 2.3 口号候选（D3）

1. **每月出账，不再手填。**（原型采用；把会计的活写进第一行）
2. 五道工序，算到催缴单。（已用作出账链章标题）
3. 每月，自己长出两样东西。（评审第二案首屏，强调两个产物并列）

### 2.4 文案铁律

- 不出现破折号「——」与「—」；不用「·」做万能分隔符（每行最多一个）。
- 不写「赋能 / 无缝 / 一站式 / 颠覆 / 极致 / 智慧 / 全方位」。动词要具体：算、派生、拦、对上、留痕。
- 数字只用仓内坐实的（D8），示例数据明确标「示例」。事实清单外的产品细节一律不写（如「按月锁定」「拓扑序」「下游全部重算」「审核员」「格式照旧」「每次提交都跑」「30 分钟」）。
- 每章一个标题（≤ 12 字）+ 一段导语（≤ 40 字）。产品内屏名照抄：**经营驾驶舱**（不是「驾驭舱」）、**租户对标**、**异常提醒中心**。
- v1.3 加两条：分支上还没合进 master 的功能不许写上屏（写进批注与 §10 等合并）；2024 年的盘点数必须带年月（152 / 209 / 920 是 2024-03，51 池是 2024-02）。
- 眉标全站 3 枚：首屏「灵睿 LinkSight」、「催缴单」、「经营分析」。

## 3. 视觉系统（v1.2：黑底全程 + 香槟表盘）

原则一句话：**层级靠字重、字号、底色对比与留白，不靠颜色、描边、投影和字体切换。** 全站只有两种「亮」：白字与香槟金按钮。金只出现在按钮、链接、进行中的锁、图表尾点四处；异常色只出现在图表尾点（带 ≤ 12 字标注），图标一律次级灰。

| 角色 | 值 | 对比 / 规则 |
|---|---|---|
| 页面底 | `#000000` | 全程，不翻色（D2） |
| 格 / 纸 / 舞台 | `#1D1D1F` | 不描边、不投影 |
| 次级格（内嵌画面底、滑块、节点未点亮） | `#2C2C2E` | |
| 主文 / 次文 / 三级文 | `#F5F5F7` / `#A1A1A6` / `#86868B` | 三级文从 `#6E6E73` 提到 `#86868B`：12px 脚注对黑 5.8:1 过 AA（原 4.1:1 不过）；`#6E6E73` 只用于标志矮柱。**三级灰只落黑底与格色（对格 4.65:1），不落次级格（3.85:1 不过 AA）**：压次级格的小字（角标）用次级灰 |
| 发丝线 | `rgba(255,255,255,.14)` | 顶栏底边、问答分隔、出账链底线；**不许改成金色** |
| 控件边界 | `rgba(255,255,255,.36)` | 锁按钮描边（WCAG 1.4.11 非文字 ≥ 3:1） |
| 主按钮 | 底 `#C9B790`，字 `#1D1D1F` 17px Regular | 8.5:1（AAA）。HSL 41 / 35 / 68：饱和度压到 35，远看暖灰，近看才是金。亮度 l68 落在主文（l96）与次文（l64）之间，插进文字层级不打架。锁值允差：色相 ±3，饱和 ≤ 40 |
| 主按钮悬停 | `#D4C3A0` | 只变亮不变暗，与链接色排成一条明度梯 |
| 链接 | `#D6C7A1` | 对 `#000` 12.5:1，对格 10.1:1。独立文字链必带 ›，行内链接常驻下划线（对次文 `#A1A1A6` 只 1.5:1，链接不能只靠颜色被认出） |
| 进行中 | `= 主按钮`，不另设令牌 | 出账链当前节点实心；锁按钮「编辑中」1px 描边 + 文字；「请求接管」实底 |
| 图表 | 主线 `#A1A1A6`，正常带 8% 白，常态尾点 `#C9B790` r4，异常尾点 `#FF6E57` r5 + 标注 | 一张图只有一个彩色点；常态与异常靠形状加文字区分（两色亮度只差 1.4:1，红绿色弱下会混） |
| 异常语义色 | `#FF6E57` | 对格 6.1:1。只做图表异常尾点与 ≤ 12 字标注，每屏最多两处，不做底色，不上图标 |
| 标志 | 站上用产品新标志的两片刃改两档灰：主刃 `#F5F5F7`、次刃 `#6E6E73` | 图形取 `frontend/src/assets/brand/logo.svg`（产品里是 `#38b6ff` 与 `#5271ff`，站上不动它）。旧的三柱 `factory-park-mark.svg` 已在 2026-09-18 删除。标志不上金，否则成第五处强调色，且与导航右侧的金色按钮抢眼 |
| 投影 | **无** | 全站零投影，叠放深度只靠 scale / opacity / y |

- **字阶**（全部系统字体，Semibold 600 承担层级）：首屏 `clamp(44px, 6vw, 80px)` / 1.06 / 字距 -0.012em；章标题 `clamp(32px, 4.1vw, 56px)` / 1.08 / -0.008em；眉标 21px / 600 / 次级灰；导语 21px / 1.42 / 400 / 次级灰；正文 17px / 1.47；说明 14px；脚注 12px。数字用同一字体 + `tabular-nums`，不用等宽字体。
- **圆角规则**（全站一致）：格 / 纸 / 舞台 28px；内嵌画面 18px；按钮、标签、分段控件 胶囊（980px）。
- **材质**：只有局部导航用半透明材质（页底色 78% + `blur(20px) saturate(180%)` + 1px 发丝线）；`prefers-reduced-transparency` 时回落为实底。批注卡是设计稿期专用。
- **图标**：沿用产品的 lucide，正文共 16 枚（`siren / calendar-clock / scale-3d / bell-ring / sun / coins / layers / target / zap / plug / check / chevron-right` 加 v1.3 三个新章的 `app-window / moon / sparkles / keyboard`），24px，描边 1.5，次级灰，不上金、不上异常色。`gauge` 只在组件表的样例里出现，正文没用。
- **动效克制**：滚动结构保留（用户要求），但零发光、零光环、零渐变纹理：链路线与揩痕都是 1px 白线，节点点亮只换底色。缓动统一 `power2.out / power3.out`，不用 expo 与回弹。

## 7. 技术方案

| 项 | 取法 | 理由 |
|---|---|---|
| 构建 | **零构建**：`site/` 下一个 `index.html` + 一份 `styles.css` + 一份 `main.js` + `vendor/`（gsap 两个文件）+ `assets/`（录屏与截图）。托管方的 build command 留空、输出目录直接指向 `site/` | 全站就一页，Vite 能给的只有压缩与指纹，换来的是 node_modules、锁文件与一条会坏的构建链。一页站零构建最省，改一行推一次就生效 |
| 动效 | **GSAP 3 + ScrollTrigger**（钉住 / scrub / 横移 / sticky 叠放的退后）；一次性上浮用 `ScrollTrigger.batch`。**文件自带在 `site/vendor/`，不走 CDN** | 两个卖点章要 pin + scrub，这是 GSAP 的主场；自带是因为对外站不该有第三方请求（隐私与可用性），也省掉 SRI 那一套 |
| 禁止 | `window.addEventListener('scroll')`、在框架状态里存滚动进度、动 `top/left/width/height` | 逐帧重排；只动 transform / opacity / clip-path |
| 录屏 | `<video muted autoplay loop playsinline>`，WebM 优先 MP4 兜底，`poster` 首帧 WebP；进入视口才 `play()`，离开 `pause()` | 首屏 LCP 靠 poster |
| 配色 | 单一黑色主题；全站颜色只走 CSS 变量 | 换强调色只改一处 |
| 减少动态效果 | `gsap.matchMedia()` 三档：桌面 / 移动 / `prefers-reduced-motion`。reduce 档：不钉住、不横移，所有终态直接可读 | 非可选项 |
| 移动端（< 900px） | 全部不钉住；出账链改原生横向 scroll-snap；Bento 两列；双窗上下排；设备并排改竖排且关掉 `flex-grow`；分段控件回到普通 tab | 小屏劫持滚动体验差。**注意**：这个 900 是展示站自己的一档，与产品的 600 / 960 / 1280 四档不是一回事；手机章屏上写的档位必须是产品那四个 |
| 字体 | **零字体下载**：系统栈 | Apple 自己就用系统字体；LCP 不等字体 |
| 性能预算 | LCP < 2.5s（poster 预加载）、CLS < 0.1（所有舞台定死 aspect-ratio）、首包 JS < 60KB | |
| 可访问性 | 顶栏与按钮键盘可达、可见焦点环（香槟 2px）；录屏有 `aria-label`；分段控件 `role=tablist`；批注卡与组件表只在设计稿期存在 | |
| 部署 | 静态托管（Cloudflare Pages 一类）：连仓库、root 指 `site/`、build command 留空。单文件别超平台上限（Pages 是 25 MiB/文件，录屏远低于此）。`_headers` 给 `assets/` 长缓存、给 HTML 不缓存 | 用户 2026-09-20 定 |
| 后端 | **没有**。站上没有表单、没有接口、没有统计脚本（要加统计另议，见 §10 第 17 条） | 零后端才能零构建、零运维 |
| SEO | 单页，每章 `<section id>`，标题层级 h1 → h2 → h3；OG 图用首屏截图；`favicon` 用产品新标志（两档灰版） | |

## 8. 不做什么

- 不做定价页、不做自助注册、不做客户 logo 墙（D5 / D9）。
- 不做插画、不做 3D、不做粒子；画面全部是真产品。
- 不做双语；**站上**不做暗 / 亮手动开关（全程黑）。产品自己有深色外观，那是产品的事，站不跟。
- 不复刻产品的语义色：产品里「正在编辑」是橙环、异常是红，站上只用香槟与 `#FF6E57`，差异写进素材说明，不反过来改产品。
- 不在产品仓 `frontend/` 里加路由或依赖；不为展示站改产品令牌（D13）。
- 站上不做表单、不做登录、不做后端接口；不引第三方脚本（含统计、客服、字体）。
- 不写事实清单外的数字与产品细节。

## 9. 验收标准（实施期）

1. 桌面 1440 宽：三个钉住章节（出账链 / 催缴单 / 经营分析）的 `start` 都是 `top top`，钉住期间无跳动（`anticipatePin: 1`），解钉后无空白。
2. 全程黑底：任何滚动位置 `body` 背景都是 #000，无翻色。
3. 系统开「减少动态效果」：页面无任何钉住与位移，全部文字与终态可读。
4. 390 宽手机：无横向溢出；出账链可横向拨动并吸附；所有素材位 aspect-ratio 定死，CLS < 0.1。
5. 视觉字符串扫描：全站 0 个「—」「——」；每行「·」≤ 1；眉标 ≤ 3 枚；0 个「驾驭舱」（产品屏名是「驾驶舱」）；0 个「园区管理系统」（产品名是「灵睿 LinkSight」）；0 个「六步」「三方勾稽」「19 屏」。
6. 「预约演示」三处文案完全一致；无第二个同意图按钮。
7. 强调色审计：香槟只出现在主按钮、文字链、出账链当前节点、锁按钮进行中、图表常态尾点；标题、数字、发丝线、图标、公司条上 0 处金；全站 0 处渐变；一屏之内只有一块 ≥ 44px 的亮色实心胶囊。
8. 链接审计：每个独立文字链带 ›；每个行内链接有下划线。
9. 异常色审计：只出现在图表尾点与 ≤ 12 字标注；每处都与文字或图标同现；0 处底色。
10. 双设备过稿：一台会议室投影 + 一台普通办公显示器（开 Windows 夜间模式）各看一遍，香槟未漂成黄铜。
11. Lighthouse 桌面：Performance ≥ 90，Accessibility ≥ 95。
12. 手机章的三块画面底边对齐，宽度比 = 1440 : 768 : 390（±2px），竖排档下没有被 `flex-grow` 拉变形。
13. 屏上不出现还没合进 master 的功能（读数句、窄栏重画、44 触点）；每处产品事实都能在 §4 的「事实来源」里找到文件。

## 11. 与原型的对应

原型 `../运维文档/设计稿/未实现/产品展示站-2026-09-05/prototype.html` 已实现 §4 全部动效与转场（GSAP 3.12.5 via cdnjs），用「素材位」占住 §6 全部位置并标注规格；右下角「设计批注」开关显示 / 隐藏逐章说明与末尾的「UI 组件表」（§3.1 的实物）。它是设计稿，不是站点代码：实施时按 §7 重建，不直接复用。**文案以本 spec §4 为准，原型只是其实物**；两者不一致时改原型。v1.3 的三个新章（§4.7 / §4.12 / §4.13）在原型里都已经画出来并渲染核对过（1440 与 390 两档各截图看过一遍）。

实施要点（v1.2 对抗复查坐实，写进代码即可）：钉住的 ScrollTrigger 必须先于其余触发器创建（否则后者按无钉住的位置算，会提前几千像素触发）；减少动态效果与无脚本两档的协作双窗直接呈现播放终态；经营分析分段控件在静态档要能当普通 tab 切换四张画面；光伏 SVG 的 viewBox 跟随渲染尺寸。

v1.3 新增三条：① 设备并排用 `flex: <宽度> 1 0` 按真实像素给比例，但竖排档必须 `flex: 0 0 auto`，否则 `flex-grow` 去分配高度、把画面拉变形；② 底座那个带千分位的数字要用 `toLocaleString`，计数器读回初值时先 `replace(/\D/g,'')`；③ 协作双窗的「正在编辑」环在两扇窗里挂的元素不同（左窗是自己 `.me`，右窗是对方 `.other`），静态档两处都要给。
