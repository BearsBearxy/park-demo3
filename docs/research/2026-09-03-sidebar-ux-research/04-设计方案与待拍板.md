### 2.2 面板高度（预算 500px）

真实可用高：1366×768 办公机浏览器内视口 ≈ 620（PV-ANALYSIS-SPEC §6.1 同口径）→ 导航卡 594 → 面板内容区 562 → 减头 24 / 间隙 28 / 分割线 1 = **≈509px**。三位评审按 768 全高算出的 660 是错的。常量 `PANEL_BUDGET = 500` 写在 `navHeight.spec` 一处。

| 层 | 默认态 | 最坏单组展开 |
|---|---|---|
| 数据中心 | 448（出账展开） | 448（两个 5 项组尺寸相同） |
| 账簿与报表 | 356 | 356 |
| 经营分析 | 300 | 480 |

算式：行 34 · 组内 2 · 组标题 30（18 行高 + 6×2）· 组间 16（`SidebarNav.vue` 实测常量）。
用户手动多开一组 → 超预算，面板滚动 + 新增 `scrollIntoView` 当前项。

### 2.3 折叠语义（C8 复核后改）

- 带标题组标题行变 button，30px 不变，chevron `absolute right:12`（DESIGN-FIDELITY §2.3 需补修订记录）。
- 路由变化：**只展开**含当前屏的组，**不收回**用户手动展开的组（会话内记忆，内存态，不落盘；换层清空）。评审原稿「路由变化即收回」对专员跨组是净加点击，已改。
- 折叠组标题行右侧聚合子项在场点（任一子项有人编辑 → 同款 6px 橙点）。
- 删除 `SidebarNav.vue:223-320` 不可达的折叠轨道/flyout 分支（约 100 行）抵体积。

### 2.5 导航语义

| 入口 | 现状 | 方案 |
|---|---|---|
| 侧栏项 / 手机抽屉目录项 | `openFresh`（重建） | `open`（恢复现场）；当前项 no-op；Shift+点击 = `openFresh` |
| 轨层钮 / 手机底栏 | 点当前层也跳走 | 当前层 no-op；换层 `openFresh(home)` |
| 首页 / 清单行 | 裸 push，不带期 | `period.pick(y,m)` 显式选月（C7 复核：不给 `adoptYm` 加 force）+ `periodLink`；链屏处于编辑态时先确认「切到 X 会退出 Y 的编辑」 |
| 报表中心 / 期间条 / 分析深链 | 各自约定；KeepAlive 命中时 query 被丢 | 统一 `nav/deepLink.ts`（`periodLink` / `parsePeriod` 兼容 p、ym、y&m）+ `useDeepPeriod`（onMounted + 复用 `composables/onReactivated.ts`，按 fullPath 去重） |
| 分析深链 9 处 `pin:true` | 页签无限堆 | pin 规则：来源屏在 preview 槽 → 目标 pin（`LedgerView.gotoTenants` 规则通用化） |
| preview 被顶替 | 静默 | 仅当被顶屏处于**编辑态**时出 4s toast「已被替换 — [固定它]」（无条件出会变噪音） |
| KeepAlive | `max=10` | 提到 16（专员月内 15 屏，否则「恢复现场」时灵时不灵） |

### 2.6 外壳其它

- 页签标题：`屏名 · 期 · 公司`。零位移做法：页签**定宽**（Chrome 式，148px，ellipsis + title 全文），改名不改宽。
- 顶栏上下文 chip：面包屑后**常驻预留位**（定宽 132px，无期显「—」），不凭空出现。写入点含报表层屏内换期。
- 收藏 ★ → `tabs.pin(当前页)`；主题 ☀ 钮删；搜索文案改「搜索页面 / 分组（Ctrl K）」；命令面板可搜分组名。
- 在场点：文案带期（`lockScopes.scopePeriod`）；`role=img` + `aria-label` + 点按弹 Popover。
- 账号菜单角色行：按 permissions/navLayers **派生**（`auth.role` 是 V32 遗留列，新建用户恒 'admin'，C3 复核坐实）；真名待后端 `LoginResp` 加 `roleNames`（同时修 `PresenceService` 的同一遗留列）。
- 落地页：零 `:edit` 且含 analysis 层 → `/cockpit`（总经理 / 只读）；`tabs.baseHome()` 随落地页（否则总经理基底页签指向数据层）。

## §8 审核机制（2026-09-03 追加需求）

**需求原话**：加一个审核员角色；被他审核完的已录表格（出账、附表这些）不能轻易修改。
**已拍板**：粒度 = 一张表 × 一个月；已审核 = 只读，只有审核员能撤销。

### 8.1 审核单元与键

复用清单行的口径，一行一个审核键；键的写法与编辑锁 scope 同一风格，但**独立于锁**（锁是「谁在改」，审核是「能不能改」）。

| 清单行 | 审核键 | 备注 |
|---|---|---|
| 计费参数 | `params:YYYY-MM` | 审的是该月生效的参数快照 |
| 园区抄表 | `meters:YYYY-MM` | 抄表屏按年锁，但审核按月：守卫按读数所属月判 |
| 公共电核算 | `alloc:YYYY-MM` | `params/recalc` 也受它守 |
| 楼栋损耗 | `alloc-loss:YYYY-MM` | |
| 催缴单 | `bill-notices:YYYY-MM` | 与现有 `draft→confirmed→exported`（主管业务确认）是两条轴，都保留 |
| 月度台账 | `ledger:{companyId}:YYYY-MM` | 每公司一键 |
| 附表10 | `s10:{phase}:YYYY-MM` | 每期区一键 |
| 附表12 | `salary:YYYY-MM` | |
| 办公·三期水电 | `utilities:{office\|phase3}:YYYY-MM` | 附13 / 附14 各一键 |
| 附表6/7/8/11 | `pv:YYYY-MM` · `charging-car:YYYY-MM` · `charging-ebike:YYYY-MM` · `elec-cost:YYYY-MM` | 年表屏内按月份行上锁（D18） |

收入核对与报表层本轮不进审核（报表是派生输出，等清单跑顺再议）。

### 8.2 状态机（每个键）

```
录入中 ──交审(录入方,需该表 edit 权)──▶ 待审核 ──通过(审核员)──▶ 已审核（只读）
   ▲                                      │                        │
   └────────────退回(审核员+理由)───────────┘                        │
   ◀──────────────────────撤销审核(审核员+理由)──────────────────────┘
```

- 「录入中」是派生态（有数据即算），不落库；其余三态落 `review_state`。
- **待审核也锁**（D17）：审核员看的是定稿，不是移动靶。
- 通过前置（D19 的另一半）：公共电核算通过需 参数 + 抄表 已审核；催缴单通过需 公摊 + 损耗 已审核。清单行显 padlock 与原因。
- 撤销前置（D19）：下游有已审核时上游不能撤销，提示「先撤销 公共电核算 / 催缴单 的审核」。
- 整月「本月锁账」行 = 该月全部键已审核，**派生**（D20），月格显 ✓ 锁标。

### 8.3 权限与角色

- 第 15 个权限点 `review:approve`：通过 / 退回 / 撤销审核。交审不设独立权限点，谁能编辑该表谁就能交审。
- 新预置角色 **审核员**（`reviewer`，`builtin=1`）：只有 `review:approve`；`nav_layers` 三层全开（要看数据）；零 `:edit`、无 `elevate:request`（审核员不能自己录自己审）。
- 六个既有角色不变；财务主管默认不带审核权（D16），客户可在角色权限屏勾。
- 后端强制：`review:approve` 挂四个审核端点；已审核/待审核态由 **写路径守卫** 拦，与谁有 `:edit` 无关（主管的接管锁也拦不过）。

### 8.4 后端

| 项 | 内容 |
|---|---|
| 表 | `review_state(key PK, status, submitted_by/at, reviewed_by/at, reason)`；`review_log(id, key, action, actor, at, reason)` 追加写 |
| 端点 | `POST /api/review/{key}/submit`（该表 edit 权）、`/approve` `/return` `/withdraw`（`review:approve`）；`GET /api/review?period=YYYY-MM` 一次返回全月所有键（清单用） |
| 守卫 | `ReviewGuard.assertEditable(kind, period, scope)`：写入前查 `review_state`，`submitted`/`approved` 一律 423，消息含「谁、何时审核、撤销后才能改」。挂在 §5.2 写端点表里所有碰期间数据的 service（含导入、`params/recalc`、复制上月、系数簿生效月） |
| 覆盖率测试 | **从源码推导**写路径清单（扫 §5.2 映射表的 controller 方法），逐个断言调用了守卫；不用白名单（stage-review 新1 的教训） |
| 日志 | `review_log` 进「操作日志」时间线，作第 4 张来源表（RBAC-SPEC §7 表补一行） |

### 8.5 前端

- **编辑模式闸**：`useEditMode.toggle()` 在权限检查之后、占锁之前查审核态；`submitted`/`approved` 时不进，按钮位渲染同尺寸禁用药丸「已审核 · 李审 03-05」（零位移），tooltip 写「撤销审核需审核员」。`elevate:request` 弹窗也不出现——提权解决的是权限不齐，不是审核锁。
- **屏内状态**：顶栏上下文 chip 加审核态；矩阵月格全审 ✓。
- **清单行**：状态列 未交审 / 待审核 / 已审核（人 + 日期）/ 已退回（理由）；行动作按角色：录入方「交审」；审核员「通过」「退回」，已审核行「撤销」。台账/附10 的公司 chips 与期区 chips 各自带审核态色。
- **审核员落地**：`/data-home`，主管条位置换成审核条「待审核 N」+ 筛选「只看待审」。落地规则：`can('review:approve')` 且零 `:edit` → 本月出账。
- **撤销 / 退回弹窗**：理由必填，居中弹卡（DESIGN-FIDELITY §七），确认后写 `review_log`。
- **通知**：交审 → 审核员铃铛计数 +1（复用待批授权红点通道，抽屉多一段「待审核」）；退回 → 录入方铃铛 +1。

### 8.6 与其余方案的关系

- 取代 P6 的「锁账落库」：不再需要 `period_close` 表；锁账行改为派生。
- 与编辑锁（CONCURRENCY-SPEC）正交：审核态不占锁、不发在场点；已审核屏的在场点自然消失（没人能进编辑）。
- 与催缴单现有 `confirmed`（主管业务确认）并存：主管确认无误 → 交审 → 审核员通过。两步是否合一，等清单跑一个月再看。

### 8.7 测试面（新增）

`Perm` 枚举 +1 与 RBAC 覆盖率回归；`V1xx__review.sql` 建表 + 角色 seed；`ReviewGuardCoverageTest`（源码推导）；`ReviewApiIT`（提交/通过/退回/撤销/前置阻断/423）；前端 `useEditMode.spec` +3（approved 不进、submitted 不进、returned 可进）；`monthClose.logic.spec` +4（审核态映射、前置 padlock、锁账派生）；`reviewDialog.spec`（理由必填）。破坏验证：删掉某 service 的守卫调用 → 覆盖率测试红；把 `approved` 改 `entered` → 编辑按钮出现。

### 8.8 不做

审核员批注到单元格级、多级审核（初审/复审）、审核时限与逾期提醒、报表层与收入核对进审核、审核态进页签标题。
