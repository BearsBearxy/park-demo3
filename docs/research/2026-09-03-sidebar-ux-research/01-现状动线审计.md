## §0 方法与范围

- **方法**：静态源码追踪。四个审计 agent 各自从 `fpNav.ts`、`router/index.ts`、`stores/{tabs,ui,billingPeriod,screenPeriod}.ts`、各视图 `setup`/`onMounted`/`router.push` 调用点出发，按角色权限矩阵（`V101__rbac.sql` 及后续迁移）推算动线。
- **未登录实测**：口令不能由 agent 输入。所有「几次点击」是从登录落地页起的静态推算，不含选期门内的格子点击与弹窗确认；「每月频次」是从权限矩阵与屏功能推的，未经真实用户确认。
- **视口基准**：办公机 1366×768，属 XL 档（`BP.l=1280`），rail 66 + 面板 234 内联，内容区 ≈ 1027px，面板可用高 ≈ 550px。
- **证据格式**：`文件:行` 逐条来自各 agent 原始 JSON（`scratchpad/research/code-{clerk,supervisor,exec,shell}.json`），本文原样保留、不改写行号。
- **计数口径**：`fpNav.ts` 实际为 数据层 19 / 报表层 10 / 分析层 19 / 系统层 3 = 51 项（`fpNav.spec.ts:5-8` 钉 51）；exec 审计文中「20 屏」按分析层 19 项 + 驾驶舱基底重复计一次，本文统一按 19。

### 1.5 需要 vs 从不需要

**每月实际要碰（16 项）**：数据中心首页(data-home) · 计费参数(params)——每月第 1 道，需主管提权 · 园区抄表(meters)——需主管提权（meter-master 捆绑）· 公共电核算(alloc)——需主管提权（param-policy）· 楼栋损耗(alloc-loss)——只读核看 · 催缴单(bill-notices)——生成可做；确认/标记导出需提权（billing-issue）· 月度台账(ledger) ×6 册 · 附表6 光伏发电(pv-income，报送台账模式) · 附表7 汽车充电桩(car-charging) · 附表8 电动车充电桩(ebike-charging) · 附表10 销售收入(sales-income) ×4 册 · 附表11 电费成本(elec-cost) · 附表12 工资明细(salary) · 办公·三期水电(utilities，附13+附14) · 导入中心(import) · 收入核对(reconciliation)——月末交接报表层的入口（report:edit 专员有）。

**从不需要**：银行流水(bank-flow)——占位页 · 楼栋管理(buildings)——无 master:edit，偶尔查阅 · 租户管理(tenants)——无 master:edit，仅台账补别名时经深链到达 · 合同管理(contracts)——无 contract:edit，只在首页 blocker 误导下进入 · 经营分析层全部（cockpit/park/park-energy/tenant-energy/tenant-portfolio/fin-pnl/fin-balance/fin-cashflow/fin-expense/churn/expiry/breakeven/pnl-analysis/budget/pv-roi/pv-meter-analysis/elec-analysis/charging-analysis/anomaly）——决策视图，录入岗每月不看 · 系统管理层(sys-users/sys-roles/sys-logs)——已按 system:view 隐藏 · 三大报表 + 损益附表1-5——主管/经理消费，专员至多在收入核对后偶尔打开。

### 2.5 需要 vs 从不需要

**实际需要**：数据中心首页（月份锚/出账链进度）· 合同管理 · 楼栋管理 · 租户管理 · 计费参数（含系数簿入口、本月变更、参数历史）· 公共电核算（审核/生成）· 楼栋损耗（审核）· 催缴单（确认/导出/签发·作废——后两者缺 UI）· 园区抄表（审核专员读数、偶尔接管）· 月度台账 / 附表10（审核 + 接管）· 报表中心 · 利润表 / 资产负债表 / 科目余额表 · 附表1-5 损益附表 · 收入核对 · 顶栏铃铛：待批授权 · （缺）操作日志 / 接管记录——需权限，今不可达 · 经营驾驶舱 / 异常提醒中心（月末复核）。

**从不需要**：银行流水（占位页）· 导入中心（专员日常；主管偶用）· 附表6/7/8/11/12/13-14 逐表录入屏（专员录入；主管只在接管/复核时进）· 用户管理 / 角色权限（不可见也无权）· 经营分析层中大多数专题（园区能耗/租户维度/光伏分栋/充电桩分析等，总经理与股东视图）· 预算对比 · 顶栏「收藏本页」「浅色/深色模式」（死按钮）。

### 2.6 机会（主管审计原提）

1. 主管「审阅态」与「写态」分离：在计费参数/催缴单加只读审核动作（重算本月、确认签发）走一次性确认而非整月占锁；或至少让告警面板的「重算本月」直接触发 enter→recalc→exit 三连，避免主管长期握着出账链月锁。
2. 补回催缴单「签发 / 作废」入口（端点已在，S4 §136 明写待恢复），并把「须先作废」的 confirm 文案改成可点动作。
3. 给财务主管一个审计视图：要么给 finance_manager 授 system:view（V101 改一行）并在系统层只露「操作日志」，要么把 audit_log（接管/提权/导入）并进计费参数页的「本月变更」抽屉。同时把 company:manage / book-template:* 的默认授予扩到主管，否则迁移注释里的「主管在角色屏勾选」是空话。
4. 待批授权要主动到达：新增 pending 时 toast + document.title 角标 +（可选）Notification API；抽屉里的「页面」行做成跳转（带 ym/公司）；请求 TTL 从 2 分钟放到与在场一致的时长或允许续期。
5. 报表层期跟随修到位：三大报表/附表/收入核对加 onReactivated 重读 parsePeriodQuery（照台账 LedgerView.vue:113-119 的写法），或让 FPStepStrip 走 openFresh；报表中心 go() 带 co（默认 'all'）而不是落第一家公司；勾稽瓦片可点直达未平那张表。
6. 统一账期上下文：数据中心首页 go() 带 ?ym=（目标已支持 adoptYm），出账链期可选持久到 sessionStorage（仍不跨天），分析层/报表层共用 y/m 查询参数约定。
7. 主管接管路径：若当前用户 hasOwn('lock:takeover')，FPTakeoverDrawer 直接提供「以本人身份接管」（仅密码）与「强制释放，让持有人重进」两个动作（后端 lock.force-release 已登记）；侧栏/顶栏增加「谁在编辑什么」总览（presence.users 已含 editScopes）。
8. 主数据三屏互链 + 影响提示：合同抽屉的租户/楼栋名可跳；租户抽屉列该户合同；改面积/在租期后在出账链月格与计费参数告警里显示「上游主数据已变，快照可能过期」。
9. 命令面板兑现占位文案：按租户名/合同号/凭证号搜索并带上下文跳转，或把占位文案改回「跳转到页面」。
10. 清理死 UI 与口径：去掉或实现收藏/主题按钮；账号菜单显示真实角色名（auth.role）；DataHome 用 can() 而非 isReadonly；把高频屏的 alert/confirm 换成 FPToast/FPDrawer 二次确认。
