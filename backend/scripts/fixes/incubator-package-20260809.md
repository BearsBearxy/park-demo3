# 孵化协议固定收取(包干)口径 — 设计说明

配套 SQL:`incubator-package-20260809.sql`(草稿,未执行)

## 1. 源册口径(取证结论)

包干是**替换**,不是附加。一张纸单只留一行:

```
粤海华创!C6  '公共用电分摊'  H6='47.2元/月'  I6=47.2
粤海华创!A35 '电梯用电'      X35=0
粤海华创!A38 '路灯公摊'      X38=0
```

`2024年2月电费总表` 同步:5 个包干户 **I(消防用电)=包干额、J(电梯用电)=0、K(路灯公摊)=0**。
即包干吞掉三项:楼层公共/消防照明 + 电梯 + 路灯公摊。**损耗仍照收**,且损耗基数含包干额
(联塑精铟 `K7=ROUND(0.0616×(43.8+232),2)=16.99`)。

同一张纸单上还有第二个包干:「公共用水分摊 xx元/月」。**2026-08-09 取证并同批落地**:
它替的是**绿化水公摊**一项(五户 sheet 底部汇总的「绿化水公摊」行=包干额、「用水维护费」行=0;
「2024年2月水费总表」R37/R39/R42/R48/R52 逐户 F(用水维护费)=0、G(绿化水公摊)=包干额)。
**水管网维护费不在其内**:三张明细型纸单上它仍是活公式(联塑精铟 `I12==I11` J12=0.5、
优唯特 H14=0.5、重瞳 J14=0.5),当月为 0 只因户内用水量为 0。取证细节见 SQL 抬头。

## 2. 池侧怎么记(源册做法)

- 有楼层池的户:包干额进**该户楼层公摊池**的 `AE(已分摊)`。
  `公共电分摊明细!AE19 = 电费总表!I41+I51+I79 = 63.8+79.45+20.11 = 163.36`
- 无楼层池的户(联塑精铟在一楼,没有它能挂的池):源册单开一行
  `公共电分摊明细!r12`,`AE12=AF12=232` 两个手输常数 —— 这就是库里 `alloc_rule` 92 的由来。
- 电梯池不收包干户 → `AF27 = 839.00 − ΣAD = −172.18`,园区自担。

**结论:包干产生的池 gap 不是数据质量告警,它就是源册的「盈/亏」列。**

## 3. 选定方案:户级包干配置 + 派生时短路 + 包干行回挂楼层池

- 配置落 `tenant_price_cfg`(`scope='tenant:{id}'`,`cfg_key='share_elec_fixed'`,元/月),
  与已存在的 `elec_package`(联塑精铟/粤海华创/禹晨都已有 1.0元/度)同一条例外轨道,**零 DDL**。
- `BillNoticeService` 公摊行循环里:该户命中包干 → 丢弃 `share_elec_floor / share_elec_elevator /
  share_elec_light` 三类池行,改落一行:
  - `fee_key='share_elec_floor'`(**沿用旧键**:`BillFeeMap` 不动、E2 损耗链的
    `share_elec_floor|elevator|fire` 白名单不动,包干额自动进损耗基数 —— 与源册 16.99 全等)
  - `rule_branch='fixed'`、`price_key='share_elec_fixed'`、`price_scope='tenant:{id}'`、
    `qty=NULL`、`price_snap=包干额`、`note='孵化协议固定收取'`
  - `pool_rule_id` = 该户 `share_elec_floor` 池成员关系里 `sort_no` 最小的一条(联塑精铟=92,
    禹晨/重瞳=32,粤海华创/优唯特=33);解析不到则置 NULL 并进 warn。
- `allocated/gap` 由 §5.9 从 `bill_notice_line` 回填,**不需要改**,自动复刻源册 AE/AF。

## 4. 拍板结果(2026-08-09,用户「你定」)

1. 包干**吞路灯**(证据说吞;影响联塑精铟 −63.38/月)。已实现。
2. 黄路生(已退租)与帷幄(无档案)两户 131 元/月:**只录 5 户,不给这两户录**。
   `tenant_price_cfg` 没有终止月字段,「按月失效」只能补 0 值月行=长期维护的影子配置,且对该月
   之前的任何月份都是错的;帷幄连档案都没有,写不出 `tenant:{id}`。引擎侧「当月无在租合同不落
   包干行」是第二道闸。等拿到「当月实收」证据再各补一条。
3. 水包干 313.64 元/月(5 户)**同批做**,替 `share_green_water`(见 §1)。
4. 粤海华创/禹晨/重瞳 源册损耗率硬置 0,库里按 0.0616 收 —— 户级损耗率例外,**另开一刀,本刀不碰**。
   本刀只要求这三户的损耗**基数**与源册全等(84.75 / 170.26 / 221.24),即证包干额进对了地方。

## 5. cfg_key 命名

`share_elec_fixed` 是价目簿白名单里 `elevator_package` 的**改名**(建键时以为包干只替电梯,
证据表明它替三项);改名时该键全库 0 行。水侧新增 `share_water_fixed`。两键都是户级可覆盖,
单位 元/月,落在「特殊轨道」组。前端 `PRICE_KEYS` 镜像同步(19→20 键)。
